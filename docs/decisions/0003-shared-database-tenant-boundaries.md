# ADR-0003：共享库表、租户隔离与独立业务部署

## 状态

Accepted：仅以下用户明确确认的架构约束。具体代码组织、迁移目录、管理入口和隔离实现仍以一期评审稿批准结果为准，不因本ADR自动获准开发。

## 日期与来源

2026-10-19，用户连续确认；需求编号见[一期评审台账](../planning/phase1-review-2026-10-19/README.md)。

## 背景

ResearchHub给另一项目使用，已有独立Demo域名；用户希望最大复用旧科研系统代码、Agent、知识库、解析和数据基础，避免重建，保留未来整合可能，同时保障旧系统持续运行。

## 决策

1. 新旧共享PostgreSQL实例、数据库和已有公共物理表，以不同租户隔离业务数据；租户管理可作为共用能力。
2. ResearchHub独立项目/部署，hub.pengxc.com；旧系统继续运行，首期不迁移历史研究数据。
3. 首期公开注册账号属于灵枢心域所属新租户；注册不自动获得私有Study数据，另经邀请授权。L2/L3认证二期。
4. 实施前验证旧后台扫描共享表等风险；为租户隔离所必需的旧后台代码可以修改，不能因此扩为旧业务重构。
5. 不复制第二套账户/知识/患者公共表作为默认方案；允许为ResearchHub特有业务新增兼容扩展实体。

## 替代方案与后果

- 两套独立生产库/平行公共表：不符合用户选择，不作为当前实施默认。合成开发/验收副本不受此限制。
- 共用整套旧运行后端：不能据此取消新项目独立交付与发布边界；是否局部共用服务需评审。
- 共表不意味着数据互相可见、自动共享账户登录、共享所有密钥或无故障耦合；请求、后台、存储、搜索/AI和共享迁移均须验证。
- 共享结构变更需新旧兼容与唯一受控迁移链；先验证风险并修补，再启用新租户任务，不以静态RLS/测试代替真实隔离。

本ADR不改变ADR-0001的冻结Shell或ADR-0002既有独立发布目录、Compose和端口。具体推荐设计、准备门槛与未决项见[总体方案](../planning/phase1-review-2026-10-19/overall-design.md)。
