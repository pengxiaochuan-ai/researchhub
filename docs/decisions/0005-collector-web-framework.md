# ADR-0005：独立采集项目的双获取路径与网页框架

## 状态

Accepted：仅“官网免费正式接口/许可数据集优先、获准网页补覆盖；网页路径以 Scrapy 为主、Scrapling 按站点需要增强”的框架决策。具体来源、采集字段/用途、数据库权限、项目创建、运行与部署仍须分别按实施规格确认，本 ADR 不自动授权。

## 日期与来源

2026-10-31，用户确认网页路径按“Scrapy 为主、Scrapling 按站点需要增强”定稿；双路径要求来自同日讨论。详见[采集项目设计评审稿](../superpowers/specs/2026-10-31-hub-collector-design.md)。

## 背景

ResearchHub 需要独立定时采集情志病领域临床注册、论文、指南和教材候选。只依赖单个正式接口可能留下覆盖缺口；但网页可访问、可抓取、可再展示和可供 AI 检索是不同的判断。科研来源还要求字段准确、原文/版本可追溯、重复可识别。

## 决策

1. 先核对并使用来源方免费正式接口或许可数据集；其范围不足且逐站获取条件获准时，再启用网页采集。两路径共用隔离候选、版本、强键去重、权利/内容审核及 Hub 交付，不重复计数。
2. 网页通道以 Scrapy 管理批量请求、队列、限速与断点；业务幂等和跨批次游标仍由采集项目账本管理，不把框架 checkpoint 当成数据库事务。
3. 仅对确有必要且获准的动态/易变页面，按站点引入 Scrapling 解析或浏览器能力；自适应定位输出必须通过字段结构、稳定编号和交叉校验，低置信候选隔离，不自动公开或交给 AI。
4. 不以 Turnstile 处理、代理轮换或 MCP 自主采集能力作为获取许可；遇到访问控制、条款或 robots 阻断时停止该来源并人工核对。两路径均遵守逐站白名单、频率和用途边界。

## 替代方案与后果

- Scrapling 单独承担所有网页采集：其异步 Spider 与 checkpoint 可用，但首期更需要稳定、可观察的批量采集主流程；全站启用自适应解析会增加静默误配风险，故不作为默认。
- Scrapy 单独承担所有网页采集：可作为最初实现，但遇到获准动态页面或频繁改版时可以按站点补入 Scrapling，不另建第二套全量爬虫。
- 用反爬绕过或代理轮换扩大数据量：不采用。数据量目标不能凌驾于来源许可、字段准确性和可复现性。

实施前仍需确定首个获准网页站点及其条款/robots、字段/用途、请求上限；本地 HTML 夹具测试不等于真实站点能力验收。此决策不改变既有来源审核和独立部署边界。
