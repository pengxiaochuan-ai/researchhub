# ADR-0006：租户管理员长期默认拥有本租户完整业务权限

## 状态与来源

Accepted（**产品权限原则已由用户确认，具体模块代码/实际启用未因此自动完成**）。2026-11-02用户连续确认：Study任务管理者创建、分派和验收，科研人员处理本人负责/协作任务；租户管理员还须自动获得临床数据、方案审批、锁库和导出权限，并明确这是正式产品长期默认规则，而非本次验收临时特例。

## 决策

1. 当前有效租户管理员是**本租户业务最高权限角色**：本租户全部Study的任务与临床业务数据、方案审批、锁库及导出均具备默认操作权限；无需逐Study加入、邀请、逐项申请或人工补角色。非本租户的数据不在范围内，也不等于平台跨租户管理员。
2. 科研人员仍遵守本人负责/协作与当前Study授权；Study任务管理者在其获准Study管理任务。普通注册用户不因该规则获得私有Study权限。
3. “最高权限”消除角色授权障碍，不消除业务前置条件：真实对象/版本、合法状态转换、锁库条件、记录保留、导出内容完整性、审计和已锁数据更正规则仍有效。不得伪装其他账号执行，不以管理员名义静默改写历史/科学数值；权限不等于可读取密码、Cookie、模型密钥或跨租户数据。
4. 权限必须由服务端**当前**账号/租户状态、authVersion及`isTenantAdmin`真值判定，不信任邮箱、显示名、前端菜单或旧JWT里孤立的管理员标记；撤销身份后，后续请求/在途提交重验即生效。
5. 新增受控的管理员判定分支，不向每个Study插入伪成员，不给所有普通角色补全权限，不全局删除StudyGroupGuard，不取消tenant/RLS/对象Scope/来源完整性检查。每项操作保留实际管理员、tenant/group/Study、对象/版本、动作与原因/结果。

## 实施与验收边界

- 此规则是正式产品目标，不只是“有一个代码开关”。每个模块必须分别证明代码覆盖、目标环境启用、真实管理员请求与业务效果，未接线模块明确标未生效，不能宣称管理员已经能完成所有验收。
- 当前优先完成[S08整页](../product/study-tasks-s08-complete-spec-2026-11-02.md)；临床数据、方案审批、锁库和导出按对应页面逐页接线，不在S08顺带实施。S08未完成不切S10。
- 本地开发/验收仍仅专用合成库，不因产品权限规则放开而连接真实临床库、变更云配置或真实发布。具体本机账号启用/兼容表字段/最小测试夹具见[S08授权清单](../planning/study-tasks-s08-2026-11-02/authorization-scope.md)，待实施规格批准后执行。
- 实查原`admin@example.org`在合成库的`isTenantAdmin=false`。显示“管理员”不构成规则已启用的证据，本轮未修改它。

## 取舍与兼容

采用“服务端当前身份自动派生权限＋模块业务流程守门”，不采用验收时临时全权、邮箱白名单、逐Study补成员或全局Guard短路。这样满足用户正式产品要求，又不扩大跨租户可见性。

本ADR优先覆盖既有文档中“租户管理员不能自动获得Study业务权限”的**通用角色原则**；旧R1本人只读切片及其当时403测试作为历史结果保留，不伪改为新规则已验证。具体旧内核的最小适配要列出影响并经规格确认，不以该ADR授权旧系统全量重构。ADR-0003的租户隔离/普通用户邀请规则和冻结UI/独立部署继续有效。
