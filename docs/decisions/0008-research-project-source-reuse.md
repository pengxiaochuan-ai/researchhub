# ADR-0008 · 科研课题创建复用源码与事务核心

状态：Accepted（用户2026-11-11批准补充调用方式并开始实施）。范围：本批课题意图、默认研究建立与读取；其他模块按复用清单逐项实施。

## 背景

旧系统已有执行项目、成员、认证、审计和数据库边界。ResearchHub需要独立的课题意图和产品Study身份；直接调用旧Controller的HTTP不能得到跨两套对象的原子创建，裸调Service也不会自动执行Controller Guard。

## 决策

ResearchHub提供自己的课题API和独立选择装配入口。复用Auth/Prisma/当前授权锁，提取StudyGroupsService最小createResearchProjectInTransaction核心；旧入口继续调用该核心，Hub先检查当前创建权后在同一受限事务调用。公开数据库模型保留，新意图/绑定/明确Hub角色/回执放在rh_research。

同一事务涵盖旧执行项目、创建者成员、绑定、意图版本、审计和幂等回执。当前授权和父链在应用及数据库分别校验。不伪装租户管理员，不通过HTTP转发整套旧业务API，不自动迁移历史项目。

## 比较过的方式

- 直接HTTP调用旧项目API：依赖旧管理员Controller，且无法与Hub意图/绑定共享数据库事务，故不用于本次创建组合。
- 复制旧项目/成员实现：会产生两份规则和修复路径，故只提取共用核心；Hub独有产品对象另存。
- 独立Worker API：保留给原本独立部署的确定性计算服务，本批创建不需要引入Worker。

## 代价与运行约束

独立发布包需要同时携带被复用的app/server源码、其运行依赖及ResearchHub代码；这不是可单独拷贝页面即部署的静态站。只装配本批服务，不导入旧AppModule、fixture启动器或恢复扫描。迁移显式执行，启动不自动建表。

后续独立计算Worker仍按既有受控API调用；源码复用与Worker服务调用是两种不同边界。新采集/分析接入必须使用统一Study解析，中心/盲态/正式启用规则尚未交付时保持拒绝。

## 验证

旧入口回归、当前权限/CAS/幂等、真实PG强制隔离及中途失败回滚、真实API与Chrome创建流程分层验证。见[本轮证据](../testing/research-study-creation-2026-11-11.md)。不将本机合成测试称为生产或临床专业验收。
