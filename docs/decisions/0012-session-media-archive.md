# ADR-0012：岐研AI会话媒体原件与文献解析分离

状态：**Accepted**，2026-11-16。用户明确批准视频规格MV01–MV03并要求串行实施。仅专用合成库的一张媒体关联表、本表最小DML及原两账号最多六文件的验证；不授权临床/云/生产或模型费用。建表及目标19501六文件真实归档/播放/检查验收已完成，用户主观体验签收、内容理解及正式部署另行进行。

## 背景

旧视频分片/私有落存/受控读取与容器检查可以复用，但Hub现有两类上传实体分别绑定文献或CSV/XLSX。视频没有可复用的当前语义理解结果，不能造一个ready KnowledgeDoc，也不能靠已退役VideoAnnotator重新启用检测。

## 提议

仅rh_ai新增session_media_uploads关联表，保存本人会话、稳定原件身份、原key回执、归档与检查的独立状态/版本；原文件存储、分片上传、签名/SHA、权限来源和媒体检查解析复用旧代码。只给既有app该新表最小DML；public表/角色/旧源代码/旧扫描保持。

视频首片不生成Subject/Visit/Feature、AI摘要或可检索正文。后续合法内容理解执行链的派生转写/片段必须绑定原件SHA/时间点，再按真实授权交Agent；不以容器valid冒称内容分析完成。UI沿原上传入口及文件列表按需播放，不改Shell或对话布局。

## 替代方案

- 扩原session_materials/research_data_uploads：会混淆已有guard和ready含义，亦需DDL，不采用为默认。
- 仅用Message.meta/Audit/临时文件：未发送消息或重启后的回执、版本/列表/原子边界不足，不采用。
- 恢复旧VA检测或直接换视觉Provider：不属于当前有效复用，涉及独立算子/数据/费用评审，不自动执行。

## 后果与依据

代价为一张自有表的RLS/父链/CAS及媒体适配；不重建上传引擎或通用IAM。详细字段、接口、MV授权及测试以[规格](../product/qiyan-ai-video-ingestion-2026-11-16.md)和[实施计划](../planning/qiyan-ai-video-2026-11-16/implementation-plan.md)为准。归档/检查/播放/内容理解四项分别举证，不用离线探针替代目标环境能力。
