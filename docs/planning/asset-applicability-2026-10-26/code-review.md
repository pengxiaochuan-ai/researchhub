#### 2. [P2] 空访视映射被判为“声明相同”，掩盖未声明

位置：[asset-applicability-contract.mjs:24](/Users/mac/aisciencesys/researchhub/scripts/asset-applicability-contract.mjs:24)，调用点第44行。

`present()` 将空数组视为已声明。使用合法输入，把源与目标同一映射的 `visitKeys` 都设为 `[]`，实际结果为 `source.present=true / target.present=true / state=declared_equal`。但现有配置契约允许该空数组，原准备规则将其识别为“映射尚未指定访视”。这应是缺失核对依据，而非两端已声明且相同。

影响：确定性核对会把双端同样缺失的信息显示为绿色相同，并将该错误状态继续提供给 AI。

最小修复：对 `visitKeys` 使用明确的非空声明判定；一端或两端为空时返回 `not_checked`。保留 `false`、`0` 的有效声明语义，补充双空、单空、非空相同及非空不同测试。

#### 3. [P2] 四秒轮询会撤销用户尚未填写意见的依据切换

位置：[AssetApplicabilityDetail.jsx:13](/Users/mac/aisciencesys/researchhub/pages/shared/AssetApplicabilityDetail.jsx:13)，覆盖行为在第19行，定时刷新在第42行。

`dirty` 只计算意见字段变化／错误，不包含依据切换与确认状态。用户选择另一个依据后，新意见为空，因此仍是 `dirty=false`；下一次成功轮询会把依据恢复为服务器旧依据，并清除确认。

基于当前组件代码的纯内存状态模拟确认：选择AI依据并确认时 `basis=actual-ai / dirty=false / confirm=true`；下一次轮询成功为 `basis=null / dirty=false / confirm=false`。

影响：用户停下来阅读或思考就会丢失明确选择；随后填写的意见可能绑定到已恢复的旧依据。现有立即切换并填写的流程证据没有覆盖这个等待窗口。

最小修复：把未提交的依据切换纳入草稿保护状态，并用于轮询覆盖及离开保护；仅在成功保存、明确放弃或相应失权时清除。补充跨越轮询周期的双向依据切换测试，同时保持原 CAS 不变。

#### 4. [P2] 同一基准自检提示比较了不同实体的 ID，实际不会显示

位置：[AssetApplicabilityDetail.jsx:61](/Users/mac/aisciencesys/researchhub/pages/shared/AssetApplicabilityDetail.jsx:61)。

当前判断 `binding.sourceAsset.id === binding.targetPlan.id`，左侧是资产候选ID，右侧是方案ID，不是源资产对应方案的身份。已有owner/admin成功样例中，`sourceRoot.planId` 与 `targetPlan.id` 相同，但资产ID不同，因此规格要求的“同一基准自检，不证明迁移到新研究”提示被隐藏。

影响：两端实际来自同一方案时，用户缺少明确自检标识，容易把声明相同误读为跨研究复用已获支持。

最小修复：依据服务端已验证的 `binding.sourceRoot.planId` 比较目标方案ID；补充同一源方案显示提示、不同方案不显示提示的断言。派生参考提示保留独立语义。
