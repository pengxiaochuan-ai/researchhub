### Important

**I-1：读取校验失败后，旧候选仍显示“来源有效”，并保留可写动作。**

位置：`pages/shared/CrfMethodAssetDetail.jsx:17,18,34`。列表存在相同保留旧状态的问题：`pages/shared/CrfMethodAssetWorkspace.jsx:15`。行号为评审快照。

触发：先成功读取 current 候选，后续 GET 因根报告/祖先 Source 完整性冲突返回 409，或因连接/服务失败无法完成验证。`reject()` 对非 401/403 只设置错误，不失效已读状态；`asset.sourceStatus/canEdit/canDerive` 原值继续驱动文案与按钮。后台校验确实能够产生这类 409，见 `scripts/local-crf-method-assets.mjs:69`。

影响：页面同时宣称“无法核对”和“来源有效”，并允许用户继续尝试修订/派生。后端会拦截无效提交，但前端仍对已无法确认的来源作出正面保证。下一次成功轮询也没有清除旧错误。

最小修补：区分读取失败与 mutation CAS 冲突。读取失败设置独立“当前未核实/校验失败”状态，禁用写动作；完整性错误隐藏不可信报告/配方，暂时网络错误可以明确标注“上次读取内容”。本人未保存 notes、原 CAS 和请求键单独保留。成功重新验证后恢复状态并清除对应读取错误；不要破坏已成功写入但丢响应的同键重试。

补验：current → GET 完整性 409、current → 网络失败 → 恢复；同时回归 dirty CAS 与丢响应重试。

**I-2：独立鉴权探针验证的是 A01 列表，无法保护正在读取的 A02 历史目标。**

位置：`pages/shared/CrfMethodAssetWorkspace.jsx:19`、`pages/shared/CrfMethodAssetDetail.jsx:18,19`。

触发：历史版本读取取得 200 后被延迟交付；期间仅撤销 A02，保留 A01。探针始终请求 `/crf-method-asset-drafts?limit=1`，只要求 A01，因此仍成功；详情自身 busy 时跳过 refresh，迟到的历史 200 会通过原 sequence 检查而显示。类似地，列表首项属于其他合法根时，该探针不能确认当前所看根仍在授权范围内。

影响：已被撤销历史读取权限的内容继续呈现，迟到响应保护对细分操作/目标失效。现有浏览器反例关闭整个 scope，因此不能证明本场景安全。

最小修补：独立探针绑定当前实际展示/请求的候选 ID、当前或历史版本及对应读取目的；可复用现有精确 GET，不需要新增授权平台。目标切换同步更新探针目标；探针拒绝后统一失效详情代次并清内容，迟到响应不能重新呈现。

补验：A01 保持、仅 A02 撤销的历史慢读；以及查看非列表首项时撤销该根登记。恢复后显式重读，不自动重发写入。

**I-3：合法字符串型选项被渲染成 `undefined=undefined`。**

位置：`pages/shared/CrfMethodAssetDetail.jsx:42`。

触发：合法 select 配置采用 `options: ["a", "b"]`。原 normalizer 明确保留字符串选项；新 snapshot 也合法接收。界面却统一按对象执行 `o.label+'='+o.value`。

影响：用户无法核对配方中的真实允许值，直接损坏本切片“复用准备”的关键呈现。当前 golden/UI 夹具使用对象型选项，未覆盖这一合法分支。

最小修补：字符串直接显示自身，对象显示 label/value；增加字符串、对象及混合选项的呈现验证。无需修改存储契约或原配置服务。
