日期：2026-11-13（Asia/Shanghai）。范围：当前真实课题的PHQ-9准备工作；用户说明原文页面未打开、稍后自行查找，先继续其他工作。本包不依赖未取得的证候量表分值，不恢复其他历史专项。

## 可复用的现有能力

- 9项整数0–3由现有`numeric-sum-v1`计分；字段key、原文、值域、功能题不计分与来源哈希沿用已冻结内容。
- CSV沿用当前`subject_code,visit_code`及固定表单字段的契约；CSV是研究者录入的传输方式，不增加一种`captureMode`。
- 现场与H5复用同一固定表单版本；一人同一访视的同一要求不能因有三种输入渠道就重复创建三份正式答卷。未知提交、已有内容、更正、同意、权限和版本约束保持现有流程。

## 已发现的发布前适配项

1. 9项整数当前会显示为数字输入框，不能据此宣称已忠实展示四个原文频率选项。需要保留整数存储/计分，为现场与H5展示同一组固定原文选项；未选择必须保留缺失，不能默认选择0。
2. 现有`normalizeFormSchema`只保留顶层`schemaVersion/fields`，会丢弃随意添加的顶层标题、过去两周指导语和作者致谢。来源/指导语应有明确版本化展示契约，并贯通管理员核对、研究者录入、H5及历史阅读，不能只写在工程JSON中就称已接入。
3. 当前提交/历史核对使用通用`displayAnswer`，会回显`difficulty_1`或数值代码；须结合固定版本选项还原原文标签，现场、H5、历史/更正和版本预览联动，不能只修改填答控件。
4. 发布还需真实有权组/执行项目、模板/草稿版本和V1–V4固定引用；当前ID均未绑定。功能题必填策略、第9项后续处置、研究/自填/邮件同意仍待实际方案配置，不虚构临床响应规则。

现有`StudyFormsController`的clone/PATCH/publish属于核心后台接口；ResearchHub当前独立运行装配没有挂载该Controller，不能将候选正文直接发往ResearchHub同源`/api/study-forms`并声称可用。核心GET templates可能创建内置模板，线上CSV preview会查库取锁，本轮均未调用；离线检验只使用纯函数。

## 文件用途

| 文件 | 用途 | 当前可执行范围 |
| --- | --- | --- |
| `form-version-patch-body.json` | 现有后端草稿版本更新的schema/scoring正文候选 | 仅内容校验，不含真实版本ID，不发送请求；单独使用不含完整PHQ指导语/选项展示能力 |
| `field-dictionary.json`、`field-dictionary.csv` | 固定字段、原文选项、值域及缺失语义 | 可供核对/映射，不是患者数据 |
| `csv-template.csv` | 与现有前端模板一致的UTF-8 BOM/CRLF空表头 | 填写并具备真实已发布版本/访视/受试者/权限后才可实际导入 |
| `csv-synthetic-examples.csv` | 三个公开合成计分例 | 只用于离线校验，不提交业务系统 |
| `visit-bindings-unbound.json` | V1–V4按同一固定版本采集的绑定意向 | 版本引用为空且非API请求；健康组访视范围不自动套用 |
| `presentation-requirements.json` | 原文展示及缺失/功能题规则，供最小适配实施 | 需求契约，不冒称现有组件已支持 |
| `verify-preparation.mjs` | 复用当前前端模板、后端CSV解析和纯计分核心验证 | 无网络、数据库、账号、通知或运行重载 |

空模板只有表头，尚无记录，当前解析器预期拒绝直接提交，这是正确行为；字段填齐后另行预检。功能困难CSV保存`difficulty_1`至`difficulty_4`等非计分代码，原文见字典，不给原件功能选项发明分数。
