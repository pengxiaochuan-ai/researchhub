# P4研究质量准入核对：现有能力、剩余缺口与实施边界

日期：2026-11-13。状态：**准入核对完成，实施未开始；不是S05整页交付或生产验收。** 本轮用户只授权对照S05已有能力明确P4缺口，避免重复开发。采用当前目录串行核对＋一次独立只读评审，只用专用合成环境。

## 1. 结论

**不重做疑问、更正、审阅锁定、分析计划／快照或通用导出／Agent底座。** 优先完成“当前有权Study选择 → 真实质量总览与问题 → 原页处理／放行 → 返回”的页面接线与受限投影；再补当前缺失的核查运行、SDV、趋势／轨迹、质量专用报告和固定结果AI解释。

现有方案是两条S05真实分支：`formalCapture=1`的数据疑问工作台，以及`formalAnalysis=1`的合成分析数据准备。后一条目前仅在具名Study装配，固定3名合成受试者、BASELINE和直接字段映射，**不是任意Study质控入口，不是整Study锁库**。普通`/pages/s05/`当前仍是不可用门禁。G02的quality适配器为空，不能把暂无汇总当作零问题。

原P4清单QL01–14继续有效；仅中心对比随既定多中心功能延期。SDV、质量报告导出、AI解释不因依赖未确认而自动移出本轮目标。未涉及共享底座排空、通用权限引擎或旧系统重构。

## 2. 本轮实证及限制

- 专用库身份检查通过，PG明确`transaction_read_only=on`；只读访问既有合成基准Study及表结构，没有创建夹具、改账号／角色／关系／政策或处理历史任务。
- 当前基准Study查询到186个符合本次非删除／非验收夹具谓词的Subject、38个draft及101个submitted FormResponse、2条closed/formal_response疑问，以及真实审阅／锁定／解锁事件。这是混有历史边界测试的Study存量，**不是计划纳入的3例，更不是可直接展示的完整率或科研质量分母**。CRF总数还必须区分定义、分配、答卷和修订，不能直接拿139条Response替代全部定义。
- admin通过真实HTTP读取疑问两页，记录不重复；分析计划可读，定义明确为synthetic／3人／BASELINE。只抽取最近最多5份计划和5份快照元数据，并读取其中3份快照：2份200，1份409 `PARTICIPATION_CAPTURE_BLOCKED`。失效快照被正确阻断，不能为了填页面而绕过。
- 原owner可以读取研究目录，但对该基准Study的疑问与分析均403。该账号组关系有效，**没有该Study项目成员关系，这是本次疑问只读403的决定因素；疑问GET本身不要求`form.fill`**。原组角色也没有`form.fill`／`data.analyze`／`artifact.export`，这些分别关联后续填写／更正、分析和导出动作，不能为修复只读入口而一并补齐；虽有`study.review`，仍须项目负责人和当前父链成立。不能归因于邮箱、把目录可见性当临床读权，或直接扩大组角色。admin不需要伪造Study成员。
- 两账号真实Chrome截图／录屏：S05直接入口、两真实分支、G02研究质量筛选。admin疑问页只有“数据问题”可用；分析准备页只开放其现有数据核查区域／问题回链，其余非多中心Tab仍未接通。六卡、趋势／分布图和AI卡保持未核验空态。owner真实403文案沿旧通用“无权填写表单”，未来须按只读质量任务投影清楚，不据此改变权限。
- 25项现有纯契约测试通过：疑问分页／权限／回执、当前修订／原值、分析计划范围及来源变更。仅证明既有契约，不代表新增P4能力或重新验收所有旧写链。

## 4. 母版与旧清单还有两处须收口

1. **批量问题分配与责任人**：原S05表格／常用操作存在，但DataQuery没有责任人／分派API。S08已有任务分派核心，当前正式任务context只接受`formal_visit/formal_response_ref`，不能声称已原生支持queryId。推荐先评审复用S08责任跟进的最小关联及单一权威责任人规则；若决定延期或改变原按钮语义，须用户明确确认，不能默认禁用后把整页销项。
2. **导出问题列表与质量报告**：原母版“导出问题列表”容易包含患者级标识，而已批准QL13只允许聚合质量报告。推荐把本期导出范围统一为既定聚合质量报告，任何原按钮文案／语义调整在P4实施规格里明确确认；未经新增授权不导出患者明细，也不静默把一个功能冒充另一个。

“数据核查计划”也不直接等同当前T15的合成分析计划；应在核查运行／规则配置中明确它的最小业务动作，不另造一套计划审批引擎。这些是产品落点核对，不是本轮新增实施授权。
