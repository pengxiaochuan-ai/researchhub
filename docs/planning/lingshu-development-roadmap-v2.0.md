## 4. 服务契约与数据实施先后

### 身份与授权

一期新增契约域：公开注册/自助找回、Auth会话/资料、我的Hub/Study、资源动作解释、安全邀请与产品租户绑定。L2/L3二期。登录授权从服务端取得，不信任roleName、URL或客户端tenantSlug选择。

会话方式与认证库随后端设计确定；邀请校验必须过期、目标账号匹配、授权人资格、Study状态、幂等和审计。接受邀请与创建成员/授权须在同一事务或有明确一致性策略；认证pending不提前授予访问权。

### Hub与领域数据

复用V1.1现有 `/api/hubs/{hubId}/overview`、`trials`、`trial-trends`、`map`、`assets` 和 `/api/trials/{trialId}/provenance` 等职责。补充关注/Brief、共建关系、Hub申请与人工审核契约。URL只是建议，正式接口需统一版本/分页/错误/授权约定。

采集按Source原始版本→Canonical去重→Hub归属→指标刷新推进。现场已有注册记录不等于团队自己的Study；不要把C03临床注册详情改成私有S01研究后台。原Excel中的实体、资产、来源字段继续使用，新增身份/机构/邀请/StudyHub关系先补字典再迁移。

### 研究与资产

Project、Study、Protocol版本分别持久化；任务、成员和Dataset必须能解析独立studyId。草稿保存使用版本冲突检测；Study激活、邀请接受、Asset发布等操作使用幂等键与事务。

共享申请包含来源版本、目的范围、申请人、审批人、理由与策略结果；跨Study复用创建引用/派生关系，不复制权限。AI输入过滤、下载授权、导出和缓存按同一资源策略实现。

## 5. 开发顺序与验收任务

1. 产品/数据先行：确认机构、Hub、Project、Study、Role/Scope/Permission关系；补V2字典与策略表；评审真实后端范围。
2. 写接口契约与测试夹具：两账号、两机构、两Hub、两个Study、同一用户不同角色；包括公开和受限资产。
3. 建身份/上下文服务，再改登录/资料与P01；用未参与研究的新用户验证空态与返回路径。
4. 初始化灵枢心域及来源数据；建立不可覆盖版本和去重/归属审核，接领域页面。
5. 接Project→Study→Protocol、成员邀请与治理；完整验证四类用户路径再接真实受试者数据。
6. 接约定执行、质量、分析和产出；完成资产审批及Hub复用；执行跨上下文越权测试。
7. 接真实Copilot与来源引用、输入权限与派生限制；服务失败/取消/重试可恢复，不生成假结论。
8. 完成构建、浏览器视觉/响应式、权限/恢复、部署备份、用户培训与验收记录。

每个阶段的实施计划须指定文件、接口输入/输出、状态转换、测试与验收，不用一个“全站接API”任务覆盖所有页面。功能实现、测试和产品基线更新同轮提交；保留原始文档与历史快照。

## 8. 专业材料修订R1：调整开发重点

### 8.1 前置输入已明确与未明确

已明确：重点抑郁、失眠、认知障碍；有中英文文献种子数据和既有共同体活动；用户确认无EDC，必须建设采集。

实施前需要：首个真实Study、完整方案/访视表/CRF、实际角色与中心、量表授权及计算规则、随机化/盲态/揭盲要求、研究数据导出与共享政策。两条注册链接只能帮助理解字段，不能替代这些输入。

### 8.2 M2先利用已有文献

先读取合并表并对来源分表建立对应关系，完成批次/source-row/canonical-publication/候选去重/人工审核/范围分类。先用确认后的团队数据支撑E01/E02/H01与知识库，再接更多自动来源。导入要求文件、sheet、行、hash可追溯，重复导入不新增相同记录；缺失DOI/摘要/URL明确标记，不填造。

英中文去重不能仅按题名翻译或作者姓名；不把15,696条合并记录声明为15,696项临床试验。注册来源和Publication来源为不同实体，分别关联并统计。涉及全文、回放、申报书和AI使用时确认权利与可见范围。

### 8.3 M3与M4增加EDC准备和交付

M3设计阶段即定义Protocol→访视计划→CRF模板→字段/校验/状态→角色Scope，不到M4才临时拼输入框。M4分为三个可验收交付：

1. **EDC模板与受试者/访视采集**：一项真实Study的确认模板，字段类型、缺失语义、版本冻结、入组/访视状态、草稿/提交、服务端校验与并发处理。
2. **质量与锁定**：疑问分配/回复/关闭、审阅/签署、更正原因、锁定/受权解锁、数据快照、字典与导出；必要事件/偏差按方案配置。
3. **分析与科研资产**：经确认SAP及数据版本，分析结果/论文草稿、人工共享治理与Hub复用。

先完成受控采集与质量闭环，再开放真实患者数据。首期只完成约定的模板与可复用采集引擎；独立随机化服务、复杂动态表单编辑、电子签名身份保证和紧急揭盲按研究要求单独确认。若首个Study依赖这些能力，相应能力成为启动前置条件，不默认为已具备。

### 8.4 新增测试门槛

| 范围 | 验收 |
| --- | --- |
| 导入/术语 | 同文件重复导入、跨表来源关系、缺失标识、候选去重人工决策；认知术语与扩展检索不混作临床标准 |
| CRF/量表 | 日期/枚举/数值/条件必填；空白/未测/不适用/0；量表版本与明确算分规则，越界值不写入正式记录 |
| 版本/并发 | 修改配置不改变已采集模板；并发保存返回冲突；访视数据能定位Protocol与CRF版本 |
| 更正/锁定 | 原值/新值/原因和操作者完整；签署后变更触发重审；锁定拒绝普通编辑；解锁有理由/授权/审计 |
| 中心/盲态 | 跨中心受试者不可见；设盲角色不能在附件、AI、搜索和导出看到分组信息 |
| 分析/资产 | 导出与分析绑定锁定快照/字典版本，公开统计结果不自动公开原始行数据 |
| 共同体 | 讲座/活动显示原日期与已授权链接；不能由活动参与自动授Study成员权限 |
