## 本片结果与范围

1. 原AI01数据导入区内提供当前已导入批次的概览/质控折叠区，不新增页面、导航或多步选择。展示Study/方案/表单、实际被试/访视/表单数、字段类型/非缺失/缺失/异常及程序计算的描述统计；0和false是已记录值，未知单位不猜填。
2. 只分析当前本人已提交P05回执内对象。来源文件版本/SHA、来源预检、Study与真实执行项目、固定CRF revision/hash、当前授权重新核验。来源会话的scope不能代替目的项目。不是全Study/跨账号分析，也不把BASELINE说成随访；completed字段不冒充访视完成状态。
3. 复用旧表单schema/原生答案类型与范围校验/确定性评分、原生固定revision读取和现有数据识别。新增概览算法只做明确的计数、缺失、最小/最大/均值及规则覆盖说明；不推导疗效、诊断、插补、显著性或跨组差异。未设定/未执行的质控标为未评估，不把“未见结构错误”当数据质量整体合格。
4. 当前结果生成内容hash和确定性证据ID。AI沿既有真实OpenCode＋DeepSeek、当前科研Agent工具授权、会话队列和租户/账号Token预留/结算，只获得已授权的聚合摘要，不获得原文件、逐行数据、任意SQL、网络工具或新增写权限。
5. AI回答分“程序结果”“AI解释/建议”；程序事实和数字由后端渲染，模型解释必须明确选择真实结果来源，引用由后端生成。可追溯到本次固定表单/访视；未知/失效状态先查原任务，刷新恢复，不自动重试或再次计费。未入库/失权/来源变化/缺引用不得伪装成功。

本片不恢复退役检测，不接眼动/fNIRS/媒体算子，不增加正式采集、审批、锁库、共享、发布、导出；完整D01–D12仍按后续切片逐项交付。目标环境中旧data Agent配置及执行器的实际可用性先快照核实，不能以源码目录存在冒称已启用。

## 契约与复用约束

实施裁定：强READ ONLY已核实目标租户没有data Agent实例；当前九项默认Skill中的医学报告Skill面向体检/检查和健康管理，不能冒充科研数据质控。故本首片复用科研Agent真实执行/工具授权与旧表单核心，增加版本化`hub-research-data`受控结果解释适配，路由skill=null并固定解释策略hash；九项Skill安装、装备、权限及原路由不改。`research_data_result_read`是服务端固定结果读取记录，沿当前file.read授权，不是开放db.query或新的通用模型工具。

原生固定答卷读取内部有行锁，业务只读GET复用该原生事务，不宣称这些读取运行于数据库强READ ONLY模式；O01准入确为强READ ONLY。P05的被试/入组/访视/答卷/原件均不改；新队列契约测试只在同一专用合成事务中创建本片新消息/任务并全部回滚，Provider调度替身只证明契约，不证明AI真实执行。

- GET `/sessions/:sid/research-data-imports/:planId/analysis`：本人原来源会话、当前result.read与真实目的Study校验后，返回固定结果及安全来源，不创建任务/不调用模型。
- 任务沿现有commands/knowledge-messages，入队固定本人导入选择，认领固定结果与Skill版本，Provider前/提交前/历史读取均重验。使用现有knowledgeChatJob.payload和回答provenance，不新增表。
- 概览读取、入队、认领、提交的授权/父链在各自同一真实事务中校验；在已有事务内复用原连接，禁止另起事务等待自己持有的租户授权锁。切换目的GUC后finally还原来源scope。
- 不给owner新增组角色或data.upload/form.fill。先核实既有result.read和原科研Agent权限能否承载只读聚合/解释；若必须新增数据或工具权限，停下列出最小差异。
- 付费验证单独记真实请求/Provider用量/业务预留与封口，不充值、不补额度、不操作未知旧预留；实际Provider未知用量不得估算对账。
