## 3. 推荐架构与取舍

主路径：岐研 AI 当前登录会话 → 当前授权及 Token 并发预留 → 任务路由 → 固定 Skill 版本及上下文 → Hub 专属 OpenCode 执行 → 已授权知识检索/PubMed MCP/确定性计算 → 结果核对 → 持久化会话、来源和用量 → 现有页面。

优先组合复用旧 `OpencodeClient`、模型路由和治理服务，由 Hub 自己管理部署范围、工作目录、进程及 MCP 工具授权。旧池的工作区生成不能原生注入这九项及 MCP；实施首步验证是否可通过现有接口完成隔离装配，不能先写配置再被旧初始化覆盖。若必须新增共享内核扩展点，先提出最小接口与回归范围，不直接修改旧服务默认行为或配置。不复制整个旧 Agent 平台。

替代方案：单纯在当前 KB 提示词拼入九份说明，实施较快，但缺真实工具和长任务执行，拒绝；重建新 Agent/权限平台成本过大，拒绝。为每个 Skill 启动独立常驻 Agent 也无必要：一个岐研 Agent 按需装配能力即可。

自动触发只决定任务和方法，不授予权限，不扩大当前来源集合。单篇封闭解读、翻译和纯润色不自动进行全网综述。工具执行不可用时标记失败或明确降级，不用无工具模型回答冒充相同能力。真正不依赖缺失工具的局部任务可以交付，但标明实际范围。

## 5. 路由与上下文合同

1. 先鉴权，再只从当前账号已发布、已装备且依赖就绪的 Skill 中选择；显式指定优先，但不能越过权限与有效来源。
2. 文章/附件/当前草稿等确定上下文优先，结合用户最终目的、输出要求与最近会话；必要时用结构化意图判断，不能只按“报告/文献/最新”触发。
3. 返回内部主 Skill、子任务、来源范围、输出模式和需要的工具。只装载当前 Skill 的适配说明与所需参考，不拼入全部说明，不让模型执行任意脚本。
4. 模糊且会改变结果时只补问一个关键问题；不让用户先学习或手动选择九项能力。低风险只读行为不反复确认，订阅/草稿提交等有状态操作遵循现有业务规则。
5. 多轮会话保留与当前账号/Study/文章绑定的有效上下文；历史回答是对话，不自动升格为证据。每轮重验材料权限与版本，取消或切身份后的迟到结果不得交付。
6. 执行回执至少含任务ID、实际 runtime、Skill key/version/hash、路由版本、工具/查询/时间/状态、PMID/PMCID/DOI、实际读取范围、来源版本、产物及 Provider 用量。用户界面只显示必要进度、来源、范围、失败与下一步。

## 6. 内容、输出和安全适配

- 去除默认飞书/豆包专属组件、强制文档/白板张数与不存在工具的“已经可用”断言；保留医学方法、来源归属、术语、忠实翻译及证据强度要求。技能名称中的 `doubao` 不绑定豆包模型，仍使用当前项目获准模型。
- 适配结果通过岐研现有会话与本人草稿交付，长文支持分段持久化、恢复、完整性清单；不以 1536 Token 的旧短答配置冒称全文翻译或完整报告。逐任务选择正常模型输出额度，不全局盲目放大。
- 复用现有数值处理矩阵：可靠原词/来源事实可解释；语境不明或无法可靠核验的局部内容标注并保留可交付定性内容；确定性计算由程序完成。来源伪造、越权、失效材料或版本错配不得靠免责声明绕过。
- 患者表达与专业临床表达按当轮身份和目的区分，不把原 Skill 的消费端限制机械覆盖本项目持证专业人员规则。来源缺失和重大风险必须诚实表达。
- 原文件、参考和脚本先做来源/许可、工具依赖及副作用清点。许可不明时不擅自把原文打包成商用发行；可先进行本地适配及专业验证，正式复用状态留待权利记录。不要为临时脚本授予 shell、全盘文件或任意联网。
- 模型沿用租户/账号 Token 额度、并发预留、取消与失败实际用量结算。意图模型、OpenCode 各阶段、长文各段及获准重试的每次真实 Provider 调用均计入同一业务任务及对应账本；取消/失败保留已发生用量，不能仅结算最终回答或双计同一调用。真实 trace 与账本逐次核对。不恢复开发轮次/固定 5 元或 10 元预算门禁，不充值，不自动续额。

## 7. PubMed MCP 部署边界

候选为固定版本的 `cyanheads/pubmed-mcp-server`，不是 NCBI 官方发布；其服务端采用 Apache-2.0，是否适合仍需依赖与实际出站核对。采用本机受限进程或本机 HTTP 服务接入 Hub，客户端及服务端都不接入 Codex。MCP 读工具不意味着任意外部发送均安全：只传主题/关键词/公开文献标识，不传患者资料、私有全文、内部身份或模型凭证。

首步固定工具 Schema、版本和进程生命周期，逐项映射本地 Skill 声明的 11 项能力；固定只读工具 allowlist。启动不得未经审核通过 `latest` 自动升级；核验实际版本的进程/HTTP传输、认证、重试、日志和可选外部提供者，禁用不在本切片来源范围内的自动转接。超时和取消传播到 Provider，未知用量按现有业务状态处理，不盲重试。

复用联系邮箱 `cooperation@pengxc.com`，不代表自动注册账号或向外发送邮件。NCBI 无 Key 请求按其使用规则执行；Hub 与采集服务同 IP/同 Key 时协调总限速。PubMed 题录/摘要与 PMC OA 全文分别记录，获取正文不等于获取所有图片和补充材料。实时结果与 Hub 管理员已审核来源分层；入库、公开与 AI 长期检索继续走现有一次决定审核流程，不自动批准。

参考：[MCP 服务端项目](https://github.com/cyanheads/pubmed-mcp-server)、[NCBI 使用规则](https://www.ncbi.nlm.nih.gov/home/about/policies/)、[PMC OA 范围](https://pmc.ncbi.nlm.nih.gov/tools/openftlist/)。外部条款和工具接口在实际接入前重新核对，不照搬文档中的过期参数。

- 管理员端：复用已有 Skill 版本/发布/装备和审计；先核对 Hub 对应管理入口的真实接线。新增管理控件若母版不支持，先给出具体差异，不因此重设计 G02。具名发布与实际技术装配各自留痕，不能以发布按钮替代真实可用性验证。
- 后端：复用 `Skill`、`SkillAssignment`、AgentConfig、会话、模型账本及已有稿件/来源绑定；优先使用允许的结构化字段，不把脚本路径、MCP endpoint 或明文密钥当作可由模型任意指定的参数。
- 持久跟踪：优先复用旧 `ResearchIntelligenceService.runSubscription` 的增量、去重与授权提交逻辑；本次只读核查尚未发现可直接当作完整 scheduler 的现成装配，独立采集项目也不能仅凭项目存在当作调度已就绪。新增最小 Hub 专用持久调度及可恢复任务执行，仅在本机具名合成订阅演练，用户关闭浏览器不影响运行。须验证时区、下一次到期、单次认领防重、重启恢复、所属租户、操作者当前权限、撤权后不再执行、时间窗、去重、任务状态及失败不推进成功游标；不恢复 WP01 完整排空协议等旧底座工作。
- 不预先建立九套新表。确有长文段落或订阅状态无法承载的持久化缺口时，先列字段、真实复用失败依据、租户约束、只增迁移及测试，再确认最小数据库变更。
