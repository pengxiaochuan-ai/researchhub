# T06 · 自然语言文献问题与真实PubMed检索

范围来源：用户明确推进T06；沿用九项全量规格的S01/S05及T05当前会话守门。当前目录串行实施，一次独立总评审。仅本机专用合成环境，不动临床库、旧服务、旧内核、既有权限或正式部署。

## 最小路径及验收

原AI01直接提问 → 当前授权/默认Skill → 问题拆解及版本快照 → 已审核Hub资料与PubMed实时检索分层 → Hub独立OpenCode受限综合 → 真实回执/来源/正常Token结算 → 原会话持久化与刷新恢复。

1. 测试先行：提取原问题中的疾病/干预、检索目的、显式时间/研究类型；失眠/焦虑等常用表达使用具名版本的检索词形扩展，不作诊断等同。未知限定、排除逻辑或隐私标识不能静默丢弃；必要时只问一项澄清。仅公开主题/英文检索词形发往NCBI，不发内部身份、原私有材料或凭证。
2. MCP复用固定2.11.1/官方SDK/11工具发现，T06只实际绑定search+fetch题录摘要；不宣称S05其余九项逐个业务验收已完成。记录查询、返回总数、实际页范围、PMID/DOI/URL、读取范围、时间及原响应哈希。空结果/工具错误不得用模型记忆补文献；无自动重试、不偷偷切提供者。
3. 来源分层：明确只用Hub资料时不联网；文献检索任务查询PubMed，同时使用能可靠满足限定的Hub获准资料。外部结果标明“PubMed实时结果，未进入Hub审核资料库”，只作为本次本人会话证据，不插入来源目录或更改审核。真实书目数据由系统渲染，AI只写带来源标识的解释；不编造或改写题名、PMID、DOI、年份及引用链接。
4. Hub独立运行时：复用现有私有工作区和旧OpencodeClient，不修改旧池。只装载当前S01/S05适配说明，禁止shell、任意文件、任意联网和外部写入。MCP公开读取由后端受控执行，OpenCode负责当前固定证据的综合；不宣称本轮已允许模型自主无界工具循环。模型BYOK仍留在Hub；隔离子进程只取得一次任务的本机代理凭据，Provider实际用量回到原Sessions/Billing；失败和未知用量保留真实状态，不只结算最终文本。
5. 不新增表：复用Job/Message JSON保存计划、固定证据与回执；提交及读取重验当前账号/Skill/Study和内部来源，外部快照校验归属/内容哈希及原实际读取时间。来源撤审、当前权限/Skill版本变化和取消不交付迟到内容；不把旧回答当证据。
6. UI/UE：保留AI01布局、输入、历史及来源区域；仅接真实结果/必要范围与错误提示，外部来源走真实PubMed回链，不伪造本地文章详情，不新增开发说明。普通使用者无需手选Skill、翻译关键词或填写技术字段。管理员沿用相同已授权会话能力，来源审核页面及公开范围不变。

## 小步顺序

- Q01：问题编译与未知限定/隐私/仅Hub/时间/研究类型负例；纯函数先红后绿。
- Q02：实际Schema核对、受限MCP搜索+题录/摘要读取，归属、去重、空结果及取消/撤权测试。
- Q03：受限OpenCode综合与单任务Provider代理，真实用量交回原账本；先假Provider真实运行时集成，不触发费用。
- Q04：原会话入队/执行/提交/读取接线、真实PG隔离验证；不支持任务仍入队前阻断。
- Q05：保持原位来源展示，真实浏览器新通用问题、刷新及失败保输入；原两个账号，正常Token额度，不充值。
- Q06：一次独立总评审，重要项测试先红后绿；产品/手册/版本/测试与Notion同步。
