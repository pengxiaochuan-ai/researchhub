## 本切片路径

原 AI01 发送 → 当前会话与资料授权 → 服务端目的/上下文路由 → 原子保存 Job 路由快照 → Worker 当前装备/来源/依赖重验 → 已有适配或明确不可用 → 正常业务 Token/用量结算 → 原会话结果/来源/刷新恢复。

九项均参加目的识别；依据操作动词、对象、输出要求、当前文章和近期本人任务，不单凭“报告/文献”一词。当前文章不阻止用户改换翻译/检索意图，但改换不能扩大资料授权。含歧义时只问一个关键问题，不要求手选 Skill。“继续”从同账号、Study、会话内服务端已完成任务恢复目的及原用户问题，实际检索和模型输入均使用该锚点；不把历史 AI 回答作为证据。规则是确定性路由，不宣称覆盖任意自然语言表达。

T06–T13 才交付新的各项完整业务适配。T05 保持已可执行的固定文章解读、当前获准 Hub 资料问答，明确记录 `existing-fixed-article` / `existing-reviewed-hub` 兼容执行器；这不是九项 OpenCode 自主执行已生效。新 PubMed 搜索、全文翻译、订阅、病例/报告等依赖尚未就绪时在入队前阻断，不发送模型，不用原短问答模板冒充新能力。已有正文阅读/会话查看不受影响。

不提前改写已发布 Skill 的 pending-runtime 元数据，不给旧 AgentConfig 横加九项声明与工具，否则旧 KB 专用执行器会失效。后续完整执行适配通过真实验证后再版本化启用。T02/T03 的 OpenCode/MCP 准备结果继续保留，但不得把本切片兼容执行器标记成真实 OpenCode 模型调用。

## 快照及重验

快照含规则版本、Skill id/key/version/source hash、租户/账号/Study/会话、输入摘要、固定文章绑定摘要、实际兼容适配器、必要工具及近期本人路由来源。只从真实数据库有效装备中绑定；默认装备不增加使用、资料或 Token 权限。

在提交、执行准备、模型请求前、结果原子提交前校验。当前账号/Skill 停用、草稿/版本/原包/父会话或证据变化、缺依赖及篡改快照全部阻断；原资料校验和实际用量结算保留。成功结果附真实路由回执，刷新从 DB 恢复；当前装备撤销后新结果不再交付。历史无快照结果不伪造新路由或回写账本。

## 小步与验收

1. 路由正反例、歧义/改意图/上下文恢复测试先失败再实现。
2. 默认装备同事务读取及路由快照，验证隔离、禁用/篡改/版本/依赖负例。
3. 接入现有 Job 创建、Worker、Provider 和提交守门，结果回执持久化，不改前端结构。
4. 专用 PG、真实 HTTP 验证不支持任务零入队/模型；用全新公开来源问题验证真实兼容执行和账本，无临床材料/充值。
5. 真实浏览器发送、恢复、不可用错误保输入；独立总评审、living spec/手册/版本与 Notion 同步。

T05 的通过是路由与校验真实接线通过，不代表 T06–T13 新能力专业验收通过。若发现必须新增迁移、共享内核或其他权限，报告具体差异再确认；不重问九项默认装备或本次路由授权。
