# 科研课题流程设计：核对与评审记录

日期：2026-11-11。范围是用户本轮要求的 ResearchHub 课题创建、数据录入、访视问卷与分析流程设计，不是实施、部署或历史任务恢复。

## 现状核对

- 两个只读子 Agent 分别核对旧底座执行/数据/分析契约和 ResearchHub 产品/页面/服务装配；未改文件、未查询数据库或读取真实被试数据。
- 主 Agent 核对产品基线、PRD/用户路径、既有执行准备/合成 EDC/方法/S08 规格，检查关键路由、作用域及模型；具体源码证据在[设计草案](../../product/research-study-workflow-design-2026-11-11.md)第15节。
- 外部数据治理与归档语义参考官方 ICH E6(R3) 和 CDISC ODM 文档，仅作设计依据，不主张认证或替代团队研究政策。

## 独立可实施性评审

全新只读 reviewer 阅读设计，并对必要位置核对现行基线与代码。原评审提出两项重要补充，没有将本次设计审查当代码或专业能力验收。

| 原意见 | 作者处理 | 状态 |
| --- | --- | --- |
| Hub负责人既有业务权限未显式承接，可能误实施为逐Study加成员 | 第10节补明有效Hub负责人、本Hub实际Study绑定、与关注/内容协作的区别及服务端约束 | 已由作者补充；未独立复签 |
| 撤回同意对既有数据、未来分析/导出及派生产物的效力缺业务输入 | 第6节补当前范围向快照/分析/报告/资产/导出的传递与交付前重验；第14节列明确认输入，区分保留审计与禁止新使用、外部已发包处置 | 已由作者补充；待研究团队提供实际政策 |

Reviewer同时指出验收应串同一新案例，并预先固定独立计分/方法预期。已补入第14节；这是未来实施规格的用例收口，不将其写成已执行测试。

原稿、作者修订与未来实施批准分开：本稿仍为 V0.1 评审草案。Project/Study 的薄映射是建议路线，物理表/ID/授权/迁移须在 A 批具体规格确认；正式 Protocol/CRF/SAP/同意政策等输入不由工程师或 AI 代定。

## 本轮验证与不适用项

- 文档本地链接、代码围栏、标题唯一性与证据文件/行号做静态检查；检查结果写在 progress.md。
- 针对本轮修改路径执行 git diff --check；结果写在 progress.md。
- 业务代码、页面、API、Schema、运行配置、模型调用和部署均无本轮变更；单元/PG/API/构建/Playwright业务验收不适用（仅设计），未重跑旧证据，不声称正式功能可用。
- 本轮仅新增设计/规划记录，并在文档中心及版本记录登记；现行产品实现基线和使用说明书不改写为规划能力。
- Notion同步以指定研发文档下 ResearchHub 的 product/planning 章节为目标；正文与本轮记录同步，不发送患者数据、凭证或历史数据集。

## 检索与工具异常

- 本机没有Paseo独立模型配置文件，沿用原生子Agent的当前会话配置。
- 首次路径模式触发zsh无匹配，随后改用限定目录rg --files，未扩大扫描范围。
- 部分历史文档/索引篇幅较长，后续改为定点读取；不从旧文档的“下一步”恢复任务。
- Notion首次更新因参数及Markdown往返规范化未匹配而被拒绝，未删除任何内容；按工具返回重新读取当前正文，改为基于实际文本的定点替换。
