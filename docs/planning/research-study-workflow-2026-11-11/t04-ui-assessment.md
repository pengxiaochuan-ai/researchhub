# T04 研究准备页面接线评估（只读，2026-11-11）

本文件是实施前评估，不表示正式配置接口、页面、目标环境或业务验收已完成。依据当前代码、T04/T05 计划、流程设计和 M02/M06/M08 复用清单；本轮未在浏览器观察页面，几何与母版差异必须在实施前按同视口实测，不能仅由组件结构认定一致。具体 HTTP 方法、字段名、原子性和权限以主循环确认的服务端契约为准；下文是 UI 所需语义，不是现有 API 声明。

## 现有承载事实

- 新研究 S01 `ResearchStudyOverview` 使用 `researchStudy=1&studyId=...`，读取 `/research-studies/:id`，研究准备卡片仅显示状态，没有配置入口。目录 Q02 与 S01 已承载当前研究入口，不能把课题意图 ID、产品 studyId、旧 researchProjectId 或本人 researchPlanId 当作同一 ID。
- S11 `executionPreparation=1` 是 `ResearchExecutionPreparation`，依赖 `studyGroupId + researchProjectId + researchPlanId`，是本人私有合成草稿；现有四个卡片“结局定义 / 访视安排 / CRF字段草稿 / 结局—字段—访视映射”可参考其原有布局和交互骨架。它没有正式 Protocol 或已发布 FormVersion/ScaleVersion 关联；默认基线/随访只是待确认占位，不能复制为正式事实。试填、AI 核对、历史、合成 EDC 亦有各自边界，不得混为正式写入。
- 普通真实 S11 由 `MemberInvitations` 承载 Study 成员与邀请；先匹配 executionPreparation 再匹配成员页。保留该入口、授权和行为。S02 `designWorkspace=1` 是本人设计草稿列表；S07 同标记加 planId 是本人设计详情/编辑。它们是本人合成设计流，不是正式研究方案的同一对象；不覆盖原路由、历史、PICO、AI 或合成 EDC。无这些受控参数时真实 S02 是 pending，S07 不能假设自动进入正式配置。
- `platform-shell.js` 对成员、设计、执行准备顺序覆盖页头；`workflow-main.jsx` / `missing-main.jsx`、`real-mode-route.js`、`designIdentityMode`、`session-lifecycle.js` 安全返回参数白名单均需同一分支识别。旧 `readPreparationLocation` 本身并不拒绝所有未知参数，新入口须主动拒绝混合标记、重复键和未知键，禁止错误链接落入旧成员、演示或其他研究。

## 最小页面路径与数据语义（待后端契约）

| 页面/区域 | 拟承载 | 核对与继续 |
| --- | --- | --- |
| S01 研究准备卡片 | 服务端真实准备状态和一个“配置研究方案”入口；读取权限不足时保留受限信息 | 带当前有效 studyId 到 S11；无配置显示待准备，不冒称已批准或已启动 |
| S11 受控正式配置分支 | 沿用执行准备现有卡片顺序：方案基准与状态、结局、访视、表单及量表、结局映射，单一保存草稿主动作；仅呈现实际契约支持的字段 | 已保存值回读；访视展开关联的全部 requirement，选择已发布且适用的表单/量表具体版本并核对来源、名称、版本及填写方式；结局指向具体字段/量表与访视。未确认参数保留空值和待确认，不伪造数值 |
| S02 正式研究分支 | 研究内方案列表/摘要，明确名称、草稿/当前状态和版本，空态提供进入配置；每行打开 S07 对应版本 | 列表、预览、详情、编辑始终指向同一个 study + protocol 版本，不展示本人合成草稿充当正式方案 |
| S07 正式研究分支 | 同一方案版本详情，显示正文、结局、访视要求与固定表单/量表版本；有权且该版本可编辑时返回 S11 继续编辑 | 历史/已执行版本只读；显示来源及状态，返回 S02/S01 保持 study scope，不提供 T05 未实现的批准/启用成功状态 |
| 管理者 | 从现有研究目录进入同一 S01→S11/S02/S07，使用服务端返回的实际能力和状态 | 本租户管理员按当前身份的业务权限执行，普通研究者按当前研究授权；不增加全局导航、伪成员或绕过版本/租户守门。T05 再落审批启用入口 |

建议新分支使用互斥标记，例如 `formalPreparation=1&studyId=...`，S02/S07 使用相同研究范围标记和必要的服务端版本标识；最终参数以主循环契约为准。所有链接通过统一构造/解析器，严格限制唯一键、标记值和标识；后端按当前用户解析产品 study 到合法执行父链，UI 不凭 URL 自动授予权限。若首次无 Protocol，以空草稿状态展示，明确保存后才成为持久记录；新增与追加访视回读所有 requirement，不用本地默认覆盖服务器列表。选模板/预览不得触发旧内置模板初始化写入；试填只用纯校验，不能调用 assignment/draft/submit 等正式副作用方法。

### 必须由服务端给 UI 的信息

1. 当前研究身份、标题、可读/可编辑能力、方案 ID/修订或并发基准、状态、最后保存结果与明确的发布阻断项；所有版本固定所属研究、当前授权与审计。
2. Protocol 草稿的确认字段及缺项；VisitPlan 的名称/顺序、明确锚点与偏移窗口（尚未确认允许空值）、每项 requirement 的类型、必需性、来源及固定模板版本；新增和追加的完整回读。
3. 可选择的已发布 FormVersion/ScaleVersion 的不可变标识、名称、版本、适用范围、来源与填写方式；只读预览所需 schema，量表计分依据及可用状态。无确定规则显示“未计分”，不由 AI 编造或计算数值。
4. 结局定义与关联字段、量表版本和访视的稳定引用；单位和缺失处理以确认材料为准。不把 UI 临时键当后端持久身份，也不把旧方案草稿隐式转成正式配置。
5. 服务端冲突、字段错误、权限失效、对象不可见、请求结果未知的可区分语义，以及重读或幂等重试约定。是否有多步保存、部分成功、版本发布另由后端契约明确；不得在 UI 伪装成原子成功。

## 状态与恢复

- 保存中防重复提交；成功后回读并在原位置提示保存结果，用户输入在请求期间变化时不得被旧回执覆盖。网络中断/超时/5xx 区分结果未知，保留输入和原请求身份，先核对结果再重试；不能另建重复版本。409 保留输入与基准，展示最新版本并由用户决定如何处理，禁止静默覆盖。
- 401 按统一会话进入登录并安全返回原 study 路径，不重放写操作；403/404 撤销受限内容、提示原因及返回，不将普通网络故障当退出。后台刷新不得覆盖未保存输入，迟到响应不得跨身份/研究显示。
- 站内离开或放弃未保存修改采用共享确认组件，说明影响，取消/Esc 保留内容、焦点约束及返回；浏览器刷新/关闭保留 `beforeunload`。旧 S11/S07 现存 `window.confirm` 在涉及该页的实现时逐项替换并保留原条件，不引入重复确认。输入错误定位字段并说明保留情况；14/22、共享 Button、窄屏重排和真实风险/来源/权限可见。
- 版本/试填和正式采集分开：未确认字段允许保存草稿但不得发布；版本替换及历史受试者影响不静默改变。T04 完成仅意味着配置可保存、回读；T05 负责审查、批准、启用及迁移影响。

## 需用户确认的真实布局差异

有待确认，不能宣称“没有差异”：目前正式新研究没有 S11 配置视图；真实 S11 既有成员邀请页，合成执行准备虽有四个卡片，但没有正式方案/已发布表单与量表/要求项绑定。将其作为新 studyId 分支的母版会新增这些内容与 S01 的入口，且 S02/S07 新研究分支与既有本人草稿页对象和部分内容不同。上述最小方案是复用既有区域/顺序与受控路由，尚未证实与用户确认母版同视口一致；需先在真实浏览器只读观察并逐项列出原样、拟改样、原因及影响，再按项目规则取得对实际布局差异的确认。不得用“接线”名义覆盖成员页或私有草稿页。用户已授权连续开发不自动消除既有明确的布局差异确认规则；若主循环持有更具体的已确认母版，应先核对该证据。

## 后续验证要求

按目标环境分别覆盖研究者、负责人/租户管理员、无权与跨租户；验证 S01→S11 保存→刷新回读→S02 列表→S07 详情→S11 编辑同一版本，以及失败/冲突/未保存恢复、版本固定、纯预览和旧合成分支回归。单元、集成、功能 UI、真实浏览器 Playwright 截图/录屏及母版同视口对比留痕；真实执行、环境启用与专业用户验收各自举证。全程使用合成数据，不将验证结果称为生产或临床专业验收。
