# T05 审批与启用实施契约

日期：2026-11-11。范围为同一 Study 的方案审批、启用及历史转版；不另建 EDC，也不代表真实临床政策已批准。

- 沿既有 ProtocolVersion、VisitPlan、Requirement 和 StudyOperationsService 的 release/transition/activate；真实身份与 Study 父链、租户当前权限及 `study_operations` 在同一授权事务内重验。租户管理员依 ADR-0006；Hub owner 的配置权不自动赋予审批权。普通成员还需 workbench、study.configure 和 project_manager；不采客户端 actor/scope。
- 每个方案绑定不可变政策版本，记录录入与审核人/时间、材料来源及筛选、研究同意、数据使用、撤回、安全、中心、盲态、采集审核各部分。缺省为 missing；不适用须明确状态、理由、来源、责任人和日期。实际临床规则由团队提供；单中心、非盲或合成案例均须明确记录，不可推断。需多中心或盲态但相应机制缺失时阻断启用。
- 方案 `draft → pending_review → approved → executing`；提交后配置不可原地修改。批准和启用必须在锁内重新检查完整时间、固定版本引用、发布检查与已审核政策，记录政策和方案版本、审核/启用责任与时间；不得因 Remediation 未装配而跳过守门。旧入口同样守门，避免绕过。并发或权限变化时拒绝并回滚。
- 新版本启用默认不迁移既有入组、访视及结果；替代关系和旧记录保留。历史转版先预览固定来源/目标版本及受影响集合，再显式提交并重验预览和权限，全部成功或事务回滚；不可静默覆盖历史。旧 activate(migrate=true) 未能证明预览一致前必须拒绝。
- canonical Prisma schema 与唯一迁移链新增政策/审批事实；只生成迁移，目标合成库无完整 applied 历史，不执行 migrate deploy/db push。回滚为停用新入口、恢复服务版本，保留审计和旧版本；DDL 回退仅经数据备份与依赖核查后由运维执行。
- 首期验证只使用隔离的合成 fixture；不可将合成决定称为临床 IRB 或专业验收。缺真实材料、部署、真实业务执行或专业签收时分别标明，不宣称正式启用。

## 首版结构化政策边界与后续执行

政策的九项分别为伦理、筛选、研究参与同意、数据使用、撤回退出、安全、中心、盲态和采集更正审阅。每项明确 `missing/configured/not_applicable`，后两者须来源、理由、决定人及时间；决定人和时间由认证服务端生成。已支持的机器判定只有：中心 `study_wide`，盲态经明确依据 `not_applicable`，以及审核独立性 `required/not_required`（required 时审核人不得是政策录入人）。需要受限多中心或盲态机制的研究保持阻断。其余材料及条目、用途、责任和保留规则目前是需要人工核对的材料引用/描述，不能被当作 T06/T09/T15 自动执行判断；相关下游正式操作必须由后续任务先提供结构化规则和执行守门。不能由合成案例的不适用决定推断临床豁免；真实临床启动、采集及专业验收仍需团队确认和相应执行机制。

治理入口需按当前身份、租户与 Study 作用域返回待审事项和安全站内链接，不接收任意租户参数；发布、提交、审核、启用分别返回能力。退回只允许 pending_review → draft，原因和责任人记入审计；已批准版本不能退回后原地修改。预览和转版提交绑定受影响集合与版本，任何变更须重新预览。
## 责任人展示增量（2026-11-12）

读取方案审核详情时，只在当前已授权事务按本租户的政策记录人/审核人账号ID查询显示名称，增加 `createdByName` / `reviewedByName`；不读取联系方式、不改不可变政策内容或哈希。原账号ID、时间和来源仍保留供责任详情核对，普通页面优先显示姓名/显示名称，缺名称如实显示“已记录”。提交回执仍保留原提交结果，读取详情返回最新名称；名称不构成新权限或审核依据。
