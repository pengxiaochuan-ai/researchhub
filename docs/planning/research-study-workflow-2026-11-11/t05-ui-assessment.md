## 任务路径与最小页面影响

1. **S11 草稿准备**：保留研究与方案基准区和四张配置卡；在现有方案基准/状态位置呈现服务端状态及准备情况，并在已有配置流中提供政策录入/补充入口。九项为伦理、筛选、研究参与同意、数据使用、撤回退出、安全流程、中心范围、盲态、采集更正审阅。先显示实际状态和缺项；常见操作按团队确认材料合理预填表单，但全部默认为待确认，不能凭单中心/非盲/合成自动认定完成或不适用。用户明确选择不适用须说明理由和来源；责任人/日期由服务端根据当前真实身份与时间记录，而非用户任意填报或前端推断。
2. **S02 列表 / S07详情**：显示同一Study固定Protocol与政策版本、状态、责任人和时间及可回读的阻断项，点击具体版本进入现有详情；不可将草稿列表的普通配置权限显示为审批权限。草稿可编辑，提交后该版本只读，方案/政策更改使用后端支持的新版本或退回机制，不擅自覆盖历史。若接口不提供退回或创建新版本，不伪造入口或成功反馈，说明真实可用状态并与后端收口。
3. **按能力和状态选择唯一主动作**：草稿且可配置时「保存/完善」或确认无未保存输入后的「提交审核」；待审核且当前服务端授予审核时「审核方案」；已批准且具启用权时「启用方案」；执行中以状态和历史为主。当前角色不可操作时可只读查看，显示真实限制。Hub owner 的配置权不能作为PI/审核证据；租户管理员按服务端当前权限，同样经过完整状态及版本门禁。
4. **治理审批入口**：当前G01并非真实审批页，不能直接跳演示数据。优先复用G02现有「待处理事项」列表及伦理合规模块，增加服务端授权的待审研究方案事项，点击直达同一Study与固定版本的真实审核视图（现有S07/S11的能力状态操作）。这样不新增一级导航或第二个配置页；具体G02条目适配、列表/分页、已处理历史和安全回链要以授权待办API和实际母版为准。若接口尚不提供管理员跨Study待办，仅从已有研究目录进入该研究，并将治理聚合入口明确标为待接入，不能声称管理者完整发现流程已交付。
5. **审核和启用**：从同一版本只读核对方案、政策、材料来源、未满足项、当前责任人后按当前服务端能力分别提交审核决定及启用；伦理批准与本系统方案审核分别呈现，不借一个按钮暗示伦理已获批。真正有不可逆影响的确认使用共享站内弹窗，明确对象、版本及影响，取消/Esc和焦点恢复；不叠加无意义确认。提交前允许调用只读发布检查，失败显示具体可修复位置而不是统一绿色。
6. **历史转版**：默认新执行版仅作用未来入组；已有入组的变更须单独只读预览来源/目标版本、影响对象、访视及已有结果，展示不兼容与审批前提；显式确认原预览后，由后端在当前权限和原版本上重验并执行，失败显示保留状态及重试方式，不篡改旧记录。预览为空不等于已有对象已迁移；无迁移能力不得以启用结果冒称已转版。

## 需后端固定的 UI 契约

- 每Study可见的方案及每版状态/固定政策版本、具体阻断项与定位、当前审阅/批准/启用动作能力、实际责任人和时间；按身份和父链重新核对。`canConfigure`、`canReview`、`canApprove`、`canActivate`、`canMigrate`不得互推。
- 九项政策的具体状态、理由、来源、录入/审核责任、服务端版本和变更并发基准，服务端独立判定已满足/不适用/阻断。后端当前草拟状态 `missing/configured/not_applicable`，site仅配置 `study_wide`、blinding仅有依据的 `not_applicable` 可放行；本说明不推定其他临床模式可运行。采集审阅政策须明确是否独立审核；要求独立时由服务端核验政策录入人与审核人不同，UI不得把配置者直接当审核人。
- 检查、提交、审核、批准、启用和转版各自输入及完整成功/失败回执；确认两个审批动作还是单个审核决定、退回及重提规则；unknown结果在原账号+Study+版本恢复同键/原载荷，不自动重放。只读preview不能触发正式写入，审计来自后端。
- 若提供管理者待办，明确完整范围、分页/过滤、读权限、稳定标识、各项到具体Study及版本的回链、待审/已处理口径与撤权行为；不可依据普通成员本人列表伪称全租户。
- 历史转版预览ID/固定版本/影响集合与时效、失效后重预览、可见数据范围、冲突回执及事务边界；由后端规定，不在页面用对象数或本地缓存推算。

## 反馈与验收边界

沿用共享Button、14/22、Shell、站内确认、beforeunload及T04授权/身份epoch、失权清除可读内容、未知结果原键恢复；网络错误不当退出，未保存输入及冲突处理有明确恢复。草稿、待审、批准、启用必须刷新后回读，不以本地状态假冒持久成功。真实Chrome使用合成账号分别走科研者、负责人、租户管理员、无权和跨租户/撤权，覆盖版本锁定、政策缺项/不适用理由、审批/启用守门、转版预览失效及无历史静默变更；保留截图/录屏、真实HTTP与数据库证据。代码、目标配置、真实执行和团队专业确认分开陈述。

## 待确认的布局影响

政策录入和审核决定是T05新信息，拟放在S11现有方案准备流及S07固定版本详情的原内容区，治理入口复用G02既有列表；现有S11四卡顺序、S02列表、公共Shell和一级导航保持。现阶段后端响应与G02待办来源尚未确定，故无法声称细节与母版已做同视口对照；若实现需新增独立页面、重排四卡或改治理导航，须把原样、拟改样、原因和影响提交主循环核对后再实施。本轮未改正式组件、路由、服务或数据库。

## 历史转版的最小接线（2026-11-12）

沿用方案审核与启用卡内的折叠区域：按受试者编号分页选择，预览显示来源与目标版本、旧访视、待取消任务及阻断原因；候选不代表可转版。仅经服务端许可且预览允许时，填写理由并在站内确认后执行。预览令牌仅存在内存，账号、研究和方案切换或撤权清除；页面刷新后可显式重放原预览取回有效令牌。执行结果未知时保留不含令牌的原请求信息，通过当前权限与账号范围内的只读回执查询核对；404仅表示暂未查到，不能推断失败或自动重做。预览过期须重新核对，不能将未知执行当成未执行。现有卡片顺序、公共 Shell 与导航不变。真实转版仍须完成后端并发守门、独立审查及目标环境验收。

执行结果未知时，用户先只读核对原执行回执；暂未查到时可在原预览有效且原入组仍可核对的条件下显式恢复原预览、复核原理由并确认重试同一请求。若原预览过期或对象无法核对，继续保留未知状态供后续查回执。已固定政策不展示只适用于草稿提交的提示；责任人优先显示可读名称，缺少名称时显示已记录，账号标识仅在责任详情按需查看。
