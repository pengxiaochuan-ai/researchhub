## 一条任务路径：对象、状态、下一动作、结果

1. **找到本次访视**：S04 选择当前正式 Visit；S09 顶部显示假名编号、访视名称、计划与实际时间、窗口、状态、固定方案/表单版本和返回 S04。时间或锚点未知显示等待安排，不计算或补造；不存在/错父链/撤权显示受限或不存在，不跳到其他 Visit。访视列表如由后端提供，分页和筛选只覆盖真实授权范围，不声称全部中心或研究规模。
2. **核对必采项并分配**：显示该 Visit 的固定 requirement 名称、必填性、现有分配/响应状态和缺项。仅按服务端当前 `canAssign` 且指定固定已发布 FormVersion 分配；已有分配直接打开，不要求用户填模板 key 或内部标识。每条响应只归其真实 Subject/Enrollment/Visit/固定表单；其他文件、量表或干预要求如果此包不能采集则明确未完成，不把同日记录自动当作证据。
3. **录入、暂存、提交**：按固定已发布字段标签、类型、选项、单位和验证规则呈现真实输入。空白、0、false 和接口明确支持的缺失/未测/不适用分别保存，不以空值生成 0 或推断缺失类别。只读查看已保存值；有写权时先暂存再可继续填写，提交前显示明确缺项。提交成功只在重新读取后显示当前状态。评分仅在服务端按固定已发布 scoring 返回时显示；缺失、未知算法或未计分显示未计分，不做 AI 数值运算。
4. **更正与疑问**：已提交数据先只读，授权人员显式进入更正、填写原因并比较当前值和拟改值；保存后展示新修订，历史保留，旧审阅是否失效以服务端事实显示。疑问准确指向指定修订及字段或文件，从 S05 进入后定位该项；回复、更正和关闭分别呈现，回复或更正不能自动冒充关闭。关闭理由、责任与时间来自真实授权记录。
5. **审阅、锁定与访视完成**：当前动作基于独立服务端能力、固定政策及当前修订：审核通过/退回按实际权限和独立性，退回需原因；锁定仅作用当前表单，解锁需原因及影响确认；更正后旧审阅失效，历史保留。访视完成或已完成后的重新核对必须依据该 Visit 实际全部要求、最新证据与当前审阅，不把一个已提交表单当整次访视完成。风险确认使用共享站内弹窗，支持取消/Esc、键盘焦点恢复；普通暂存不重复确认。

## 当前源码可见的接口，尚需集成方锁定

- 当前 Hub 代码已有 `GET /research-studies/:studyId/assignments/:assignmentId`、`POST .../visits/:visitId/assignments`（固定 `formVersionId`）、`POST .../assignments/:assignmentId/draft|submit|correct|review|lock|unlock`，以及 assignment 和命令的按原请求键只读回执。写入由服务端确定 scope/actor 并重验访视、入组、同意、政策和固定版本；路径和返回以最终控制器及目标环境核验为准。
- 可见的 assignment read 返回固定 `formVersion.schema/scoring`、当前 response 的状态、版本、答案、可空分数、内部 ref、审阅/锁状态及 `canSaveDraft/canSubmit/canCorrect/canReview/canLock/canUnlock` 和禁用原因。修改基准 version/ref、请求键和 hash 只由系统管理，不出现在普通输入或说明；用户可按需查看来源/修订说明而不需理解内部哈希。
- 可见 Visit 投影包括受试者假名、访视计划与要求、分配、窗口及 `canAssign/canComplete/canReverify`；列表/详情 Hub 路由、访视开始/完成/重核、疑问的 list/detail/create/reply/close 及跨页精确定位字段仍须主循环提供最终契约与实际权限。不能将旧 `DataQuery` 服务存在推断为完整 Hub 路由或已支持字段级回复。
- 正式 S09/S05 scope 参数须和现有 `projectId` 演示、S05 `syntheticCapture`、其他真实分支互斥；显式 Study、Visit、Assignment 和问题定位按服务端授权父链检验，`real-mode-route`、身份模式、header/面包屑、session-lifecycle 安全返回同步。无效/混杂/重复参数不能回退演示、其他被试或旧页面的默认示例。

## 身份、失败和恢复

只读者可查看当前授权范围与历史，不显示无权限动作；研究者的填报、更正能力与管理员/有权审核者的审阅、锁/解锁、完成能力分别依服务端返回，Hub owner 或租户管理员身份标签不能代替具体授权和政策判定。允许的查看范围、撤回同意后的历史可见性和当前写入能力分开表述。角色变化、撤权或身份/认证版本变化立即清旧对象、草稿与待发内容，使迟到读写不回流；网络 503/超时不能当注销，保留尚未发送输入并禁止未核对的新写。

未保存表单只在当前页面内存；跳转用站内确认及 Esc/焦点恢复，刷新/关闭有 beforeunload。对于已经发送且结果未知的命令，必须有同 actor、认证版本、Study、Visit/Assignment、动作及原请求键的恢复：用户显式核对，绝不自动重发；15 分钟后删除含答卷的原命令内容，仅留不含答案或凭证的 scope+动作+请求键未知标记，继续禁写；调用当前授权的原键只读回执，404 仍是未知，成功后必须再读当前对象，不能让旧回执覆盖后来修订。15 分钟以内跨刷新是否允许存含患者答卷的原请求，必须由主循环结合当前用户授权、数据治理和最终契约明确；未经明确允许，不把答卷/人口学/凭证放入 sessionStorage 或 localStorage，也不把答案记录到日志或录屏之外的测试元数据。若只保留内存，刷新后只能按标记查回执，不能声称可以重放丢失正文。

冲突或政策变化时保留未发送输入和原并发基准，显示当前版本已变化并允许核对，不用后台轮询把新版本写进编辑基准；有锁、无权、用途撤回、其他窗口已提交、更正或审阅使本次动作失效时展示真实原因，不静默覆盖。成功写后如果 GET 失败，显示“已保存但当前状态暂不可核对”，禁后续动作直至重读；同键回执必须验证 actor、动作、目标和 scope。
