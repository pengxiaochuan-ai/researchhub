## 当前行为

公开 `/h5/questionnaire/:token` 先 POST 原邀请恢复/兑换会话，取得 assignment 后 GET 当前问卷。GET 当前状态、GET 原回执和 draft/submit 全部携带 expectedAssignmentId，后端授权锁内核验，前端也校验响应目标。多标签共享 Cookie 时 A 问卷不能读、写或核对 B 问卷，错配清除当前答案。无后台身份、导航或数据可见范围扩张；URL token 仅当前内存与邀请 URL，no-referrer，原 token/会话凭证不写存储、日志或证据。

当前问卷可填写、显式暂存、刷新继续、核对后提交、提交后只读。0、false、未填写缺省及显式 null 分别保留，不补填或推断数值；没有确定性评分时后台显示未计分，H5 不生成分数。提交确认、CAS 放弃确认均使用共享弹窗，Esc/取消/焦点恢复，刷新关闭保留 beforeunload。CAS 保留原输入，读取最新内容后由用户明确选择放弃；网络/503 不当成退出或成功。

未知保存持久标记仅 assignment/action/key，答案仅当前内存和用户明确保存的服务端草稿。刷新后仅 GET 原回执；404 仍未知并禁写，200 核验原键/动作/目标后 GET 当前问卷。未知内存十五分钟后清除，保留最小标记；不自动 POST、不用新键重发。当前同意撤回、过期、权限/父链/邀请目标变化清除敏感内容。

S09 按固定 requirements.allowedCaptureModes 选择现场录入与自填，缺省仅研究人员，非法集合关闭采集动作。patient_h5 行内可明确登记接收邮箱和邮件渠道同意，再确认发送一次；未知发送只 GET 原回执，不提供 POST 重试。visit.assignment 的安全 emailInvitation.invitationId 定位状态，无邮箱/token 常显；刷新后可读取已兑换、已提交、服务商接受、明确拒绝或未知状态。服务商接受不声称送达。S11 三个明确方式选项保存到新方案草稿，S07 显示同一范围，已执行方案不直接改写。

## 失败与边界

保留失败 `h5-ui-59e839b5`（选择控件名称包含选项导致精确定位未匹配）、`h5-ui-8b8cb69c`（测试误把选填缺省预期为 null，已修断言，未改答案）、`h5-ui-b6440327`（真实共享前端验证把 optional number 的 null 当数值错误）及 `capture-email-ui-50138afe`（新增采集方式控件名称含选项）。共享字段给可见标签显式 aria-labelledby，新增方式给显式 aria-label；null 回归先 RED 后 GREEN，选填缺失可提交，必填 null 仍阻断。最终全链重新通过。

390/200% 的后台顶栏现有全局搜索与身份区域重叠仍为冻结 Shell 限制，正文区域和控件可操作，本包未将其悄然重设计。公开 H5 无该 Shell，320–1440 及原生 200% 均实测。跨邀请切换会严格防串题，不自动找回另一邀请的 Cookie 会话或重新兑换已用令牌；不可恢复时页面引导联系研究团队。漂亮路径已在本机 Vite dev/preview 重写并参与构建；正式静态服务器的同等路径回退需部署时配置，不能把本机页面当公网已发布。
