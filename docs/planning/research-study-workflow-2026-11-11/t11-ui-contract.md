带邀请链接每次初入先 POST token resume，再 GET 当前会话，绝不先显示旧 Cookie 对应答案。令牌只在 URL 与当前内存，页面 Referrer-Policy 为 no-referrer，不写浏览器存储、不进入证据/日志。会话 Cookie HttpOnly；未知标记只含 assignment/action/key，无 token、会话凭证或答案。答案仅当前内存与用户明确暂存的服务端草稿；刷新丢弃未保存输入、GET 已存草稿。未知提交刷新后仅 GET 原回执，404 保持未知并禁写；200 核验原键、动作及 assignment 再 GET 当前状态，无自动 POST。当前页未知正文十五分钟后丢弃，不以新键重发。CAS 保留输入并展示核对/放弃路径；当前同意撤回、过期、邀请错绑/失权清除内容。

多标签会共享 H5 Cookie，写命令须在服务端同一事务核对 expectedAssignmentId，避免 A 邀请答案写入 B。前端 GET 当前会话和 GET 原回执都携带 expectedAssignmentId，写命令同名字段也在服务端同一事务核验；结果与当前重读再严格核对已绑定 assignment。后端保护未启用前不以跨标签测试通过销项。

S09 仅在已有“本次采集要求”的 patient_h5 行中增加邮件邀请折叠区：地址、明确邮件同意、一次发送确认、服务商接受/明确失败/结果未知/已兑换/已提交的当前状态，及现有回收表单链接。无原地址/token 常显，未知发送只查原回执不重发；SMTP accepted 不表述为送达。现场填写按钮按完整 allowedCaptureModes 决定，不从标题推测；无配置仅 researcher。S02/S11 现有 requirement 行追加采集方式选项及详情展示，仍由协议发布固定，不修改已发布协议。
