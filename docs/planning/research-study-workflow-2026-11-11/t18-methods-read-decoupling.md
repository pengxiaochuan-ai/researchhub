# T18：S06 精确结果与近期列表读取解耦

实施依据：本轮 `t18-acceptance-contract.md` 的读取解耦补充。27 条近期运行逐项重验超过 20 秒，原先把精确结果串在列表之后，造成已有 Run 无法核对。

保持现有页面全部 Card、动作、导航、数值及当前权限/来源/算子核验。精确 Run 或快照先完成独立核验，之后在原“近期分析运行”Card 读取真实列表。仅固定的只读列表 GET 使用 60 秒上限，其余请求仍为 20 秒。原重新读取动作可重读列表；10 秒 quiet 核验只读精确上下文。无精确上下文时仍须取得真实列表，不能将未载入当空。

近期列表具有独立取消与代际，身份重置时作废；读取前后核对原账号及 authVersion。普通列表失败仅显示“近期分析运行暂不可读取，请使用‘重新读取运行与来源’重试。”；401/403 仍清受限内容。列表状态为“正在读取近期分析运行…”、失败或真实空集合。迟到列表只能更新列表，不能写当前详情、触发写操作或更改原键恢复、15 分钟内存期限。

并发补充：列表前后的身份 GET 使用独立的原 20 秒客户端，与 60 秒列表一起取消。写入或原键恢复开始前取消该读取；已恢复/未知标记存在期间暂停近期列表，原 Card 显示“请先核对上次操作结果，再读取近期分析运行。”，不使迟到的旧身份响应误删正在核对的原键。成功 ACK 后由已释放的 writer 启动新列表，写前旧状态不能覆盖新的审核状态。独立审阅发现的两项实际 hook RED 已留痕，修后相关 23 项纯测试通过；此结果仍不替代根任务的真实浏览器验收。

范围：`useFormalMethods.js`、`FormalMethodsWorkspace.jsx`、一个专用读取 helper 及相应纯测试。不改共享客户端、入口、后端、统计值或 T17 冻结合同/检查点。纯测试验证精确结果不等待列表、来源变化停止展示、60 秒仅用于列表以及失效代际/权限拒绝；真实 Chrome、完整构建与当前主 Run 续审由根任务统一执行。未完成真实验收前不标记功能完成。
