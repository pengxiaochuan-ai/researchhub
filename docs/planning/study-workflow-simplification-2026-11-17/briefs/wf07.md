# WF07 确认数据并开始分析 · 实施合同

当前唯一实施为WF07。WF06已归档`wf06/final-manifest.json`（SHA45e444c1c13937c069c6f0762b1fa419063522e2942a6a418a0adc1b3470f899），14文档/11页Notion及本机四层齐备。对应用户已批准的“分析计划、数据预览、放行、计算”精简项，不实施WF08后台调度，不改变临床规则或Frozen Shell。

## 任务与页面差异

在当前已批准计划内，保留原值、来源、结构质量阻断和放行理由。系统以只读请求准备当前数据预览；用户核对后使用一个“确认数据并开始分析”动作，在一个站内确认框明确数据放行与开始本次计划的计算。系统顺序调用原生服务，不要求再次选择同一研究、计划、快照或运行。审批分析计划仍单独由有权人员决定。

普通描述统计与已登记整课题分析都覆盖，沿各自原页面布局，保持当前研究上下文。不可执行时显示实际阻断及对应原入口；无运行权限者仍可按原权限回看数据或只放行，不通过隐藏权限问题来冒充合并完成。不加入未来访视必须全部完成等新门禁。

## 已核原生事实与三侧影响

- 普通分支：`useFormalAnalysis`管理计划、预览、放行及原键回执；`useFormalMethods`管理原生统计运行。`POST /analysis/runs`已经原生准备工作台、创建并执行确定性Worker，通常返回待审核结果；普通分支没有可调用的process接口。准备工作台可能创建当前actor/project所属Session，验收预算须计入，不调用模型或恢复旧任务。
- 整课题分支：`useFullStudyAnalysis`的快照放行后创建group；原生create会登记group并执行第一片，process才负责后续分片。不得把create误当无副作用准备步骤或因丢响应新建第二个group。
- 两分支仍由原服务分别重验当前角色、authVersion（0合法）、计划批准、固定来源、用途/同意/盲态、结构质量、执行权限及原逐项审计。前端不得改造DTO来绕过这些校验。
- 管理员与研究者复用同一入口，按钮按原权威能力显示；不按显示名/邮箱提升权限，不增加API、schema、grant或默认放行。
- full放行会在manifest加入qualityEvaluation，释放的root manifest hash因此可不同于previewHash；普通分支保持原manifest hash。分别保存预览hash和释放后root hash，以各自原回执和snapshot父链核定，不统一要求两hash相等，也不以预览hash直接验证full group。
- 普通Methods的本地canCreate仅说明字段适用性，不是执行授权。不可借canReleaseSnapshot推导计算权；创建被原服务拒绝时保留“数据已放行，分析尚未开始”及原证明，提供只放行路径和权限原因，不称整体成功。

## 一个意图与原生子步骤

以经核定的actor/authVersion、Study、planId/contentHash/批准序列、manifestHash和当前URL绑定确认意图。理由在确认前保留，由人填写一次；不默认代写同意或放行结论。确认回调紧邻写操作时同步核对来源与身份，拒绝过期dialog和迟到响应。

1. 获取并验证当前批准计划与只读预览，展示原值/来源、实际阻断；不偷偷将人已核对的来源换成latest。
2. 以固定previewHash、理由和唯一原生请求键放行。成功后验证原回执及固定snapshot精确父链。
3. 以该snapshot及另一个固定原生请求键创建原生运行。普通分支执行到原生返回结果即停止；整课题正常响应时沿原process逐批推进。各步骤显示当前处理状态及已完成事实。
4. 统计结果仍待原独立/有权审核，不自动确认结果或生成、发布报告。

写前必须可靠保存恢复标记；存储失败不发送。只保存必要ID/hash/原生子键与阶段，不保存原值、表单正文或理由。理由仅在受限内存保留，沿既有超时清除规则。

独立意图checkpoint不得直接依赖旧hooks的send/forget/reset：普通放行成功会清原marker并改URL，旧Methods失权也会清未决；full旧retryPending可在404后POST。新意图先可靠保存已证实release、固定snapshot和create key，再进入下步；临时离页或失权只停止写，不抹除未知事实。相关原按钮/Methods跳转与新意图互斥，不能出现再次确认、重复create或借旧retry绕过unknown只读核对。明确区分自身已证明的URL衔接与外部导航；后者失效旧确认，前者不错误丢掉成功checkpoint。

普通Methods快照页也须在按钮与紧邻create POST时核同actor/Study活动意图（含同actor旧authVersion未决），不能只在PlanDetail隐藏链接；安全指回原意图核对，不阻止原运行的回看或原审核。反向已有legacy Methods创建未决时，新合并入口也不能忽略它重新放行/创建。仅复用原marker合同做最小双向守门，不重构原Methods状态机或增加后台接口。

Methods重置须核实际storage中同actor/Study的合法pending-create，不能因当前RAM marker为空而删除旧授权版本的未知创建。原create保留原`rh-methods-pending:<actor>:<Study>`键；审核/取消用独立、含authVersion的`rh-methods-action-pending:<actor>:<authVersion>:<Study>`键，不覆盖原create。恢复优先读取当前版本操作键，并兼容原legacy审核标记；核定成功仅清与该原请求完全匹配的操作键。GET失权、版本切换、审核未知或成功都不得删除或覆盖旧create，且不能把旧版本create当当前版本的重放资格。验收用实际hook的create POST 503生成原opaque，再核版本切换、403重置、审核及跨mount原审核键GET恢复；不通过禁用原审核来规避此边界。

## 中断、恢复与确认反馈

已成功放行不得重放；已创建运行不得新键再create。任一写响应未知时停线，只读查原键回执与原运行；404不等于未执行，不清除标记或自动POST。找到明确成功结果后，只展示成功checkpoint；剩余步骤由人明确“继续分析”触发并重新校验权限、固定批准与来源。刷新或重新登录不自动写操作。

恢复的released状态也必须查询原release键及预留create键；存储阶段不是“尚未发送”的证明。根裁定允许人明确“继续本次分析”后以**同一原键和完全相同body**续办：紧邻续办先再GET原键，查到结果只消费、不POST；仍404不称未执行，仅在当前权限/固定来源核定后以原createKey和原snapshot提交，由原生幂等/CAS处理竞争。process仅可复用原process marker的key/body/hash，不换latest stateHash冒充重试。recover函数本身始终只有GET，任何已有unknown不因4xx/404而清除或新建意图。release仅原理由仍在15分钟有限内存且hash与原releaseHash相同时允许人明确同键续办；刷新或超期不能精确重建则只读保留，不伪填理由，也不新增重填理由界面。原生幂等保证须源审及本项反例核定。

来源/政策/批准/权限变化即停止，保存已证实的历史事实并引导当前核对；不得悄悄重新放行新来源。部分成功清楚区分“数据已放行，分析尚未开始”“原运行已执行，结果待核对”等，不统一成失败或成功。

原release回执已权威证明成功后，即使后续计划/快照读取或来源校验失败，也保留“数据已放行”的事实和原键；不得因下游失败重新伪称放行未知。它不构成后续写授权，继续前仍须完整核原证明及当前条件。

已正面证明完成的当前意图必须可靠归档，保留原历史和当前结果，不依赖使用者一定点击某一个结果链接；正常返回列表、概览或刷新后不能永久锁住下一次分析。未完成但已证明属于本意图的运行可回看，其安全URL衔接须持久保留活动记录；不能导航后因旧URL限制再也无法只读核定。列表或已保存快照详情没有preview时，也须提供当前意图的恢复入口或安全回原对象路径。纯GET核定与允许写入的来源/URL门禁分清；上述回看不清unknown，不把任意新URL当旧写授权。

已由原生证实停止且无实际在途计算的失败/无适用数据记录，可由人明确结束并归档，保留其失败/无数据结论及历史，不能永久挡住新计划；归档不宣称分析成功或已调用原生取消。未知、在途或只有本地存储宣称终态的记录不得借此清除。

确认期间弹窗保留，显示“正在放行数据/正在开始分析”等状态，禁用重复提交；已确认尚在执行不能立刻关闭后无反馈。取消/Esc只在未发送或已停止的安全阶段生效，焦点恢复；确认结果未知时在原界面提供只读核对。真实未保存理由与在途写保留防丢失保护，纯预检GET不误拦离页。离页持续执行属于WF08，不能提前声称本项已支持。

正面核定成功并已衔接原结果后，原确认可自动关闭，外部成功/运行状态与精确结果入口保留，不额外要求一次“返回当前计划”只为关框。未知或仍需决定时继续保留。初始触发按钮可能在发送后卸载，须使用稳定的本区host作为fallbackFocus，避免恢复或成功关闭后焦点丢到body；不改共享弹窗或全局样式。

恢复Control在同一Card内使用单一稳定挂载槽，以当前actor/authVersion（0合法）/Study为作用域；计划尚未读到、随后到达、暂时缺失或revision更新都不卸载正在核对的弹窗，正常计划的布局顺序保持。普通页的理由、受试者标签和旧确认仍绑定原plan/revision：新绑定首render即隐藏旧值，不靠effect延迟清理；旧确认和迟到输入回调紧邻提交时核当前计划、批准、来源、身份及URL。输入重置域与恢复弹窗的挂载身份分开，不为保弹窗保留另一计划的文本；身份/授权版本/Study切换则同步隔离旧Control与旧确认。

开发中阶段预审P2须以行为反例关闭：同actor旧授权版本的未知记录不得因key变化而被忽略；恢复的stage不能替代原release/create键回执证明；首发确定拒绝与既有unknown分别呈现，404本身不证明未执行；full remaining=0不等于执行成功，须核group和实际slices终态，失败不继续派发；理由15分钟期限在紧邻release写入处再次核对，跨GET不续期。

正常已知200响应复用原DTO内的receipt/body及既有fullStudy证明函数，保持原服务端每批权限、来源、CAS和逐项审计；不丢弃已知正文后每批重读计划/完整快照/原键/运行。沿当前已证实stateHash推进，CAS变化停线。未知或刷新恢复才强制只读查原键、原快照与原运行；该规则不准用本地stage或缓存代替权威证明。验收记录正常链的来源GET次数和实际耗时，防止精简操作却退化性能。
