# 单篇AI解读：三档处理矩阵

2026-11-06，用户批准收敛规则并实施。仅当前单篇解读，当前目录串行＋独立总评审；原页面布局、来源/身份权限、Token业务计费不变。旧失败任务/预留/答案只读，不回写历史。

## 处理矩阵

| 情况 | 档位 | 系统动作与用户结果 |
| --- | --- | --- |
| JSON外层单一代码围栏、重复来源ID、模型写入已知引用编号 | 自动修复 | 去围栏/去重，后端依据真实片段重建引用；不改变科学措辞，不调用模型重试 |
| 模型选择了过多合法原文依据 | 自动修复 | 最多接收6个候选ID，按当前段真实归属及显示容量保留每段最多1项/全篇最多2项；省略额外引用，不因此整篇失败，不扩大权限 |
| Th17/Treg等含数字术语与所选原文词形一致 | 正常解释 | 记录原词对应，不再当作统计数值；不宣称验证了整句结论 |
| 文献年份与所选原文同类研究归属一致 | 正常解释 | 只核文献年份关系，不把随访年份或文献编号误作出版年 |
| “一项RCT”等明确研究计数与原文对象对应 | 正常解释 | 有确定对应时保留；不同数量/研究类型不自动纠正 |
| 明确单病例计数及既有有限随访时长映射 | 正常解释 | 复用已验证规则，保留完整数值原文receipt，不能扩大为自由数值生成 |
| 其他测量值、范围、比例或新计算缺乏完整核验 | 标注后继续 | 相关句不作为结果交付，原位提示待核对，保留其他句和可读原文依据；不以数字相同假装组别/单位/时点核验成功 |
| AI解释、假设、材料不足 | 标注后继续 | 整份回答明确AI解释不是原文已证实结论；模型可标假设/材料不足，用户继续核对，不声称程序理解所有语义 |
| 无法匹配的模型引用/数值依据ID | 标注后继续 | 丢弃无效引用、说明未核实；该段没有任何有效来源时不交付其结论，其他段可继续，不补造来源 |
| 推荐等级不受选段支持、已知停药误译、明显与选段冲突 | 标注后继续 | 相关句不交付并解释问题，其他段继续；不偷偷替模型修改科学结论 |
| 越权、AI使用授权撤回、文章/审核版本变更、封存包或内部receipt篡改 | 必须停止 | 后端阻断当前版本回答；模型不能绕过授权，不能把旧答案悄悄换到新版本。仅质量撤稿、但访问仍获准的情形另按资料治理状态展示，不混同权限撤回 |
| 网络失败、截断、不可解析协议、所有段均无可交付内容、Token不可预留 | 必须停止 | 明确未交付原因，保留问题与实际用量，无自动重试；不能伪装为正常成功 |

## 最小实现与边界

采用“系统控制面硬校验＋内容局部处理”，不选择继续增加逐篇正则例外，也不选择无条件免责声明放行。原文数值仍以系统完整引用为主；本轮不新增统计/计算服务，模型要求新增计算时明确本轮未执行，不输出未经工具复核的计算结果。未来接算子应另行明确输入/公式/运行记录。

新增响应策略`rh-article-response.v3`：四段text/fragmentIds与可选numericFactIds保留，可选kind为interpretation/hypothesis/insufficient；模型不决定核验状态。后端生成固定说明、局部警告、来源与响应校验回执。输入proof绑定完整片段、策略与问题；提交/刷新时按同策略重建显示文本及回执并核对，不靠模型自报可信度。旧v1/v2严格规则只供历史回放兼容，当前新任务不走旧一刀切拦截。

不改API路由/DDL/角色/旧Agent/Billing源码；只在Hub单篇适配器接入。页面继续原四段阅读区，使用现有Markdown文本/引用/16px阅读字号，无新表单、审核步骤或技术字段。研究者和管理员各自本人会话、跨身份隔离、当前审核状态仍全链一致。

新任务由后端在payload固定articleResponsePolicy；最终提交/刷新不依据模型或回答自报版本决定校验分支，因此删除回答的版本/回执标记也不能降级为旧策略。v3回执对JSON对象键序规范化，以支持PG JSONB往返；旧回答仍保留原策略。数字术语按完整连续词形（含大小写、Greek后缀、连续正负号）匹配，计数不可借复合数尾或否定句；“正常解释”仅表示这些对应关系，不表示整句科学意义已被程序证明。

原文块可能自带[132]等文章内参考文献编号。只有在v3完整重建核验后，才从旧Hub引用编号扫描的投影视图剥除系统原文块；实际正文/原文块/receipt不改，真实Provider/用量检查不跳过。
