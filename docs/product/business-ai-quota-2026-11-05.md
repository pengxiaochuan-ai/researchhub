# AI 统一业务 Token 规则

日期：2026-11-05。用户明确取消开发临时限制，采用原有租户／账号 Token 额度、并发预留、实际用量结算。不增加新的人民币定价或充值系统。

## 当前规则与覆盖范围

- 本机当前装配的知识库／Hub 问答、单篇解读、PICO／方案、研究设计完善、执行准备、EDC 质控解释、CRF 方法解读、资产适用性核对，统一读取原 BillingService 的当前业务额度。
- 运行不再读取开发 5/10 元总预算、累计任务／请求次数、验收价格过期、付费开关或指定文章费用白名单。原账本、审批收据、任务及预留保留取证，不删、不重置、不当作现行准入规则。
- 预检不扣费。真正发送仍由原 SessionsService 使用租户锁进行原子预留，扣除其他任务在途和待对账占用；本机当前模型配置的预估预留为 12288 Tokens，来自原 estimateRunTokenBudget(1536)，不是新增固定业务额度。
- 成功交付沿原事务保存消息、UsageRecord 和实际用量结算；多余预留释放。模型已调用但结果不确定或业务校验失败，沿原待对账规则保留预留及已知用量，不伪造成功或免费释放。请求前失败且无消耗证据才释放。
- 不自动重试／充值／增加额度／清理历史待对账；额度不足联系租户管理员按既有业务流程处理。租户管理员身份不绕过额度、来源和对象边界。

## 用户路径与状态

仍从原页面按钮进入、填写问题、主动发送、查看进度／答案、回链核对来源。布局、字号、控件位置和权限不变；不要求用户输入开发审批码或重新核价。

额度可用时可发送；不足时说明 Token 预留不足；额度查询失败时暂禁新发，刷新恢复。原答案、来源及人工编辑／保存不因额度不足隐藏。发送后发生额度竞争，以后端原子预留为准，页面保留输入／原请求键供核对，不自动另发。

## 保留边界

仅专用合成库和本机独立环境；不接临床数据、不影响旧服务。不增加角色／Agent／Study／草稿授权；各业务授权有效期、审核来源、版本、真实父对象、幂等、失权中断、科学数值守门及技术容量限制仍有效。业务授权到期不是被移除的开发价格到期。

本次未增加管理员额度管理页面；管理员既有额度／对账服务是复用边界，不能将本轮前端适配称为新运营后台。

## 兼容与验收

费用状态 DTO 使用 quota，不再以 budget 驱动页面。GET 状态只读且 no-store；缺失状态失败关闭。历史读取不调用模型、不做新费用审批。原来源证据包不携带无消费者的开发 feeApprovalHash／feeResumeHash 投影，历史 payload 不修改。

免费测试覆盖余额边界、过期开发值不干扰、当前身份、原生预留与结算、未知／非法 JSON／来源失效／截断的待对账、成功不重复记账，以及原组件与真实 PG。真实浏览器区分真实接口回读和 UI-only 余额不足替身，必要的一次实际调用另核消息、用量、预留、来源和专业限制。
