| 身份 | 可执行操作 |

“项目通知”只承载面向该范围的公告文字；不得自动导入私有课题名、成员、临床数据或内部会议密码。扩大为公开必须明确选择并在发布确认中看到范围变化。

### 目录与详情交互

- 默认按实际发布日期倒序，同时间以稳定ID排序；每页20条，用“加载更多”，返回后恢复已加载位置。查询按钮执行搜索，分类切换立即重读并清空旧分页；不每输入一个字就请求。
- 一条卡片只保留“类型／活动状态、标题、简要说明、日期／地点、详情入口”。不同时堆“详情／阅读／查看更多”三个同义动作，不加入运营统计数字。
- 活动列表用活动实际日期，正文另列发布日期；过期内容标“活动回顾”，无获准回放时写“暂无回放资料”，不显示空播放按钮或“正在报名”。
- 详情将正文及日程一次完整呈现。来源链接叫“查看原始来源”，资料叫“查看资料／前往回放”；外部网站明确标识。列表不是全文授权证明，不能直接复制第三方全文／嵌入回放。
- 历史活动回顾仍须处于已发布状态。公开“历史”是已结束活动目录，不是允许访客访问草稿、被撤下内容或旧发布修订。

## 4. 管理员的实际操作

```text
治理总览 → 资讯与活动 → 新建内容
  → 选择类型，填写标题与正文（活动才展开日程）
  → 保存草稿／预览
  → 发布前核对来源、范围、资料权限
  → 一次发布 → 原详情回读／查看前台
```

### 4.1 列表

默认“全部状态”，按最近修改倒序。顶栏一个主按钮“新建内容”；筛选仅类型、状态、搜索，范围放次级筛选。行显示标题、类型、发布状态、可见范围、活动日期／阶段、最近修改，主动作“编辑”，次级操作“预览／撤下／历史”。首次空态给“新建内容”，筛选空态给“清空筛选”，服务失败给“重新读取”，不都叫暂无数据。

已发布但有新草稿的行明确标“已发布 · 有未发布修改”，避免把保存草稿误认成前台更新。列表保留当前查询及位置；保存后不强制回首页，发布后定位原行。

### 4.2 编辑：一个页面完成，不走多步向导

采用现有表单卡片与页头动作区。主区依次为“内容、活动安排（条件显示）、来源与可见范围、资料链接（按需添加）”；编辑页不放运营报表、权限技术字段或开发说明。

| 字段 | 默认／必填时点 | 减负与校验 |
| --- | --- | --- |
| 内容类型 | 从入口带入；无上下文默认资讯，可改；发布必填 | 资讯、研究进展、项目通知、活动；改类型有活动数据时提示保留草稿字段，不静默丢失 |
| 标题 | 保存草稿必填，1–120字 | 不先要求完整正文才能保存 |
| 正文 | 发布必填；草稿可空；上限2万字 | 首期使用现有受控文本／轻量富文本组件；不另建复杂CMS，不接任意HTML或内嵌脚本 |
| 简要说明 | 从正文确定性提取首段生成，管理员可修改；不必另填 | 建议80–160字；保存时取纯文本，不调用AI，不把截断全文当作隐藏正文 |
| 来源说明 | 发布必填 | 填原创说明或原始出处；来源URL可选且需校验。没有链接不自动宣称原创或已有版权 |
| 可见范围 | 默认hub内部成员可见（已确认），发布必填 | 只选一次；发布确认回显，不要求重复选择Hub、租户或栏目 |
| 发布日期 | 系统记录真实首次发布时刻 | 不要求手填、不允许回填未来“已发布”；旧活动以活动日程表达历史，不改发布时间冒充当年发布 |
| 活动开始／结束 | 类型为活动时发布必填 | 默认时区北京时间，结束须晚于开始；不强迫填不存在的具体时刻，可支持明确“全天”日期模式，服务端统一边界 |
| 讲者／组织 | 活动发布至少一项 | 一行自由文本即可，多讲者按需增加，不强制创建专家档案 |
| 举办方式／地点 | 活动发布必填；方式线下／线上／混合 | 只展开所需地点或公开参与说明。内部会议口令不放公开页；不集成会议系统 |
| 资料／回放 | 可选，逐项添加 | 标签、用途类型、合法URL或既有获准资源引用、允许展示范围及依据；不是每条活动必须有回放 |
| 精选、封面、排序权重 | 本期不作为必填；首期可不提供 | 门户自动取3条，先不建设海报编辑器、拖拽排期与推荐规则 |

编辑时主动作“发布”（新内容）／“更新发布”（已有发布）；次级“保存草稿”“预览”。尚无标题先定位首错，发布所缺字段同页汇总并聚焦，不弹一串错误框。草稿保存成功留原页；不声称自动保存，除非真正实现服务端自动保存与冲突处理。

2026-11-18用户要求的成功反馈：发布／更新发布在服务端确认提交后，主动回“资讯与活动”列表并显示对应成功弹窗，仅一个“知道了”动作，支持Esc；保留筛选、页码，URL去掉contentId。原请求结果核对明确已提交也采用相同反馈，不重复发布。取消、失败、冲突及结果待核对继续保留编辑页。发布后列表读取失败仍保留已知成功并提供“重新读取列表”，不将其误报为发布失败。关闭弹窗后优先回当前列表中原条目的编辑按钮和原滚动位置，条目不存在则回列表标题。五页局部导航最小方案随后获用户明确确认并已实施；编辑返回保留原守门，不推广其他页面。[本轮验收与设计边界](../testing/governance-navigation-feedback-2026-11-18.md)。

### 4.3 预览、发布与撤下

- 预览在原编辑页面切换“编辑／预览”，保留输入和滚动，不要求先发布或跳第三个页面。预览内容来自当前草稿，以前台相同阅读组件渲染，顶部显式“草稿预览，仅管理者可见”。
- 发布使用**一次共享站内确认**：标题、类型、范围、来源、资料项公开情况及“将替换前台当前版本”影响。此处是人工发布核对，不再串“提交审核→再次发布→确定”三次确认。确认后按钮忙碌、防重复；失败保输入，成功回读实际已发布版本并提供“查看前台”。
- 公开或扩大范围时，正文须有允许该范围展示的依据；每个资料项按它**自身的展示范围**核验用途及有效性。已有合法成员许可但不允许公开的资料可保留为“仅成员”，公开投影完整剔除其标题、URL及存在信息；发布确认分别显示公众／成员实际可见结果。缺少自身范围许可依据的资料项拦截发布，允许“移除此资料链接，保留正文继续”；不能隐式把内部附件变公开。
- 撤下只针对当前已发布内容，站内确认显示对象与当前范围，理由必填。撤下后列表／首页／详情／平台交付链接立即失效；保留管理历史。重新发布走正常权限和权利校验，不一键无条件恢复。
- 已发布内容可另存修改草稿，旧发布版保持服务；更新发布成功才原子替换。需立即阻止原内容传播时先撤下，不能以“正在编辑”代替撤下。

## 5. 状态与时间规则

发布状态与活动时间分开，避免“活动结束＝下架”：

| 对象 | 状态／流转 | 前台规则 |
| --- | --- | --- |
| 内容 | 草稿 → 已发布 → 已撤下；撤下可重新发布 | 只交付当前已发布固定版本，且符合访问范围 |
| 已发布修改 | 当前发布版本＋未发布工作草稿 | 改草稿不改变前台，更新发布时按revision检查 |
| 活动阶段 | 即将举行／进行中／活动回顾 | 服务端按活动开始、结束与当前时间计算；到结束边界自动进入回顾，不依赖浏览器常开或管理员手改 |
| 活动取消 | 建议保留“已取消”业务标记及说明 | 发布中的取消公告可保留供知悉，不显示正在举行；若内容本身不宜展示，则撤下。取消与撤下不混淆 |

时间存标准时间戳及timezone，展示北京时间；同一服务端时钟决定排序与边界。回顾无回放不补造资料。活动变更时间或取消时须更新发布，审计保留前后事实。

## 6. 来源、链接与访问边界

1. 正文允许公开、来源可引用、资料可访问、允许AI使用是不同事实；F03不自动授予AI索引、训练、下载、全文转载或跨课题访问许可。
2. 首期资料优先用既有资源引用或获准HTTPS外链；不新建视频存储、转码或上传系统。引用原资源时始终核其当前权限，平台托管下载须每次鉴权，不能发长效匿名URL。
3. 每项资料独立记录范围／允许用途／依据及确认者；资源仅成员可见时，公开内容可只保留不泄漏该资源的正文，隐藏资料项，或管理员移除该项后发布。不得在公开JSON中送出内部URL再靠CSS隐藏。
4. 外部URL只接受安全协议及长度；禁javascript/data/file、带账号口令和访问token的URL。初期不由后台自动抓取任意URL；若以后加抓取需单列SSRF与来源验证。
5. 撤下是停止平台后续交付。旧标签页在重新加载／恢复可见时重核并移除已撤下内容；响应禁缓存并在详情与资料跳转前重核发布事实。无法抹去用户已经阅读、下载或截图的内容，不许承诺远程删除第三方原站。
6. 成员内容须先认证、当前F01获准且范围匹配；403/401不泄漏标题、摘要、讲者或资源地址。公众路由只回公开字段白名单，管理版本、理由、操作者私有字段不进入公开接口。

## 7. 后端落点与候选契约

延续React/Vite、当前Nest装配及PG，不引入新CMS或多Hub通用平台。新增Hub自有运营内容聚合：内容主记录（状态、当前发布版）、工作草稿／不可变发布版本、追加操作事件；资源项保存于对应固定版本。最终表数、约束与迁移脚本在实施计划冻结，不改文献／资产的原表状态含义。

| 候选接口 | 服务端职责 |
| --- | --- |
| GET /api/public/hubs/:hubKey/academic-content[/:id] | 匿名可用的公开列表／详情，只查当前已发布公开版本及白名单字段，不接收member／draft范围参数 |
| GET /api/hubs/:hubKey/academic-content[/:id] | 当前获准成员的列表／详情，含其合法公开及成员范围；类型／活动阶段／搜索／稳定分页。草稿／撤下通用不可用404，不回历史版兜底 |
| GET 上述各自前缀/:id/resources/:key | 公开与成员资源分别装配，重核当前发布及资源用途后交付合规目标或受控资源，不构造任意URL代理 |
| GET/POST /api/hubs/:hubKey/content-management | 当前有效管理员列表／新建草稿 |
| GET/PATCH /api/hubs/:hubKey/content-management/:id | 当前管理员详情／保存草稿，baseRevision＋requestKey，冲突409不覆盖 |
| POST …/:id/publications | 当前身份、草稿revision、范围／权利校验、发布版固定、状态切换及审计同事务 |
| POST …/:id/withdrawals | 版本约束、撤下理由、发布指针失效及审计同事务 |
| GET …/:id/operations/:requestKey；GET …/:id/history | 原操作结果及管理历史；当前失权不能继续读旧管理员回执 |

固定灵枢心域Hub与绑定租户，当前管理员与原授权锁并行核验；只给本模块最小ACL及RLS，不赋运营人员Study读取权。公开列表不包含成员内容总数，避免侧漏；筛选与资源查询不能绕过范围。

明确JSON输入白名单、正文／URL限制、HTML清理、同源防护、no-store、合法回跳及错误码。相同键与相同内容回原结果，相同键换内容409；双管理员竞争仅一笔当前版本成功。发布／撤下未知时先GET原操作，查无不自动重POST；只有可证明未提交且当前版本／权限仍有效时显式原键重试。
