## 2. 首次公开时间：唯一口径

对稳定资源身份e，定义`firstPublicAt`为：e在当前tenant/Hub内第一次同时满足“属于本Hub的可纳入资源、身份可确定、当前有效公开展示批准、批准绑定的版本及来源有效”全部条件的实际生效时刻。论文还必须满足现有领域纳入规则。以服务端可信时间记录，UTC存储，按`Asia/Shanghai`自然日分组；日期区间左闭右开。注册日期、发表日期、指南发布日仍是资料属性，不充当Hub新增日期。

| 情形 | 处理 |
| --- | --- |
| 导入、保存草稿、注册账号、内部可见 | 不产生公开新增 |
| 首次审核公开且所有条件已具备 | 同一业务事务记录首次公开证据 |
| 先获准但来源尚未有效、尚未纳入领域 | 等最后一个必要条件实际满足时记录，不提前用批准时间 |
| 平台内容内部发布后转公开 | 使用首次公开版本的实际生效时间，不使用内部首次发布时间 |
| 公开实体改标题/任职、重新审核、文件更新 | 同一身份不再新增；读取仍检查当前版本是否有效 |
| 撤下、过期、归档、撤回、来源失效 | 从公开动态和数量中剔除；内部首次公开证据保留 |
| 撤下后恢复公开 | 恢复原首次公开日期，不变成恢复当天新增 |
| 重复导入或并发重复批准 | 数据库唯一约束及幂等处理，只记一次 |

定义形式为`min{t | eligible(e,t)=true}`，不能简化成`min(approve.created_at)`。跨版本历史、批次批准/单条覆盖、来源就绪和领域纳入均须按实际适用规则计算。资格首次变为真必须有可追溯事件；缺少必要时序证据时日期为unknown，不能估计。

### 历史回填

先只读盘点，逐项保留原批准/发布/版本/纳入及来源状态证据，能够重建首次资格生效时刻的才回填。不能以文件mtime、当前部署时间、created_at或第一次被新接口看见的时间冒充首次公开。证据不足的存量记为`historical_undated`，不加入每日新增；继续在原资源目录中可见。后续明确证明日期后可修正，并记录修正依据。

新索引启用前，必须给出“可回填/日期不明/身份冲突”具名清单及数量，不能把全部存量灌成启用当天新增。`observedAt`只表示系统观察时间，与`firstPublicAt`分开。

## 3. 六类资源身份与纳入门槛

所有唯一键均带`tenantId + hubKey + category`。只计当前仍公开可查看的实体；不是新增抓取记录数或文件数。

| 类别 | 稳定身份 | 公开及去重规则 |
| --- | --- | --- |
| 临床注册研究 registration | 受核验的注册机构命名空间＋规范注册号；已有可靠跨注册别名映射时使用统一身份 | 同一注册号多快照只计一次；无可靠跨注册关联不按相似标题合并。计数表达注册研究记录，不推断全世界独立试验总量。目录公开不等于正文/分组全部公开 |
| 研究论文 publication | 复用现有领域纳入及DOI/PMCID去重契约，将同文多来源绑定同一paperKey | DOI规范化、DOI/PMCID别名关联和身份冲突沿现有规则；不以标题近似或LLM合并。待核验/排除文献不进入“新增研究论文”。身份、领域纳入、公开资格任一不确定，登记待处理，不静默计零 |
| 指南与教材 guidance | 已核验作品/资料实体身份；官方稳定标识，或经审核的ISBN及版次；内部不可变documentId作为已确认实体锚点 | 指南、共识、研究标准、教材使用明确类型。一个实体文件更新不重复计数；经审核确认的独立新版/新版次可作为新实体。不得按标题关键词把标准猜成教材，也不把教材章节算多本。首次标题“新增指南与教材N份”，保留各条真实资料类型 |
| 研究机构 organization | 现有目录organization实体ID及稳定键 | 公开且有有效来源的机构档案，非自由文本作者单位；同一机构别名、档案修订、增加关联不新增。目录team不当机构计数，科室只有已明确建模为独立机构实体才按原类型处理 |
| 研究者 researcher | 现有researcher实体ID及稳定键 | 是获准公开的学术档案，不是账号；同名不合并，任职变动、账户绑定或加入团队不新增。同一人多档案须走可审核的身份归并，不由动态服务猜测 |
| 平台发布 platform_content | 现有内容contentId | 资讯、研究进展、项目通知、活动共用一个大类，保留内容实际类型。内容当前published且audience=public；编辑、再次发布、活动结束不新增。附件/回放另外检查原授权，不能随正文自动公开 |

身份归并须保留旧键→主键的可审计别名，合并后首次公开取各有效证据的最早时刻，当前公开数只计一份；冲突不任意选值。所有归并沿原资料治理执行，本功能不增加自动归并操作。

教材目前不是外部来源表的已有明确类型；第一步核对其实际承载和公开审批契约。未具备时必须登记缺口，不能借用clinical_guideline强行落库，也不能宣布教材子类已接通。

## 4. 聚合与摘要规则

前五类按“北京时间日期＋类别”聚成一条：“新增临床注册研究N项／研究论文N篇／指南与教材N份／研究机构N家／研究者N位”。平台发布逐条显示实际标题及类型，不把三篇内容合并成看不出主题的数量通知。

仅对“当前仍公开＋首次公开日期可靠＋身份有效”的集合精确计数。全部集合先去重、重新核权及聚合，再限制预览条数；禁止从首页6条预览或现有固定来源批次推算全量，也禁止用两次总量相减算新增。历史日期数量可因撤下或身份修正减少，它表示当前仍可查看的新增资源，不是不可变的历史发布业绩。零项不渲染一条“新增0项”。

按每条聚合内最新首次公开时间倒序，同时间以类别固定序及稳定键排序；显示日期由firstPublicAt的北京时间决定。“今天”由服务端当日判定，跨日刷新重新计算，不把用户浏览器时区当口径。每天自动随有效公开变化更新，不等零点跑批后才显示。

摘要只复用当前获准公开字段，禁止模型生成或从未审正文推断：注册取已核验疾病；论文取已核验主题/分类，缺少可靠主题可展示代表标题；指南取真实资料类型/发布机构；机构与研究者取已公开名称、任职/方向；平台发布取现有已发布summary。多值按出现次数降序、同数按稳定字序取最多两个，使用“涉及A、B等”而不称热点或疗效结论。缺少可靠摘要就省略；只有一个类别不列出“等”。

## 6. 后台实现契约与现有缺口

建议新增Hub专用首次公开索引，作为事件证据索引而非新的审批系统。记录：scope、category、entityKey、firstPublicAt（可空）、timeStatus、proofRefs、身份别名、observedAt、ruleVersion。唯一约束(scope,category,entityKey)，证据变化保留审计；不把用户身份、原始私密正文、未授权摘要复制进公开响应。

未来审批/发布及其他资格条件变更在原业务事务内记录资格首次生效；异步处理必须消费同事务持久化事件，使用事件实际生效时间，具备幂等、失败重试/告警，不用消费或页面读取时间代替。只记录当前通过所有原规则的资格，不修改原审批结果。资料撤下、过期、归档、最新版本/来源失效在每次读取时重新核验，缓存不能继续交付旧标题及数量。

同一只读服务拟定`GET /api/hubs/:hubKey/public-activity?limit=4|6`，按既有Hub作用域绑定，不允许客户端指定tenant/account。返回`scope、timezone、calculatedAt、status、categoryStatuses、items`；categoryStatuses分开记录读取成功/失败、集合完整性及历史日期覆盖完整/部分/未知，不能用一个ok掩盖缺口。items仅含稳定id、category、kind(aggregate/content)、day、eventAt、title、summary、count（汇总项）、现有安全链接（有则给）。服务内部保留精确成员集合以核验，不新增公开清单接口。no-store，参数严格校验；无权限、未知Hub、网络失败与真实空集合分别处理。

F03历史可通过受信任服务查询每个contentId的public版本中最早published_at；这类已发布版本持久化记录可证明首次公开，读取时仍检查当前版本公开。历史version/event有管理员RLS限制，不能为了回填给公共请求开放内部历史或新增宽泛SELECT授权。

现有可复用：Hub公开投影/原详情核权、论文DOI/PMCID身份规则、目录实体及版本化审核、F03内容/版本/事件。现有缺口：统一首次资格事件索引；历史必要条件的有效时间证据；论文纳入规则发布的生效证据；教材显式类型及审核承载；完整集合的每日聚合，不能继承首页预览或受审初始批次的统计上限。

不把“解除初始来源白名单”当动态功能附带修改；新收录仍按原资源准入。读取适配器必须覆盖既有正式纳入范围的完整集合，若当前范围完整性无法证明，返回受限/未完成，不宣称全Hub六类已覆盖。

数据库结构、索引、事务接点及历史回填清单在进入变更前形成精确迁移文件/ADR及回退方案，依仓库数据库变更规则单独核准执行；本规格不执行DDL/GRANT、不连接生产、不重批资料。运行时继续唯一19501/19502，本机与正式后端共用相同模块，不新增常驻测试环境；共享重载另核当前窗口，历史授权不自动延续。
