## 2026-10-31 · PMC 按篇一次审核（取代下方逐组件操作口径）

补采安全边界：页面预览资产清单的摘要随提交校验；预览后到点击前若有补件，提交冲突并要求刷新，未见组件不能被顺带放行。按篇决定只覆盖提交时已暂存的图片/附件 ID 与 SHA-256；同文章版本后补采的组件自动保持不可见，管理员核对后可按原范围再次确认并形成新决定版本。「暂不放行」不受组件数量上限阻断。已有按篇决定后，旧逐项写入接口拒绝，防止旧撤回返回成功但页面和 AI 未撤回；旧决定历史只读保留。

首批 PMC 候选的具名 Hub 管理员只需核对当前文章原文与缺件提示，然后对**当前文章版本**一次选择「公开 Hub 页面与 AI」「仅租户内页面与 AI」或「暂不放行」。一次决定同步应用于本篇已暂存的书目、摘要、正文、表格文字、图片/附件的页面读取，以及已解析文字的 AI 检索；不要求逐字段、逐图片、逐用途重复点选，也不要求填写权利/内容依据 HTTPS 链接或第三方图片逐项确认。系统保留来源 URL、许可原值、版本、原件/组件哈希、具名审核人、时间和不可覆盖决定历史。文章换版、撤回或失权阻断后续页面和 AI 读取；未采集成功的对象不会被补造，缺 PDF/媒体仍如实提示，图片不作为 AI 文字。

「仅租户内」必须经当前登录账号与租户重验，匿名/跨租户不可见；公开决定可供匿名页面阅读，AI 仍要求原科研 Agent 授权。此本机决定只是 Hub 内容投影的产品放行，不代表外部版权许可已核定，也不授权云端或真实域名发布。下文逐字段、逐组件的描述是旧实现历史，不再作为本切片管理员操作规则。其他工作簿及五份初始来源审核方式不变。[小步计划](../superpowers/plans/2026-10-31-pmc-one-decision.md)。

## 科研 Agent 来源重验契约

Hub 来源与私有 Study 知识库是两种不同的证据类型，不能把 Hub 片段伪装成旧 `kb_search` 文档。检索时对每个片段保存来源记录 ID、原始行哈希、规范版本、书目/摘要各自的展示与 AI 审核版本、实际使用的字段及片段哈希；题名、DOI、来源 URL/名称、文件/行号等引用元数据也必须与当前记录相同。模型调用前、模型返回后、回答提交前以及历史回答/来源再读取前，均以当前用户、租户、Hub 和这些标识重新查询同一授权投影；若撤回、过期、账号失权、版本或片段改变，整条回答阻断/隐藏，不交付缓存正文。缺少证据时不生成回答。该契约目前已在本机适配层接入旧会话/Orchestrator 并用免费替身和合成 PG 验证；真实收费 Provider 回答和专业验收仍需另行核价、费用授权与真实获准来源。

独立总评审修正：自然提问先尝试原文，再仅从用户问题确定性截取主题短语做至多一次回退检索，不由模型扩展检索词；仍要求当前已审核来源。最终发布在同一合成 PG 事务内设置租户上下文，按来源顺序持有来源目录行共享锁至 assistant 提交，与管理员审核/撤回的排他锁互斥，随后重验全部来源。历史 Hub 回答在单次只读事务内逐条重验，不并发为每条引用开新连接。上述机制已通过合成事务与并发锁测试；**真实 Provider 回答仍未执行**。

授权到期按数据库实时 `clock_timestamp()` 判断，不沿用事务开始的 `now()`；同一事务跨过到期时必须拒绝检索/提交。合成事务 RED→GREEN 已证明这一点。最多 60 条历史回答各含多个来源时的批量性能仍待后续压测，不把单事务串行等同于大容量性能达标。
