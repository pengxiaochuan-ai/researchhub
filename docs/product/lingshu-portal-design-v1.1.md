## 3 注册页面

### 页面目的与布局

以“加入灵枢心域，连接你的研究方向”为标题，让用户先完成账号创建，再补充学术身份。左侧约 45% 展示共同体价值与简洁知识网络图，右侧约 55% 放置宽度 480–520px 的注册卡。避免促销式卖点、套餐或夸大的 AI 能力。

价值说明仅保留三项：找到领域证据、参与研究协作、沉淀科研资产。底部说明“AI 辅助科研，专家负责判断与确认”。

### 拟定字段与流程

首版建议采用邮箱注册与密码登录，预留手机验证适配接口；不同时增加多个未落实的验证渠道。

| 字段 | 必填与校验 | 交互 |
| --- | --- | --- |
| 邮箱 | 必填，去除首尾空格，格式校验 | 标签常显；作为验证与找回入口 |
| 邮箱验证码 | 必填，由服务端校验有效期与使用状态 | 发送后 60 秒可重发；失败恢复重试，前端倒计时不替代服务端限流 |
| 密码 | 必填，拟定 12–64 位，允许粘贴和密码管理器 | 展示密码规则、显示/隐藏；最终规则由认证方案统一确定 |
| 确认密码 | 与密码一致 | 失焦或提交时显示差异提示 |
| 用户协议与隐私政策 | 明确同意后提交；默认不勾选 | 两个可阅读链接；正式文本接入前不得对外开放真实注册 |

流程：填写邮箱→发送验证码→完成验证与密码→创建账号→基础资料→开始探索科研空间。注册失败时保留非敏感字段，清楚提示失败原因与可恢复动作；禁止把密码、验证码写入本地存储或日志。

基础资料与注册分开：姓名或展示名、身份类型、所在机构、研究方向。身份选项为临床医生、科研人员、青年研究者、团队成员；属于同一“个人科研用户”账户，身份标签不自动增加权限。机构及研究方向允许后续补充。

团队负责人仍先建立个人账号，再进入“申请创建团队 / 加入已有团队”的后续流程。不得把团队账户设计成共享密码；管理用户由后台授权，不开放自行注册管理员。

### 状态与反馈

- 默认：提交按钮可点击，点击后聚焦第一个错误，减少猜测按钮禁用原因。
- 发送中与提交中：显示加载文案，阻止重复操作；验证码发送结果不得泄露账号是否存在。
- 验证码过期、错误或使用过：提示重新获取；服务端限制尝试次数。
- 网络错误：保留邮箱等字段，给出重试入口；前端校验通过不等同注册成功。
- 注册成功：只有服务端确认后进入成功状态；邮箱验证与会话创建失败时显示对应恢复路径。

## 4 登录与找回密码

### 页面结构

与注册页共用双栏背景和品牌区域。标题“登录灵枢心域”，说明“继续你的研究与学术协作”。表单仅包含邮箱、密码、显示密码、找回密码、登录按钮和注册入口。暂不添加微信、机构单点登录等未确认渠道。

| 场景 | 页面行为 |
| --- | --- |
| 正常登录 | 成功后返回合法站内原目标；无原目标则进入科研空间 |
| 邮箱或密码错误 | 统一提示“邮箱或密码不正确”，不暴露账号存在状态 |
| 频繁失败 | 服务端限流；显示可再次尝试时间与找回密码入口 |
| 邮箱未验证 | 提供重新验证入口，不直接放行工作区 |
| 会话过期 | 登录后返回原业务页；业务草稿按业务模块恢复，不在登录页保存敏感数据 |
| 账号受限 | 提示通过帮助中心查看处理方式，不提供前端绕过路径 |

首版不提供“永久保持登录”。会话期限、Cookie 属性与 CSRF 防护由后端认证设计落实。前端路由守卫只控制界面访问，所有业务接口仍需服务端鉴权。

找回流程：输入邮箱→展示统一发送反馈→打开有时效的一次性重置链接→输入并确认新密码→重置成功→返回登录。链接无效或过期时提供重新发送入口；重置成功后使旧会话失效。不能用前端随机验证码或本地存储模拟真实认证。

## 5 学术发起页面

### 信息结构

1. **发起背景**：标题“以临床问题为起点，共建领域科研共同体”；解释针灸防治情志病研究如何连接临床实践、领域证据与跨机构协作。
2. **发起与支持**：按确认的身份分别展示发起机构、学术专家与项目支持；机构名称、专家姓名、职务、研究方向和公开资料链接。项目支持不自动等同平台运营方或合作单位。
3. **共同体如何协作**：沿用现有网络视觉，简述提出问题、组织研究、共享证据、沉淀资产四个环节。
4. **参与方式**：个人研究者加入、已有团队参与、机构合作三种入口；说明各自用途和后续步骤，避免将机构身份设计为自行获得的高级权限。

这里的专家与机构介绍、参与方式属于门户设计。合作申请表与审核流属于拟定扩展：如首版不纳入范围，保留已确认的联系渠道或加入入口，不展示可提交但无人处理的表单。

### 拟定合作申请

用户点击“申请团队 / 机构合作”后先登录，再打开页面内表单或独立抽屉。字段为合作类型、机构/团队名称、联系人姓名、工作邮箱、研究方向、合作说明。合作类型固定选项：团队参与、机构协作、学术交流；说明限制 1000 字，首版不提供附件上传。

提交前展示用途说明，明确联系信息用于本次申请沟通。服务端提交成功后显示申请编号与“已提交”状态；失败保留当前页面内容并允许重试。重复提交由服务端幂等或去重处理。未接入后端时仅展示原型反馈，不把本机草稿描述为已发送。

拟定审核状态：已提交→处理中→需要补充 / 已回复 / 已关闭；由平台人员处理，用户只能查看自己的申请。不得承诺未确认的审核时限。联系方式、负责人和运营流程须上线前落实。

### 视觉与动效

使用蓝紫知识网络和轻量机构/专家卡片，不使用医院宣传大楼、传统中医装饰、虚构徽章或自动滚动专家墙。专家卡片高度与信息行数保持一致；介绍可展开阅读。只在真实数据完整后展示筛选功能，避免少量卡片配复杂过滤器。
