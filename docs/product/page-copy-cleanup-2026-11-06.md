# 用户页面开发说明清理

2026-11-06。用户批准统一排查、逐页清理遗留开发说明，保持现有布局与业务规则。仅ResearchHub前端与用户帮助文案，当前目录串行＋唯一独立只读评审；不恢复会话续期/底座/团队等其他实施任务。

## 文案处理矩阵

| 类型 | 处理 |
| --- | --- |
| “接口已接入”“服务端草稿”“旧算子”“本轮费用门禁”“恢复布局不新增权限”等研发叙述 | 删除纯说明，或改成用户当前可做的事；研发过程留在本规格/测试文档 |
| 尚不可用功能、缺失数据、读取失败 | 简短说明“暂不可用”“无法读取，请重试”等真实状态；不冒充暂无记录、可用功能或成功 |
| 权限、私有范围、审核/发布责任、来源有效性、AI解释局限 | 保留且用用户语言表达；不删除服务端控制或改变按钮条件 |
| 合成数据、演示样例、浏览器内草稿、体验邮件不外发 | 保留真实性质；去掉SMTP/部署/接线等实现术语，不虚称邮件已外发或资料已认证 |
| 用户保存的资料、历史报告、模型回答、科研事实、数值/版本/来源 | 不重写，不触碰数据库；不是通过清理界面来改历史科研内容 |

## 页面与路径

按当前manifest的52个登记页面排查，并覆盖已存在的Study/方案/执行准备/合成采集/质控/方法报告/资产候选/AI单篇/G02两治理叶子及帮助文章真实query分支。科研人员、管理员、适用访客及显式演示模式分开验证；源代码关键词只是候选，不能把“数据库”作为研究内容、“Token”作为实际计费或“合成”标识误删。

常规用户路径与原来一致：登录/选择研究→查看既有资料或草稿→使用原控件→得到真实反馈。纯文案清理不发送保存、邀请、审核、模型或其他业务写请求；浏览器遇知识库原自动申请空会话时阻断并记录，不改变该原行为。登录仅用于原两个合成账号。

## 实施边界

- 文本变更按copy-rules与逐节点台账执行；仅StringLiteral/JSXText/TemplateElement，剥除文字值后AST结构须一致。未知/未批准的数值、阈值、条件、URL、模型/计费/权限代码均不修改。
- 共享横幅仅在真实页面的纯开发说明处不再注入；保留显式演示与合成/私有草稿必要提示，以及其中现有导航按钮。原图文、区域顺序、表单、点击/返回、字号与CSS不改，不用隐藏风险或空白占位来伪装清理。
- 未开放页面继续原受限卡与返回入口，改写说明而不是开放业务内容。真实空错态与演示性质不得混淆。
- 首先保存同视口真实基线，再串行落地文字、运行组件/路由/合成PG和构建门禁；最后真实Chrome路由矩阵、截图录屏、必要负例和独立总评审。专业可用性与用户体验单列，不以测试数量代签。

不新增模型调用、数据库权限、云资源、远端配置访问或真实发布；不改旧系统。当前工作区的其他未提交内容保留，不整体提交、清理或回退。
