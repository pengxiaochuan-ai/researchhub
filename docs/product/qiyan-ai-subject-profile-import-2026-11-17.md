- 推荐新增**一张Hub专用subject_profile_imports确认/回执表**。旧imports仅subjects/visit_form并带固定协议/表单/grant契约，直接扩模式会改旧触发器/验收；Message.meta经原生messages/knowledge-state完整交付，不能放目标档案快照，否则仅来源会话可读时会绕过目标当前授权。新表影响面较小，不是技术上唯一可行方案。

## 持久化与提交约束

新表定义在`server/ai-agent/subject-profile-import-schema.sql`：本人来源会话/预检版本和文件SHA、真实目标Study、不可变固定快照、唯一请求键、确认hash、版本CAS、planned→committed/cancelled、原子receipt与审计、强制RLS。应用账号仅本表SELECT/INSERT/UPDATE，无DELETE/PUBLIC权限，不改旧表与角色。

准备阶段只有新确认记录和审计，不创建ModalityFile/ProcessingTask/SubjectProfile。原件先在事务外读取并核SHA，以本次不可变已验证字节作为本地只读缓存提供给原解析器；提交时再验来源行/版本及目标/档案/入组快照，拒绝迟到或并发更改。缓存不更改文件、不充当合成替身、不发模型。

确认在同一有界受限PG事务完成新原件登记/新任务、真实原始解析与档案确认、Profile写入、审计和本表回执；所有原生Prisma事务钉同一连接。该事务不调用外部对象存储或模型，原文件IO由已验字节的本地缓存完成；解析/权限/版本/超时失败整体回滚，不留“已登记但档案没写”的假成功。原处理器不注册生命周期，Ingest.kick仅为空调度器，本次仅显式claim返回的新任务，不扫租户队列/历史租约。

当前XLSX原Worker用readXlsxRowsStreaming读取第一个worksheet entry分类（旧非XLSX路径才会遍历所有sheet）；不能把通用预检扫描全本的分类直接当成实际Worker分类。准备/提交必须按同一原生流式契约校验最终Skill为subject-profile-import，且所选表的档案字段/记录可合法解析；分类为眼动/通用表格时拒绝本分支，不先执行再靠回滚掩盖越范围。英文表头等未被原路由识别的格式保留来源并明确未执行，不在首片改分类器或自动忽略档案列当编号导入。

最终事务内先锁定并重验档案/入组hash及原件重复登记，提交后逐字段比较真正保存的Profile与固定确认值，不能只看task complete/updatedAt；不符合则整体回滚。数值仅加数据库Int类型边界，不引入医学常模或补值。25MiB只是上传上限，解析/记录/快照容量仍单列（每计划至多500条、1MiB固定快照），超限/超时明确失败不截断、不自动重提。

已有原件若被旧任务登记，首闭环拒绝覆盖并引导查看原记录，不借新计划改旧任务。取消保留来源文件。结果回看重验来源和目标当前权限、真实任务/档案归属与receipt；后续档案被修改时明确“已有后续修改”，不把旧回执当最新档案。

## 权限与本机验收

只使用专用合成库、原owner/admin及当前Study；native上传权限决定可写，不按邮箱或可读Study推导授权。当前admin原生权限正向验收；owner若仍无data.upload则验证拒绝，不为通过测试扩大角色/旧限时grant。本人会话/上传边界保持，管理员不会自动读取他人会话。

具名实际验收及新表权限已单列获批：最多2个新会话（admin业务、owner拒绝）、2个admin本人新假名被试、4份新XLSX暂存/预检（成功、重复目标、缺失绑定、畸形/歧义）、最多4份确认计划及1次成功提交（1个新file/task、最多2份Profile）。旧历史行与原来源只读，免费验证，不调用模型/渠道、不新建Study/成员/角色或云资源。失败样例原则先用免费纯测试/回滚，不把额度用来堆持久坏数据。

## UI/UE与验收标准

唯一局部适配：识别为档案时，将原预检内的通用确认区替换为“关联研究/工作表/假名映射→确认导入档案→结果”；不添加一级页签、独立向导、技术参数或全页布局。动作14/22，真实长文本16/28，共享Button和站内确认；多目标/多表才选择，单一合法目标可预填但须在确认摘要中可见。错误保输入并说明能否重试；刷新不重放写请求。

验收：新会话实际上传→原生分类→明确确认→两份真实Profile及审计/回执→同页/刷新回看；0/false、空值不覆旧值、重复请求零重复写；双账号/Study/源失效/档案并发更改/源SHA不符/事务故障/响应丢失恢复；原通用表格与历史回执保持。真实浏览器检查1440/1024/390及200%可读/操作/焦点/失败恢复并留证，一次独立总评后修补。手册统一更新`用户验证与操作手册.md`，用户验收与技术测试分开。

## 独评后明确的边界

档案公式单元格拒绝，不能使用缓存值冒充原始数值；所选sheet含研究编号时，非空编号须与目标Study一致，准备和提交均核对。目标权限/来源失效清除旧档案值；未知响应只保留操作标识，先GET核对，不自动重提。结果读取重验原生任务/文件真实归属、完整完成标记和来源SHA，档案后续变更单独提示。

候选识别复用原只读解析器全部别名，包括英文档案表头。先复用原bindingColumn保留明确visitCode的CRF分支，避免education等重叠字段抢走原表单流程；其余档案候选若原Worker不能实际路由，必须明确拒绝，不能落到仅编号导入后丢掉档案字段。多份文件中的档案候选也受该守门约束；首片只接受单份XLSX，不自动合并多份档案。

## 已实现接口与数据库对应

以下均在`/api`下，要求本人当前会话、当前账号与来源项目；目标接口还复验Study原生上传权限。POST校验同源，响应`no-store`。本机Chrome去端口Origin只在完整浏览器同源证明成立时兼容，不能仅凭Origin字符串放行；其他上传模块不变。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/sessions/:id/profile-import-probes/:preflightId` | 当前批次识别档案候选或原通用导入；已有原通用计划优先保持 |
| GET | `/sessions/:id/profile-import-targets` | 当前原生可上传研究，不能以Study可读替代上传权限 |
| GET | `/sessions/:id/profile-import-current/:preflightId` | 当前批次本人未取消计划/回执 |
| POST | `/sessions/:id/profile-imports` | requestKey/preflightId/studyId，必要时sheetName/recordBindings；返回明确补选或固定planned预览 |
| GET | `/sessions/:id/profile-imports/:planId` | 重验来源/目标与原生结果后交付 |
| GET | `/sessions/:id/profile-imports/receipts/:requestKey` | 原操作结果核对，不重放写请求 |
| POST | `/sessions/:id/profile-imports/:planId/confirmations` | version/hash固定确认；原生新任务、Profile、回执与审计同事务 |
| POST | `/sessions/:id/profile-imports/:planId/cancellation` | version取消本人未提交计划；保留来源，取消返回不含目标档案值 |

唯一新增表仍为`rh_ai.subject_profile_imports`；DDL以已应用SQL为准，无后续扩大表权限。准备只新增planned及审计，确认只认领本次新任务，失败整体回滚。档案被修改后planned交付标targetChanged并禁确认，仍可取消；committed回看显示本次固定值及后续更改提示。若来源已无权访问，旧值不交付。来源预检有planned/committed依赖时不能直接取消。
