## 1. 产品定位与用户价值

科研资产不是另一套网盘或知识库，也不等于保存一份AI回答。它把研究中有价值的方案、工具、数据说明、分析方法和成果，转成**有明确来源、固定版本、责任人、使用条件、访问范围和复用记录的可治理对象**。

用户应能直接回答四个问题：这是什么、来自哪里、我能怎么用、用到哪个研究后产生了什么。核心闭环为：

`研究产出/获准上传 → 资产候选 → 人工核验与发布 → 按授权被发现 → 对照目标研究 → 人工确认复用 → 新草稿/引用与血缘 → 后续成果再沉淀`。

三类价值：科研人员不用反复整理同一套方法；负责人能把研究成果安全地交给下一研究；管理员知道哪些内容被谁、按哪个版本和范围使用。AI用于解释、找差异和建议，不替权利人授权、不替人审批、不生成科学数值或自动启用研究。

### 1.1 本稿的假设与待确认部分

1. 延续五个一级空间和现有A01/A02母版，不另造资产门户；Study、Hub是同一资产的上下文视图，不各建一份副本。
2. 登记默认私有，扩大可见或用途需明确决定；“已发布”不是“全网公开”。访客只看明确允许公开的摘要，不自动获得全文、数据或AI使用权。
3. 同租户内正式共享与跨Study复用是完整产品目标；跨租户、交易/付费下载、任意代码执行不作为推荐首批。
4. 推荐先支持研究方案模板的结构化应用；其他资产至少完成登记、版本、审核、引用与受控附件，不把所有类型都承诺为一键执行。
5. 上述推荐及具体首批范围待评审。现有两账号/固定Study的切片授权，不等于本轮已批准全租户、共享、发布、下载或模型调用。

### 1.2 成功标准

- 从现有产出登记候选后，正文、类型、作者、固定来源版本和限制可查，不需复制粘贴已有材料。
- 管理员能对具体版本作出有依据的审核决定；用户看到的版本、共享范围和实际可执行动作一致。
- 第二个有权Study能完成“查资产→看来源→核对差异→确认到新草稿”的闭环，源研究不改、源数据不泄漏。
- 每笔引用、下载、复用和撤回都有真实事件；统计可从事件复算，缺数不展示0或演示值。
- 四层分别验：代码实现、目标环境启用、真实请求执行、用户科研任务可用。测试数量不代替专业验收。

| 审核通过 | 有发布权者确认本版及获准范围，当前源仍有效 | 发布指定版本；批准不自动扩大到公开范围 |

| 来源变化/失权 | 新增来源版本、原版撤审、账号/成员停用、授权过期分别处理 | 新版不自动替换固定来源；原版撤审/失权则阻断当前交付，历史是否可读仍取决当前授权 |
| 已删除/回收站 | 本人未发布草稿可软删，具有关联/发布历史则撤回或归档 | 不物理删除来源/审计；恢复仍重新核权限、来源和冲突 |

固定版本、审核决定、共享许可、Hub纳入、引用和复用记录相互独立，版本升级不自动迁移旧决定/许可。撤回引用仍保留最小可见的关系/失效状态；未获授权者不能由关系标题/路径推知私有内容。已生成目标草稿不能被源撤回静默删除，须标记受影响并阻止后续依赖交付，历史审计保留。

并发保存用版本基准；冲突不覆盖。提交/审批/发布/应用支持幂等和未知结果核对，丢响应先查原操作，不自动新建或重复调用AI。来源变化后必须重新选择/核对，不自动替换成最新版。

## 6. 用户关键流程

### 6.1 从研究产出沉淀

S06/S10已有合法产出或经审核的结构化方案→选择“沉淀为资产候选”→自动带入固定来源/作者/版本→作者补用途、适用条件和许可→保存候选→A02核对→提交审核。原产出不改、不自动发布；只有可证明当前读/导出和沉淀权的对象可选。现行合成方法报告桥可复用，正式产出需另做适配，不能拿旧marker当通用输入。

### 6.2 上传/手工登记

A01原上传入口→选择现有资料或上传获准文件→明确类型、来源/权利和用途→提取结果供人工确认→保存候选。复用旧解析/存储/去重能力，但**上传不等于审核、索引、AI许可或正式资产**。解析失败保留可恢复状态，不造摘要；附件可先登记、解析失败仍不能伪装已处理。首批格式及大小由现有服务准入核实后定，不承诺任意压缩包/程序自动执行。

### 6.3 审核、发布与领域纳入

作者提交固定版本及用途→G02原治理入口定位同一A02→审核正文/来源/权利/敏感范围→通过或退回→具发布权者按通过范围发布→Hub维护者决定纳入本领域。可合并一次明确提交的操作，不重复录入资料；但权利决定和领域相关性仍分别留痕。资产流程不依赖被推迟的伦理材料模块或真正多中心管理，不取消源Study原有治理门禁。

### 6.4 发现、申请与引用

A01/Hub/Study按当前权限检索→右侧预览→A02固定版本详情。只有获准的摘要可被发现；详情/下载不足时展示可申请的范围和用途，不返回受限正文。申请人说明目标Study/用途/期限，授权人决定动作范围；已有授权不重复申请。引用生成固定资产版本/作者/来源信息并可复制，只有剪贴板成功才提示；复制失败可手动选择，不能编造DOI或发表信息。

### 6.5 AI解读与适用性核对

用户选源版本和有权目标研究→系统核对可比字段/来源→原科研Agent按已获准资料解释差异和限制→研究者逐项记录作为参考/需修改/暂不采用。保留问题/PICO、人群入排、结局、访视、CRF映射、方法范围六组；一组内逐子项显示相同/不同/未检查，不用总体通过率掩盖缺项。

当前缺少的结构化入排和目标方法声明应补对象适配或明确未检查，不让LLM从自由文本猜成已核验。相似≠等效，适用性建议≠方法学认可。原历史统计/阈值只由确定性程序展示；AI不重算、不填补缺失。AI结果绑定源/目标版本、选用依据和实际来源位置；未调用工具、Token不足、来源变化和失败应明确，不由普通摘要代替成功。

资产未获AI用途时仍可按原阅读许可浏览，但不能将其正文发送给模型。新解读不默认调用联网，确需外部来源时沿现有允许范围与真实工具证据，不把无需联网的解读伪装成新检索。

### 6.6 真正应用到第二Study

用户选择已获准版本及目标Study→核对当前源权限和目标写权限→选择支持的内容部件/映射→预览新增、保留、冲突与未检查项→明确确认→生成**目标新草稿版本**及复用记录。不可覆盖已启用Protocol/已采集CRF，不能复制患者数据、审批决定或源成员权限。只有确认写入真实目标对象、回读固定版本和血缘成功，才记“已应用”。

首批推荐只对研究方案模板完成这一条结构化应用；其他类型明确为引用/取文件/配方参考，不挂“一键应用”空入口。方法运行、表单装配、量表计分属于各自确定性能力，逐类型补适配后才能开放。派生副本是资产的新候选；应用目标研究与派生资产分别记录，不把两者混计。

### 6.7 修改、撤回与已使用对象影响

作者新建修订→查看相对当前发布版差异→再审核；旧引用仍指原版。撤回时说明影响范围→发布、下载/AI索引/新应用停止→有权者看到受影响引用和目标草稿→研究者重新评估。通知仅发给有权目标负责人，不在消息/日志暴露私有摘要。系统不能靠删掉原资产解除已有科研责任。

评论为有权成员对具体版本的讨论，不替代审核理由或正式更正；编辑/撤回留历史。相关研究只显示有权关系，不能由共同标签推断参与关系。附件按固定版本保存，安全下载失败可恢复，原生文件URL/Range继续当前授权；不公开存储地址或用长期直链绕过撤回。

原“编辑标签”在既有位置操作：草稿按当前编辑权保存版本；已发布资产的标签/领域修改形成待核修订，审核前不悄悄改变已发布版的检索/纳入范围。标签不产生访问权，变化留痕。推荐“换一批”与“查看更多”使用同一真实可见目录、保留已选对象，不生成假推荐或新权限。

## 8. 数据和统计产品规则

逻辑对象至少覆盖Asset、AssetVersion、SourceReference、Attachment、ReviewDecision、ShareGrant/Request、HubInclusion、Reuse/Derivation、Comment、UsageEvent、AIResult及Audit。优先映射旧Artifact/Version/Source/Review/File/ExportJob及既有权限；确有Hub特有字段才增受控扩展，不在PRD批准新表/迁移。

- 一个资产稳定ID，多不可覆盖版本；当前发布版与最新草稿可不同。每条引用绑定版本，来源定位可到文档/页段/原报告和执行快照。
- 对象所有者、贡献者、审核人、发布人和使用者分别记录，不把作者名当注册账号或把目录研究者强行绑账号。
- 全部/分类统计采用相同可见目录过滤与去重；我的贡献统计来自实际贡献事件；复用数只记成功应用/固定引用，明示口径；下载、浏览、AI核对另记不相加。
- AI/推荐索引只能包含获准且当前有效的版本/摘要，撤回、换版或权限变化可失效；缓存和分页不保留已失权对象。
- 数据集原始行留原数据存储；资产层记录数据字典/受控引用，下载授权不得从“可见元数据”推导。
- 旧两类候选不批量迁移或改状态。拟通过显式转换/来源适配形成新正式候选，原ID/版本/血缘/审计保留；旧历史仍按原策略读取。

## 9. UI/UE实施规则

沿用已确认Shell、左右布局、卡片顺序、Tab与操作位置；本PRD不是重画页面的许可。列表/表单/按钮14/22，连续正文/报告16/28，必要说明13/20，元数据12/18；不缩字挤空间。同页一项主动作，按当前状态在保存/提交审核/发布/申请/复用中选择，不把全部按钮堆成同等主操作。

常规默认当前合法Study/源版本、自动带入已有来源，不增加“先选内部类型→二次确认→再复制”步骤。内部hash/请求键在按需核查区，普通页面不出现WP编号、开发预算/接线进度；保留真实合成性质、来源、责任和失败提示。必要业务确认使用站内弹窗，Esc/取消保输入和焦点；浏览器beforeunload防丢保留。

加载、真空集、筛选无结果、权限失效、历史版本、解析失败、保存冲突、AI失败、未知提交结果分别表达。身份/范围变化清除旧内容，迟到响应不能复活；失败不回演示。列表返回保留筛选/页码/选中版本；长标题可到全文，关键风险不裁切。逐页完成获批范围及实际角色路径后再推进下一页；需延期Tab或改变布局须另列差异获批，不能以分期为由留下假功能销项。

## 10. 验收场景与度量

| 编号 | 必须举证的场景 |
| --- | --- |
| AS-AC01 | 研究产出/上传各形成候选，固定来源和作者可回查；原对象不改，失败无半成品 |
| AS-AC02 | 五类资产登记信息、当前版本/统计/筛选/分页同源，真实空集非服务失败 |
| AS-AC03 | 同一固定版本审核、退回、重提、发布/撤回完整；编辑期间旧审批不得误放新内容 |
| AS-AC04 | 非成员注册用户无私有Study数据；同租户管理员按真实身份行权，跨租户/未知ID均拒绝 |
| AS-AC05 | 元数据可见但正文/下载/AI/应用未授时各自拒绝；申请通过只放获准用途和期限 |
| AS-AC06 | Hub纳入只展示获准摘要，撤回后列表/搜索/推荐/索引和深链不继续交付受限内容 |
| AS-AC07 | 源A到独立Study B：解释差异→人工确认→新目标草稿固定版，源未改，血缘/审计完整 |
| AS-AC08 | 六组混合相同/不同/未检查可见；缺入排/方法声明不得显示适用已确认，AI引文可逐条核对 |
| AS-AC09 | AI真实任务/工具/来源/Token/失败与最终结果一致，未执行不得报完成，专业结论由用户验收 |
| AS-AC10 | 两账号并发/CAS/重复请求/提交后丢响应/撤权在途不重复生成、扣费或泄漏 |
| AS-AC11 | 下载/导出绑定当前权利与固定版本；取消/失败/过期不假成功，格式/范围/来源符合确认规则 |
| AS-AC12 | 图谱/贡献/共享协作/回收站/评论/趋势每一区域有真实数据/合法空态和完整路径，不只测主列表 |
| AS-AC13 | 原两候选族/现有方案/报告/资料、角色、旧服务不被新功能改写；迁移如需另批 |
| AS-AC14 | 1440/1366/1920、390/320及原生200%、键盘、错误恢复、截图/录屏；科研/管理员/受限角色均覆盖 |

验收主例推荐沿“针灸辅助干预抑郁障碍”研究：将已核对方案/方法报告转候选，经管理员审核在同租户限定范围发布，另一具名合成Study按新PICO核对并生成目标方案草稿，查原版本/来源和使用记录。不得把两份同源派生草稿的自检冒称独立研究迁移。

度量首先定义采集口径而非虚构目标值：首个候选完成率、审核退回原因、发现到成功引用/应用转化、来源可定位比例、无权拒绝/失败恢复、人工修改量和任务用时。初始量与具体性能目标在首批真实合成验收中建立基线后确认，不在本稿填假增长率。

## 11. 分期、交付风险与待确认

完整功能和建议首批见配套清单/计划。推荐先把原本人候选能力转成**统一真实目录＋正式版本/审核共享＋一种可验证的跨Study应用**，再补图谱、贡献、评论、推荐和复杂导出；但这不是用户已经同意延期这些区域。

当前已是2026-11-12。完整模块不可能凭既有WP08/09的3天估算承诺在11月中旬全部完成；不能把历史缓冲日期挪到今天冒称按期。建议先审批范围与首批资产类型，再给条件窗口；完整版本日期由用户决定，不擅自改原正式验收目标。前后端仅现有合成环境，不计划改旧系统；新增费用/权限/云/远端配置/真实发布另确认。复用受阻时先给Hub内最小替代或报告阻断，不默认把旧系统改造纳入本任务。

关键确认项：首批采用哪类资产完成真正跨Study应用；发布责任人/是否回避本人审核；首批共享到Study、Hub成员还是公开摘要；数据集/量表附件许可与导出格式；图谱/推荐/评论等是否允许分期。**最关键建议：先以研究方案模板完成独立Study B的新草稿应用，其他类型不假装一键复用。**
