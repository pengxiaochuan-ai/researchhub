# ResearchHub统一登录会话规则

日期：2026-11-06。状态：用户已确认的正式产品规则；ResearchHub自有实现已在本机专用合成环境启用并完成技术验证，正式部署尚未发布，用户体验验收独立。[本机记录](../testing/session-policy-2026-11-06.md) · [接口及装配](../technical/session-api-2026-11-06.md)。

## 用户确认的规则

1. Cookie与服务端认证会话均为12小时；用户实际操作时滚动续期，后台轮询不续期。
2. 会话过期后刷新受保护页面，自动进入登录页；重新登录后返回原页面。
3. 网络故障不误判为退出；停用账号或密码变更后不能继续续期。
4. 保持现有页面布局，不修改旧系统。规则属于ResearchHub正式产品，不是仅本机临时配置。

## 统一语义及边界

- 12小时为滑动有效窗口，不是“无论是否操作，从首次登录起12小时强制退出”。登录或有效活动续期成功时，Cookie与认证会话使用同一服务端基准/截止时间，不允许Cookie12小时而令牌仅2小时。没有获准增加额外绝对登录期限。
- 实际活动包括前台可见页面中的用户点击、键盘输入、表单编辑/提交和主动导航；仅打开页面、鼠标移动、窗口获得焦点、定时刷新、状态/AI任务轮询、WebSocket心跳、脚本合成事件和跨页身份核验均不得作为续期依据。用户主动刷新/导航仅在原会话尚有效且服务端校验成功时可视为实际活动；过期会话不得因刷新复活。
- 前端活动标记只能用于发起续期，不是授权证明。续期必须验证未过期的原凭证、当前账号及租户状态、authVersion/密码失效版本和部署租户范围；不得按旧JWT角色、邮箱或客户端时间直接续签。不上传用户输入内容，只处理活动信号；不将令牌写入浏览器可读持久存储或URL。
- 账号/租户停用、密码变更导致旧凭证失效时，后续续期必须拒绝；新登录仍按原账号安全流程执行。退出后迟到的续期响应不得恢复登录，多标签页不得互相覆盖为旧身份。活动合并/节流不允许把“无活动心跳”变成保活；请求并发与失败不得自动重复业务写入。
- 明确的认证失效与业务无权、网络不可用分开：401/经确认的会话失效才进入登录流程；业务403只反馈权限限制，不一律当退出；断网、超时、5xx、无效响应保留原页面及尚在内存的输入，提示重试，不清Cookie、不假称注销、不跳登录。重连后重新核验；若实际已过期再进入登录。
- 受保护页包括本人科研、Study工作区、知识资料私有操作、科研AI私有任务、个人资料和管理后台；公开门户、公开目录与登录/注册/找回入口不强制登录，不制造重定向循环。正式实现须明确逐页保护清单，不按全站统一拦截公开页。
- 返回路径只接受同源、允许的页面及必要业务上下文，复用并补齐现有safeAuthenticatedReturnTo白名单；拒绝外域、协议相对地址、嵌套登录回跳、重复/未知危险参数及URL中的凭证。无效返回地址回“我的科研”；合法页面若新身份无权，显示其权限受限状态，不自动授权。返回仅恢复页面位置，不重放保存、审核、导出或模型调用；不承诺刷新/重登录后恢复未保存表单。
- Cookie维持HttpOnly、适当SameSite与路径隔离，正式HTTPS部署必须Secure；续期写请求校验同源/CSRF，禁止通过任意GET或后台读取静默续期。Cookie命名/部署范围与旧系统分离，互不影响登录状态。不可依靠修改旧系统共享认证实现来达成本规则。

## 实施前核对（历史快照，非现行配置）

实施前本机`scripts/local-knowledge.mjs`中JwtService配置2h，复用的旧AuthController下发12h Cookie；`src/platform-user.js`负责身份核验，`src/platform-auth.js`没有统一过期跳转。现在已替换为ResearchHub自有HubAuth装配、12h共同截止及续期/退出记录，前端共用活动/回跳链含知识iframe；不改旧源文件。以上历史缺口不可再当作当前仍为2h。

## 实施建议与非目标

建议由ResearchHub独立会话适配层复用现有账号认证、状态/authVersion校验及安全返回函数，统一后端Cookie/会话时钟、前端活动续期和受保护页失效处理。不同部署入口都必须装配同一规则，不能仅修改本机启动脚本。暂不指定新数据库表、新权限、单点登录、设备管理、长期refresh token或旧系统迁移；是否需要服务端会话记录须在实现规格中结合现有结构评估，不默认扩建共享底座。

替代路径：只改JWT为12h不能满足活动续期/跳转；每个API返回都续期会被后台轮询永久保活，均不满足本规则。修改旧系统共享控制器被用户明确排除。具体实现规格与测试计划完成后进入已约定的串行实施及独立总评审，本规则不等于生产发布授权。

## 必须通过的验收

| 场景 | 预期 |
| --- | --- |
| 登录成功 | Cookie与会话同为12h，凭证不进入URL/浏览器可读存储 |
| 有效期内实际操作 | 服务端校验后两者同步向后续12h |
| 无操作但持续轮询/隐藏页 | 到原截止时间失效，不续期 |
| 过期后刷新受保护页面 | 进入原登录页；登录成功返回原合法页面，不重放业务动作 |
| 公开页面与登录入口 | 匿名可访问，无登录循环 |
| 断网/超时/5xx/业务403 | 不误跳登录，不清凭证，输入保留并可恢复核验 |
| 停用账号/租户、密码版本变更 | 原凭证及续期拒绝，不因前端操作复活 |
| 跨站请求/外域返回参数 | 拒绝续期或安全回默认页面，无开放跳转 |
| 多标签、退出与迟到续期 | 不恢复已退出/旧身份，不重复业务提交 |
| 同一身份各受保护页、管理员和科研人员 | 同一规则、原权限/布局不变；旧服务无文件或配置变更 |

单元假时钟验证12h和活动识别，真实PG回滚验证停用/密码版本失效，真实HTTP校验Cookie与续期/同源拒绝；真实Chrome验证管理员和科研人员的操作、空闲轮询、过期刷新、回跳、断网恢复与多标签。使用专用合成环境、截图/录屏和请求状态留证；不为等待12小时改电脑时钟或削弱正式时长，不动真实账号。必须区分规则确认、代码实现、目标装配、真实执行和用户体验验收。
