# 团队维护状态与弹窗局部优化

用户批准顺序：先状态/动作，再局部信息精简。全局导航、配色、正文14/22和44px操作、权限、来源、公开确认、审计与后端协议不改。仅本机合成环境，原用户团队只读。

## 状态与动作

关闭/放弃弹窗后GET刷新已应用查询及页码；不清搜索输入/位置，旧请求不得覆盖新结果。刷新失败保留列表并明确未更新，提供重试，不伪称最新。后端成功提交/回执仍在对象回读及列表刷新后关闭，未确认结果仍锁新提交/关闭。

只有已保存且当前版本已审核、本地无修改、展示范围未变化时，增加只读preview核对；确认没有待审事实变更后，主按钮显示“已审核”且不可重复提交。核对中禁发；网络失败不当已审核，允许重试。存在服务端待审事实变更时允许原动作。新建/保存待审草稿/本地编辑/范围变更不因dirty=false误禁用；审核时仍走原CAS、预检与显式公开确认，不能把新核对当作权限。

## 局部精简

列表自动刷新和翻页统一使用已应用查询，而非正在输入的搜索文字；刷新失败时窗内、窗外都有重试，不能把整个弹窗锁死。长标题可换行，关闭按钮不挤成竖排。相关回归及证据见[本机验证](../testing/team-status-ui-2026-11-08.md)，无正式发布。

弹窗一个“审核：团队名称”标题，下面短状态/保存时间。必要时说明仍展示上次审核结果，不重复大标题/泛化说明。审核范围与选填备注进入第3个分组，历史与异常恢复完整。成员姓名一处展示、可见标签“团队角色”及“移除”，可访问名称仍含具体人员，确认条件不变。审核成功文案只说实际展示结果。列表保留原列与“审核”按钮；已有展示但草稿待审写“有待审修改”，首次写“待首次审核”。不批量改其他页。

验证：状态纯函数/SSR先RED→GREEN；浏览器验证列表刷新/查询分页焦点、清洁已审禁发、待审/范围/编辑可用、网络与迟到响应、弹窗局部和窄屏。仅原独立合成夹具允许持久写，旧团队只读；受控网络故障单独标注。独立评审及文档同步后交用户验收，不宣称正式发布。
