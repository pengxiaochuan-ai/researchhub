# 舌图上传、归档与访视回看

日期：2026-11-19。范围来自用户本轮确认的三步操作：本次访视进入岐研AI → 上传舌图且带入研究/受试者/访视 → 核对后归档并返回原访视查看原图及采集记录。

## 1. 实施边界与复用

沿现有S09“文件与处理记录”、岐研AI“上传文件”和媒体归档/显式登记链扩展图片，保持Shell、布局、既有表格及视频操作。科研与管理员使用同一入口，实际权限由当前服务端身份决定。复用原分片、SHA身份、私有对象存储、原键恢复、来源及目标双授权、登记回执和审计，不另建图片库或上传引擎。

本轮工程默认：PNG/JPG/JPEG，单张不超过25MiB；先检查实际格式、尺寸和可解码性再允许登记。原字节保持，不压缩重编码、不裁剪、不去除EXIF后冒称原件；页面不读取或展示EXIF。文件名由系统生成，业务只关联假名编号。首版上传至此入口的图片明确由操作人核对为舌图，系统不做医学内容识别。

不扩展语音、EEG/fNIRS、图像特征/证候识别、质量评分、临床规则、统计纳入或生产部署。文件检查通过只证明格式可读，不能证明采集质量合格或舌象内容已分析。

## 2. 操作与反馈

1. S09既有“到岐研AI上传”带入已核验的Study/受试者/本次访视，AI显示原上下文；已有待确认/未知操作优先，URL线索不覆盖原操作。
2. 原“上传文件”选择舌图；显示实际文件名、上传/归档/检查状态。成功后可查看原图，在原登记区核对归属与采集时间，主要动作沿原“核对并登记”语义一次确认。
3. 登记成功显示真实研究/假名编号/访视、采集与登记时间、检查状态。返回原访视定位原文件区，显示“舌图原件”和登记记录，按当前权限查看原图。刷新只读找回原回执，不重复上传或登记。

图片未归档/检查失败不能登记；超时及丢响应先核对原操作。取消/失败保留当前可恢复输入，未保存离页沿一次站内确认，刷新/关闭保留beforeunload。切账号、失权、来源变更、父链错误时不继续写入，清理旧图并提示可执行的核对路径。图片加载失败单列，不能以原始存储地址直链兜底。

## 3. 数据与接口契约

沿原session-media API、版本和幂等键扩展JPEG/PNG；旧视频DTO和回执兼容。图片必须显式可区分于视频，检查结果提供hasImage及合法width/height，保持contentUnderstood=false。登记生成原ModalityFile，modality=tongue、kind=raw，保留原SHA/父链/采集时间/登记来源，status仍按原原件待核对规则，不生成ProcessingTask/Feature。

原件读取仅使用已授权的本人会话或研究侧登记内容端点；逐次核对当前权限、原件SHA、归属与登记状态，返回正确Content-Type、私有缓存及nosniff，无公共存储键。图片内容不送模型或外部托管服务。

现存媒体表extension/MIME约束及登记guard硬编码视频，必要升级限定本机合成库原两个约束和同一个guard函数，精确up/down、就绪核验、独立审查、PG全回滚正反例后再由根应用。无新表/角色/grant，不改原业务行或ACL；正式部署另行进行。
