## 4. 集中审阅如何工作

集中内容在原“访视完成”区内展开，不开全站新页面。原“本次采集要求”仍逐行显示状态并可定位原表。

| 行内容 | 展示和可执行动作 |
|---|---|
| 已提交待审阅 | 原文答案、确定性评分及不完整原因、当前修订、来源渠道；有权且满足独立审阅后可选择 |
| 已审核通过、未锁定 | 显示原审阅人/时间；同一固定修订仅执行缺少的锁定，不再造一次通过记录；原作者若具备锁定权限且该修订已由合格他人审核，可执行锁定 |
| 已审核且锁定 | 只读显示该表单审阅/锁定已完成，不据此推断整次访视已完成；不纳入重复提交 |
| 未填写、草稿、H5未回收 | 显示具体缺口并定位补录/邀请状态，不允许批量通过 |
| 已退回、有需处理疑问或来源变化 | 展示问题及原字段/修订入口；按现行政策提示处理；现有complete并不将所有未关闭疑问作为通用门禁，本轮不新增该门禁。确有原规则阻断的来源/证据问题仍阻断 |
| 独立审阅不足或无锁定权限 | 原因清楚显示；允许的单项动作继续可用，不能因按钮合并取得额外权限 |
| 文件、处理任务、质控要求 | 在同一完成清单展示原状态，沿原处理入口办理，不把表单批准当作文件/任务合格 |

汇总不能用fulfillment的“已满足”或assignment的submitted冒充已审阅锁定；提交即可能使fulfillment满足。必须复用逐份GET assignment的当前ref/version/review/lock/capabilities，或新增同等受限只读汇总；完成时仍重核所有必采证据。

集中清单包含本访视必采项及已分配的选采项；未开展选采不新增为完成阻断。“采集齐备”按原必采/适用政策判定，不强迫完成所有选采。

只覆盖当前访视明确列出的对象，不跨访视、跨受试者、跨Study或暗含全部分页结果。当前未读完整的清单不能提供全范围批准。选中不等于已审阅，只有明确提交且回执核实成功才改变状态。

确认文案示例：“审核通过并锁定已核对的3份表单？本次仅针对下列修订。锁定后修改须按权限解锁并填写原因。”清单展示实际题名，不能用内部ID替代。共用一次影响确认，后台执行单项时不再弹出重复确认。可审阅且尚未通过时canLock可能为false，不能把canReview与当前canLock同时为真作为合并入口条件。首次通过先按原canReview进入，审阅成功后再读取当前canLock；已审核未锁定对象直接按原canLock进入。原审阅会增加答卷version；锁定必须使用审阅成功返回或重新读取的新version及同一固定ref，不能沿用批次预览时的旧version。若发现并发更正或当前ref改变，停止该对象，不能把新版当作原批准。

没有独立审阅权限的采集人看到“待其他有权人员审阅”，可查看待审项。首版不新增派单、换角色、指定审阅人或消息通知能力，不显示“已通知”冒充实际触达。管理员也必须遵守独立审阅政策。

## 5. 系统处理与人工决策边界

**系统处理：**带入当前研究/受试者/访视；核对固定版本及当前授权；默认排序和定位下一采集项；只在明确的现场采集意图下准备首份/下一份缺失分配；依据原规则校验/计分；聚合本次访视状态与阻断；批次内依次审阅、锁定并核实回执；成功后刷新真实进度；后台管理幂等键、版本和审计；恢复时先查原结果。

**人工保留：**真实答案和文件；渠道同意及明确发送邀请；专业审阅及选择本次对象；批次批准与锁定影响的一次确认；最终访视完成的一次确认；退回、更正、解锁及重新核对的必要原因；原政策要求的独立审阅、偏差、豁免和用途判断。

不自动替人签同意、审阅、豁免、关闭数据疑问、修正异常数值、补零或补临床结论。不因减少按钮删掉后端检查，也不自动把无权项目跳过后称全访视成功。

## 6. 状态、主动作与异常

| 状态 | 访视级主要动作 | 结果或恢复 |
|---|---|---|
| 可开始且有相应权限 | 开始采集 | 显示真实准备进度并进入首项 |
| 进行中且有未完成项 | 继续采集 | 定位具体表单/文件/待回收状态，不强制改渠道 |
| 采集齐备，当前人可处理待审项 | 集中审阅 | 展开本访视清单，先处理异常 |
| 需要独立审阅，当前人不符合 | 查看待审项 | 显示需其他有权人员审阅，不代办 |
| 完成条件全部满足且有权限 | 完成访视 | 一次确认，实时重核后追加完成依据 |
| 已完成、依据有效 | 查看本次记录 | 保持历史只读；不重复完成 |
| 已完成、依据变化 | 核对更正影响 | 新修订审阅/锁定后，带原因重核原完成依据 |
| 任一提交结果未知 | 核对处理结果 | GET核对原操作，禁止并行启动另一批 |
| 无当前访问权限 | 无写动作 | 清受限内容；不靠旧缓存继续 |

部分失败按真实对象显示，例如“2份已审核并锁定，1份尚未确认”。允许保留已经完成的原生子操作，不宣称整个批次原子回滚；任何未确认、失败或仍不满足要求的必采项都会阻止虚假完成。首版任何子步骤失败或结果未知即暂停整个批次后续写入；已经成功的步骤保留。明确失败可核对原因并继续未领取且原修订未变的步骤，结果未知则持续只读核对。核对成功项后，用户明确继续剩余对象；若固定修订/成员变化，旧批次保留，重新预览并确认最新对象，绝不把新修订偷偷纳入旧批准。

开始已成功但首份分配失败时，同样显示已开始和准备缺口，不重复start、不覆盖已有分配。批次期间授权、用途或政策变化立即停止后续写；无权内容清除，网络故障保留当前页未提交输入。未保存答卷不写浏览器恢复标记；刷新/关闭仍使用原beforeunload防丢保护。

| 有权管理员/独立审阅者 | 同一S09、原当前身份能力与审阅政策，无需新治理入口 | 按角色显示待审/仅锁定/可完成，保持原记录定位和审计可查，不改变账号权限 |
| 后台/后端 | 原访视start、分配、答卷提交/审阅/锁定、疑问、complete/reverify、单项回执及原生审计 | 访视级只读汇总、固定成员批次编排与持久化原结果核对；仅页面循环调用不视为跨刷新可靠恢复 |

本轮新增Hub访视级薄编排合同。每个子写仍调用原服务，带原expectedVersion/expectedRef，逐项检查scope、角色、独立审阅和来源。batch与原生子操作分别绑定，旧单项入口继续兼容。持久化复用既有auditLog和rh_research.operation；没有新DDL/grant，没有复制统计批次引擎或重建旧模型。具体路由、固定成员和事务证明见[技术合同](../technical/visit-capture-review-flow-2026-11-16.md)。

批次需记录固定Study/访视/发起人和身份版本、请求摘要、明确成员/修订、动作、原生子键与真实状态。查询限原账号与原授权范围；管理员能看业务不等于自动可代查他人私有操作回执。恢复标记只放最小标识，不放答案、自由文本原因或凭证。未知回执只GET，不自动POST重放；明确继续时重核权限和原成员。单项回执404不证明未提交；没有原子操作完成证明时保持未知并停止后续写，不能凭当前“已锁定”等终态推定本次请求成功。仅已明确未领取的子步骤可在原批次内显式继续；未知在途步骤先核对，不能换键重做。

## 8. 点击模型与验收标准

旧路径计数是设计比较模型；本轮实际页面已核实新路径审阅至完成为8次操作，独立空白访视单次开始进入首表为1次。相同起点假设同一访视有3份已提交未审核/锁定表单、无异常、当前人具备所需权限且独立审阅已满足，忽略填题、阅读、滚动、文件处理及疑问操作：

| 路径 | 改动前按钮/勾选模型 | 本轮实际新路径 |
|---|---|---|
| 开始访视并进入首份尚未分配、仅允许现场的明确首项表单 | 开始访视＋填写，2次；分配与打开原本已合并 | 开始采集，1次 |
| 审阅锁定3表并完成访视 | 每表打开＋展开＋审核＋确认＋锁定＋确认，共18次；完成＋确认2次，合计20次 | 集中审阅入口1次＋逐表核对选择3次＋批次提交/确认2次＋完成/确认2次，合计8次 |

旧路径是特定起点的上界模型，已打开表单会减少旧路径点击；未实测旧页面耗时，不能宣称实际时间减少60%。新路径由另一位合格reviewer实际核对，不将角色接力算成采集人一键批准。原MAIN首次因QA登录cookie路径不符中断，原成功start未重放；MAIN补跑与另一个空白访视的一次开始分别留证，详见验收记录。

最低验收矩阵：

1. 正常三表：一处开始、按顺序提交、集中核对与锁定、独立完成；刷新后事实一致。
2. PHQ-9原题/选项、Fang类别与不完整状态、HAMD特殊值及历史修订不变；H5/现场/CSV收敛同一审阅链。
3. 草稿、缺必采文件、待回收，以及批准方案实际配置的任务/质控、现行阻断疑问要求均按原规则定位；实际完成门禁不能被表单批审替代。未配置项明确标不适用，不冒充实测或新增通用门禁。
4. 独立审阅不满足、只可录入、当前可审尚不能锁、当前仅可补锁、无完成权限及管理员路径分别验证；批次不越权。审阅/锁定/完访当前共用study.review，区分业务状态/独立政策与真正权限拒绝，不构造不存在的独立IAM角色。
5. 同批部分成功、超时/断线、刷新/新标签、服务重启、重放原请求键和迟到响应：只读恢复，无重复分配/审阅/锁定。
6. 并发更正、旧修订/旧访视版本、用途撤回、方案政策变化：拒绝错版本并停止后续操作，旧批次不换成员。
7. 更正后重审/锁定与重新核对完成依据：原完成时间和历史保持，后续分析对旧来源仍按原规则失效；不顺带重做统计/报告。
8. 原S03列表/S04详情/S09采集/S05疑问、科研与管理账号正常返回，旧单项调用兼容。
9. 真实浏览器按1440基准及1920/1366/390/320、原生200%、键盘焦点/Esc/返回、长量表/表格局部滚动，保存PNG/WebM。14/22操作字号，不缩字或裁掉阻断原因。
10. 单元/集成、真实合成PG/API、浏览器及用户业务结果四层分开；一次确认不等于后台全部成功。没有真实执行证据不能标为已启用。
