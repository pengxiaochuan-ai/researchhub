# ResearchHub 独立来源目录与导入批次设计

日期：2026-10-30。状态：**设计及八步实施计划已获用户批准；用户另行批准仅本机合成租户、灵枢心域 Hub、`admin@example.org` 的可撤销 `source.review` 最小授权。** Task 1 准入曾因缺少 Hub 范围授权而暂停；本次仅为解除该阻断，不扩大旧角色、私有 Study 权限、生产权限或发布范围。

授权落点采用 ResearchHub 自有 `rh_source` 追加式审核授权事件，记录租户、Hub、账号、`source.review`、grant/revoke、依据与时间；当前有效授权以最新事件为准。由已批准的本机初始化步骤写入具名 grant，运行时每次服务端重新核验，不把 `tenant_admin` 身份自动等同 Hub 权限。它只允许操作来源审核流程，不等于任一来源/字段/用途已获得内容许可；后者仍需管理员显式录入依据并作出内容决定。

## 意图与范围

ResearchHub 需要自己的来源目录和可重放导入批次，令领域内容页及以后 AI 检索能够回答“哪条来源、哪个版本、凭什么可展示/检索、谁审核”。旧系统知识库继续作为 ResearchHub 下**独立 Study 的私有知识工作区**呈现，不把旧 `KnowledgeBase` 的 `researchProjectId` 关系改造成公开 Hub 目录，也不让注册用户凭 Hub 身份继承私有 Study 权限。Study 的具名 ID、成员及初始化动作必须另按原授权核对。

用户提供的两份文献工作簿可作首批候选：中文合并表 10,537 行、英文去重表 5,160 行，含书目字段和摘要，**没有全文列或全文原件**。来源 sheet 与合并/去重 sheet 是同批血缘，不相加计数。入库范围可包含原始行、题名、作者、期刊、年份、DOI、链接、摘要；“全部导入”首先指完整保全候选及错误行，**不等于全部对公众展示或全部进入 AI 索引**。来自 CNKI、万方、维普、WOS 等的内容，须逐来源/批次证明使用权；工作簿在本地不构成可公开转载或模型处理的许可。

## 目标、非目标与约束

- 目标：来源行与规范化实体分开、文件/行级溯源、批次幂等及错误重放、许可与审核独立门禁、授权撤销即时阻断未来读取和 AI 检索、列表详情引文可追到原始版本。
- 非目标：本轮不抓取整个网络、不过滤后宣称覆盖全部 15 个领域页、不购买受限全文、不做旧历史数据迁移、不自动批准内容、不开放新 Study/角色权限、不改旧服务代码或临床库。
- 环境：只在现有本机专用合成环境设计与后续验证；共享 PG 实例/库内使用 ResearchHub 自有的增量对象和租户边界，生产迁移、远端配置、云资源和真实发布另行确认。所有数据路径遵循服务端租户/Hub/Study 授权，不能只靠前端隐藏。
- 科学边界：AI 仅对已审且当前可用的来源做定性解释/引文，不编造全文、文献事实或数值。来源不足时明确不足，不以未审记录补齐回答。

## 方案比较与决定

| 方案 | 好处 | 关键代价/风险 | 结论 |
| --- | --- | --- | --- |
| A：直接把领域文献塞进旧 `KnowledgeBase` | 最快复用解析、审核、检索 UI | 它按 `researchProjectId`/Study 授权；公开领域来源与私有研究知识混同，跨 Hub 引用和批次行血缘难表达 | 不采用 |
| B：ResearchHub 独立来源目录/批次；旧知识库保留独立 Study | 与现有 Source→Canonical→Hub 逻辑层一致；可逐字段治理权利、跨来源去重、撤审和复用 | 需新增小范围目录/导入模型与接口，不能假称旧模块直接覆盖 | **用户已选择** |
| C：直接用工作簿作为前端静态数据 | 立刻可见 | 无当前授权、版本、撤权、审核和可复核 API；与去演示数据目标冲突 | 不采用 |

## 逻辑对象与不变量（供后续物理设计）

1. `SourceRegistry`：来源机构/数据库或开放仓储、官方入口、抓取/导入方式、条款版本及核验时间、联系人/授权凭据引用；来源名称本身不是使用许可。与 ResearchHub 租户、适用 Hub 关联。
2. `ImportBatch`：不可变的输入文件/远端检索快照、SHA-256、原文件名、来源/工作表、映射器版本、操作者、起止/发表/检索/导入时间、状态及成功/重复/错误数。相同文件+映射版本+作用域重跑不复制来源行；保留重放记录。
3. `SourceRecord`：每条原始行或开放 API 文档的定位（batch、sheet、row/PMCID/DOI）、原始字段、row/content hash、原始 URL、抓取时间、解析状态和错误。原始证据不可由去重覆盖；缺题名等坏行也保留待处理。首批本机暂存还须保存受控的原工作簿快照及其哈希，不能只记一个可能失效的本机路径。
4. `CanonicalPublication` 与来源关联：规范题名、作者、期刊、年份、标识符、摘要等按版本保存；DOI 优先，缺失时确定性候选匹配再人工决定，绝不只按近似标题静默合并。一个规范记录可有多来源，展示/AI 可用性按所用内容的具体来源与版本判定。
5. `HubInclusion`：记录进入哪个 Hub、决定人、审核时间、可见范围与撤回历史。旧 Study 私有文档不自动建立此关联；以后从 Study 向 Hub 贡献须走独立权属/公开授权流程。
6. `ContentGrant`（可由上述关系承载）：对书目元数据、摘要、全文分别保存许可标识、证据链接/文件引用、版本、允许的展示/索引/模型用途、受众范围、审核人、有效期与撤销时间。**未知、过期、冲突、未审 = 不进入公开列表、全文分发或 AI 索引。** 元数据/摘要/全文不得用一个“已授权”布尔值包办。

物理表名、索引和 API 路由在实施计划中定稿；这里是契约，不宣称数据库已有上述表。建议只增 ResearchHub 表/字段，不重写旧 `KnowledgeBase`；同库隔离需用两个租户及第二 Hub/Study 反例验证。原始工作簿/全文对象的存储位置、加密与保留周期沿既有受控存储策略，不能把原文塞前端包或日志。

## 状态、接口与体验契约

批次：`CREATED → VALIDATING → STAGED → REVIEWED/REJECTED`，失败保留错误和可安全重试的步骤；来源内容：`STAGED → RIGHTS_VERIFIED → CONTENT_APPROVED → VISIBLE/INDEXED → WITHDRAWN`。这些为设计态名称，实际枚举须与旧系统共存验证。**暂存**是把文件快照、批次及每行原始字段/错误持久写入 ResearchHub 隔离区，初始权利未核验、内容未审核、公开/AI 开关均关闭；它不是临时浏览器缓存，也不是已发布的文献目录。审核与授权两道门均通过后才可进入列表、详情和索引；同一内容的某一用途被撤销时，缓存/向量候选失效，服务端读取前再验当前授权。历史引文保留不可变标识和不可公开的审计信息，但被撤权内容不继续交付。

首个纵向切片分两道验收：① 批次上传/预检、全部原始行及错误报告、幂等重放（只在隔离区）；② 仅对少量有权利证据且经内容审核的候选，贯通 E01/E02 真实列表/详情、来源定位及同源受权检索。第一道通过**不算**公开页面或 AI 检索通过；如果第二道权利证据迟到，则明确阻断第二道，不以全量暂存冒充内容上线。管理端看批次、错误、去重候选和撤回；科研端只看已准内容与“来源/版本/授权范围”提示；后端输出同一版本和权限判断。用户未授予的 Study 成员、正式审批/发布或付费 AI 调用不因这张目录自动开放。

E01/E02 现有样板中的研究设计、主要结果、引用网络、方法、结果和讨论，不能从书目或摘要推断。首批列表/详情只呈现已取得且获准的字段；缺全文或结构化证据时显示“来源未提供/尚未审核”的明确状态，不展示前端演示段落、AI 补写结果或伪造引用网络。开放全文试点也仅填充实际解析并经审核的栏目，不把全文存在等同于自动完成研究方法学抽取。

接口最小原则：列表只能过滤当前租户/Hub和 `VISIBLE` 且对应字段可展示的版本；详情按同一条件重验，不得靠列表的旧结果取全文；来源/批次审查接口仅给原有获授权管理角色，先做权限清单再建；AI 检索必须复用同一可见性判定并返回 sourceRecordId、canonicalVersion、contentHash、来源 URL/DOI 与引用片段位置。错误、重复、撤权和跨租户访问须有明确状态，不回退前端样例。

## 首批内容与开放全文试点

1. 两份工作簿先进入**候选/隔离区**，校验工作表、行数、空题名、长摘要、DOI/URL、重复及原始文件哈希；只有具证据的字段被逐项批准后才进入用户可见/AI 可检索范围。用户此前表达“摘要、全文也导入”，该产品目标保留，但不覆盖第三方权利人的许可条件。
2. 当前可补齐一个小型、具名的开放全文试点：由工作簿 DOI/PMCID 对齐到 PMC Open Access 可重用子集或同等明确许可的官方开放来源；逐篇记录许可证文本/URL、条款版本、允许的用途、原文哈希和获取 API。**免费可读不等于可再发布/供模型处理**；遇到许可不明、第三方图片或使用限制即停留元数据/链接，不抓全文。
3. 不通过 PMC 正文网页做批量抓取。PMC 官方说明 OAI-PMH 可提供元数据及具备重用权的全文，自动获取须使用其允许的服务且每篇许可不同：[OAI-PMH API](https://pmc.ncbi.nlm.nih.gov/tools/oai/)、[版权说明](https://pmc.ncbi.nlm.nih.gov/about/copyright/)。开放试点需要另在实施前明确条款版本和可接受的授权证据；不把整个 PMC 或表内 PubMed 记录视为可重用全文。
