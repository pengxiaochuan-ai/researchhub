# 岐研 AI · ChiCTR 实时检索、详情读取与比较

日期：2026-11-10。状态：**设计和小步计划均已批准；C01入口探针已实现，访问核准未通过，业务能力未启用。**

## 1. 目标与边界

用户在原 AI01 会话用自然语言查找中国临床试验注册中心的公开试验，读取选定记录，再比较研究设计。用户已确认本轮不附带批量入库；不修改独立 collector、不建定时任务、不自动审核为 Hub 资产，不恢复暂停的旧费用核对。

沿当前目录串行实施＋一次独立代码总评审；开发与验证限本机原两个合成账号、当前合成 Study，数据库限 `wp01_test_full_baseline`。外站仅提交公开研究主题，不传内部身份、病历、私有方案或凭据。旧服务、共享底座、角色/额度、云资源、远端配置与真实发布均不在本轮。

## 3. 路径取舍

1. **采用：会话按需受控读取。** 用户已选择先完成实时检索、详情与比较，不附带批量入库；复用现有 Job/Message 归属和来源快照，降低接线成本。
2. 暂不采用：先批量采集入库再检索。这会扩大到 collector、审核和全站索引，且不满足本轮实时能力目标。
3. 不采用：把整个浏览器/任意 HTTP 开给模型。既有固定来源运行时已能完成目标，无需开放任意网站、脚本或文件权限。

获取传输优先使用核实过的正式接口；若无正式接口，才采用符合公开获取规则的固定站点网页读取。后端可直接读取则不引入浏览器依赖；如必须新增长驻浏览器、第三方付费服务或登录凭据，停下提出具体差异，不静默改造架构。开发者浏览器核查能力不等于产品运行时已有浏览器。

## 4. 用户任务与默认行为

- “在 ChiCTR 查找针灸治疗抑郁症的临床试验”：自动识别注册检索，不把注册试验路由到 PubMed 论文检索。疾病、干预、年份、研究类型与招募状态仅在语义核准后应用；不能保留的条件问一项澄清，不静默忽略。
- “读取第一项的研究设计、纳排标准和结局指标”：绑定本人本会话最近一次成功 ChiCTR 清单的实际记录。也支持当前原站已核准的完整注册号；不能将注册号猜成 proj 参数。
- “比较第一项和第二项”：固定两条已选来源和快照，比较人群、干预/对照、随机/盲法、计划样本量、结局与测量时点、状态及已登记局限；不混用最近 PubMed 清单。
- “继续”保持原问题、来源/版本和选择，不把旧 AI 回答当证据；仅明确要求更新时重新读取，形成新快照，不回写旧答案。
- 明确“不联网/只用 Hub”时不请求 ChiCTR；同一句又要求实时注册检索则澄清冲突。注册信息不等于全文 Protocol、已完成研究、疗效结果或伦理批准的独立证明。

提议的首期产品范围：每次返回最多10条注册清单，默认6条；读取/比较1–3条详情。需要更多时明确告知本次覆盖，不宣称穷尽。该范围是响应体与来源负担保护，不是开发累计任务/费用门禁。请求串行、同源共享限速、遵守站点限速/Retry-After；不自动付费重试、不无界翻页。具体秒数由真实协议验证后确定并记入实现契约。

## 5. 接口与数据复用

在 Hub 的现有执行链新增窄适配器，暂定内部工具 `chictr_search_trials` / `chictr_read_trial`；不冒称已有官方 MCP。外部只读工具由受控后端执行，OpenCode综合固定证据。无需安装第十个默认 Skill：复用现有文献检索/解读 Skill，增加独立注册来源类型与所需工具；不改 Skill 的历史发布包/hash或强行套用 PubMed 专属依赖。

- 在 `server/ai-agent/skill-routing.mjs`、`session-skill-routing.mjs` 旁扩展注册路由/依赖校验，保留旧任务按原版本重放。现行依赖检查只对 PubMed 生效，不能删原依赖来凑新工具。
- 仿现有 `literature-query/retrieval/session` 分层；ChiCTR QueryPlan、字段解析及输出契约独立命名，不把注册记录编码成 PMID、论文摘要或 PMC B04 包。
- 复用 `KnowledgeChatJob.payload` / `Message.meta.provenance` 保存本次受限来源快照；**不是将注册记录发布或导入来源目录**。无新共享表、迁移、数据库权限或公开 API 平台。
- 证据含 schema/解析器版本、原始问题的安全研究主题、实际应用条件、覆盖/截断、注册号、真实详情URL、获取时间、原站更新时间（缺失则为空）、响应指纹和投影内容指纹；选定清单/父 Job/账号/租户/Study/会话固定。
- 每个公开业务字段保存 `value + sourceQuote + fieldPath`：题目、疾病、干预、对照、人群纳排、研究设计、计划样本量、计划结局/时点、研究日期、招募与注册状态、实施机构。未登记为 `not_reported`，读取失败为 `unavailable`，二者分开。
- 仅输出白名单业务字段；电话、邮箱、详细联系地址、签名、未公开附件不进模型或业务投影。不把全页 HTML、站点脚本、Cookie、验证码或内部研究路径发送模型。
- 提交/模型前后/刷新读取复用当前账号、租户、Study、会话、Skill 与对象状态校验；外部来源只能证明抓取时事实，历史呈现标实际获取时间，不伪称持续监测原站撤回。

## 6. 科研解释与失败规则

计划样本量、组别、结局及日期由系统直接呈现已定位的原文字段，AI做定性解释，不推算疗效、不编造计算。比较明确“相同/不同/未登记/无法比较”，结果未公开时不能生成治疗有效结论。沿现行三档处理保留有来源的解释，未可靠核验的局部标注，不恢复整篇见数字就拒绝。

| 情况 | 必须行为 |
| --- | --- |
| 搜索真正空结果 | 明确本条件无结果，保留查询；不造注册记录，不自动扩大疾病范围 |
| 校验页/403/405/429/超时或改版无法解析 | 本次来源不可用，保留输入和原站入口；不当作0条、不用旧快照替代实时结果 |
| 一条详情失败 | 列出实际读成功与失败项；比较任务未取得全部选定详情则不宣称比较完成，可保留已成功对象的只读信息 |
| 来源字段缺失 | 标未登记，不把计划信息或模型知识补成实际结果 |
| 引用不存在/编号错绑/版本不一致/越权/取消 | 不提交对应不可信结果；保留实际失败/工具轨迹，不交付迟到内容 |
| Provider失败/用量未知 | 沿原业务预留/结算或待对账，禁止改为0用量，不自动充值、补额度或处理旧预留 |
