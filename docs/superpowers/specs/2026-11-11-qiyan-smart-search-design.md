意图：研究者在原AI01输入问题，一次明确开启后即可搜索、读取网页、获得有真实来源与阅读范围的回答并续问；不用选择技术插件、管理内部版本或做额外入库审核。

## 3. 用户路径与开关处理矩阵

保留原左侧历史、正文、输入框、队列及来源位置；第三按钮改成原位可开关的“智能搜索”，用既有选中态＋aria-pressed，Tab/Enter/Space可操作，不弹“正在准备”或技术配置窗口，不新增右栏/页面。使用14/22操作、16/28阅读角色，不缩字号。

| 情形 | 实际行为 |
| --- | --- |
| 默认/OFF，普通交流或Hub问题 | 只走现有普通交流/当前获准Hub或固定证据，不执行WebSearch/WebFetch/PubMed外部请求；调用已配置模型回答不属于资料外检，仍正常计费 |
| OFF却明确要求全网/PubMed实时/读取外部链接 | 原位提示先开启智能搜索，问题保留，不暗中联网，也不把Hub结果冒充完成外部任务；不为此先付费规划 |
| ON，公开网页搜索/来源核对 | 新受控OpenCode工具循环按需搜索、读取实际选定网页、综合；显示实际已读范围和回链 |
| ON，明确要求PubMed | 复用原PubMed专门流程，但每次真实MCP请求也核对联网快照，不能从旧适配器绕过 |
| ON，但问题明确“只用Hub／不联网” | 本条进一步收窄，不联网；允许位不是要求每条都外检，不由模型放宽限制 |
| 仅解读本人已保存的固定证据或已有网页快照 | 不为了续问重复抓取；明确更新/新来源时必须该条已开启；旧AI回答不是来源证据 |
| 搜索失败/限流/校验页，或正文读取失败 | 清楚说明未完成、仅发现链接或部分读取，不以常识/Hub/PubMed的成功掩盖必需的联网步骤失败，不自动重试或切新付费服务 |

关闭开关只影响**之后明确发送的指令**，不假称取消已经提交的任务。已发/排队项固定各自的联网范围，并在原指令区域显示简短“智能搜索”状态，避免误以为现在的开关改变了旧任务；不增新的队列管理页面。继续沿现有编辑/删除：编辑只改文字，保留原联网位；要改变该项联网范围可删除后以新指令发送。未知提交按原编号核对/重试，不自动创建新编号或借当前开关重发。

新建、切历史/账号/Study、刷新均关闭当前输入区的开关，不从历史任务自动开启。已发任务恢复读取仍按其原快照，不触发新检索。单篇固定文章模式原B04来源不会因开启而被替换；只有明确的新外检指令才进入新联网分支，回答区分本篇与外部来源。

## 4. 最小数据/API契约与兼容

不建新共享表，不复制账号/权限/知识库，不迁移旧数据。复用Commands的Message.meta、KnowledgeChatJob.payload及Message.meta.provenance，服务器验证并生成版本化快照，例如：

```json
{"schema":"hub-network-intent.v1","enabled":true}
```

建议API在现有commands POST携带networkIntent；前端不上传角色、来源白名单或工具权限。服务端严格验证boolean/schema，未携带的新请求按关闭处理；不能将字符串true、模型提议或旧历史当用户允许。canonical快照为单一真实意图，route/job只绑定其hash与来源，不独立维护两份可分叉的enabled值。

- 提交幂等比较原始文字＋规范化联网快照；同requestKey改联网位返回409，不静默返回旧授权或另建任务。
- Message持久队列、原编号未知恢复、edit/revisions、stage、dispatch、route及Worker执行均绑定同一快照。文字编辑保留联网位，但再次执行必须重算更严格的文字限制；服务端当前身份/Skill/父链及claim/lease重验保留。
- 源码与新运行消费边界版本化。新规则覆盖本片上线后的新提交；旧完成历史仍按原schema验证/读取，不用新路由重判导致历史全失效，也不升级旧消息权限。专用合成环境只处理本轮具名新任务，不重新扫描、续跑或改写历史待办；旧在途或旧无快照任务若会被新运行消费，先停并核对，不能补造用户允许。
- 现有knowledge-messages、内部queue.enqueue等旁路新请求同样默认关闭并由实际出站层验证，不能只在commands按钮上守门；旧系统本身的其他租户不受本轮Hub规则改写。
- 普通对话的GENERAL_POLICY_HASH、自然检索的request/policyHash及Skill路由也要按新旧策略注册，不能全局覆盖当前提示词/hash再将旧普通历史判为失效。旧完成结果仍校验其原策略及当前身份/来源，新联网快照只绑定新任务；策略退役另行评审，不在本轮悄然使旧对话不可读。
- 新网页证据单独标web来源，不伪装成获准Hub记录、PubMed MCP结果或PMC固定全文包。记录原/最终URL、题名、实际查询词、获取时间、读取类型、截断/失败、原文片段、响应及文本hash、执行工具/状态与归属父Job。仅供本人授权会话与审计，不发布到公共来源库。

## 5. OpenCode真实执行与请求前边界

新增窄的智能搜索adapter，复用旧Client、独立workspace/XDG/临时loopback capability、当前授权和Worker执行上下文。旧runOpenCodeSynthesis仍保持固定输入单次能力；不能为新分支而全局删掉其工具防线。

允许模型在有限步数内提出真实搜索、读取及综合，后端每次调用均验证当前权限、联网快照、任务归属/运行版本、claim/租约、取消与产品资源策略。模型不能决定是否有联网许可，来源网页/历史回答不能注入系统指令。无需装备第十项Skill；新分支沿当前有效科研检索Skill的允许调用范围，不篡改九项已发布版本/历史hash。

搜索工具固定服务端provider及其官方HTTPS endpoint，只送经过核对的公开检索主题，不传整段会话历史、账号/租户/Study标识、私有材料、患者或受试者资料、Cookie、模型key。外部网页进入模型前去脚本/表单/隐藏指令，只保留有出处的限量文本；不能承诺任意自然语言敏感内容都能自动识别，出现无法安全形成公开查询时原位澄清，不先发送。

**网页读取必须在实际请求前守门**：仅公开HTTPS/default port；拒userinfo、环回/私网/链路本地/保留地址及云元数据；DNS结果验证并绑定连接，逐跳验证重定向，设置超时/流式大小/文本类型上限，取消后关闭未交付流。不借用户浏览器登录态、不执行外站脚本、不下载任意二进制、不传本机Cookie/认证头。事后tool trace/白名单校验不能替代这些控制。

首选原生websearch＋独立`hub_public_webfetch`受控只读工具（通过本次runtime的本机能力接口，在同OpenCode循环实际调用）；原生webfetch默认仍拒绝。只有S01证明其可施加同等请求前约束且留下真实轨迹才可直接使用，不能为“原生”名称放开风险。OpenCode其余shell/file/edit/任意MCP仍deny，子进程不继承数据库/Provider/Codex凭证。不需要操作系统或云网络改造来凑首片；发现必须新增依赖/代理服务时先提交差异。

公开检索不是绕过访问限制。ChiCTR原专项及其CDN放行仍暂停；本轮不实现其条件检索/详情、不绕验证码/反爬，不用搜索索引摘要冒充正式注册记录或全文。

## 6. 输出、历史与费用

用户得到直接回答、简短阅读范围与可点击来源；内部哈希/版本/模型轮次留在审计，不堆在页面。每条实质来源引用由服务端从实际工具证据渲染，模型不得补造链接或伪造已读正文。仅搜索摘要可呈现为候选，不能据其假称完整原文评审；无成功读取则不宣称完成正文依据的综合。部分失败与证据缺口明确标注，保留支持的解释，不因普通不确定性整答失败。

越权/伪引用/证据换版/任务失效停止交付；未读到不等于研究没做，网页日期不等于论文发表日期，注册/指南/论文类型明确区分。沿当前科学数值与确定性计算政策，不在本轮重做通用事实规则或授权LLM计算研究指标。

按原租户/账号Token额度、并发预留和真实用量结算；新工具循环可能有多次模型请求，每次必须保留Provider真实usage，汇总到一次业务任务。失败/撤权已知用量仍记账；已发出但用量未知保留待对账，绝不记0、自动充值、补额度或核清历史预留。业务资源界限（步数、超时、上下文/页面大小）可配置并展示实际覆盖，不恢复开发轮次累计金额/次数守门。新增外部搜索服务账单不伪装成模型Token费用；若现有通道需新付费账户/额度，先确认费用再调用，不自动切Tavily/Firecrawl。

历史保存已读快照及实际获取时间，刷新不再次检索或模型调用。当前身份、父对象/证据hash仍检查；不宣称持续监测任意外站撤回或网页更新。明确更新形成本人新任务和新快照，旧答案不改写。
