2026-11-18，承接用户明确授权：补齐两项可执行交付物，在独立合成环境演练，通过后再提交main；生产执行另确认。本文是当前任务，不恢复WP01完整排空或其他历史专项。

## 验收边界

1. 构建器显式读取旧核心源与依赖，生成有来源hash的私有包；不读取旧.env、不复制临床/历史业务数据、不启动旧AppModule。私有包不提交公开GitHub。
2. 包内含Hub代码及所需旧核心依赖，在独立目录/镜像中启动，不依赖原工作区路径。Mac node_modules不冒充Linux依赖。保留现行前端与业务权限。
3. 正式运行不建租户/账号/角色/Agent/额度，不从私有fixture授权文件恢复；初始化是独立、显式、具名的合成演练命令。未配置消费者/模型/存储等逐项报告未就绪，不以health200冒充全能力。
4. 数据库包包括完整结构依赖库存、候选有序DDL、前置结构指纹、逐项hash、迁移账本及plan/check/apply/verify执行器。仅旧Prisma历史或30SQL不能代表完整基线；需要同时核实际列/索引/FK/函数/owner/ACL/RLS。
5. 生产执行默认拒绝；本轮仅新Docker PG实例、新库/角色/具名合成数据，新端口/进程/存储，不复制历史任务、不恢复现租户队列。所有生产适用性限制明确列出。
6. 真实演练保存安装/启动、API/浏览器、数据库正反例、重启/幂等/失败回滚及零启动授权/历史任务认领的证据。付费AI不在本轮范围；只能验明确阻断/就绪检查，不称真实AI已执行。

### 确定性方法Worker交付

原生描述统计链使用独立Python Worker。构建时显式提供旧Worker源码目录及预先核定的内容摘要，只复制服务、三个确定性算子和schema，封存清单；不修改旧源码、不复制配置或历史任务。提供Hub独立Dockerfile，包含描述统计模块（不能沿用遗漏该模块的旧Dockerfile）；仅使用标准库，无模型、数据库或外部检索。演练只启动本轮具名容器，在专属Docker网络内访问，不公开端口；API显式配置本轮合成Study和Worker令牌。镜像构建/内容验证与真实算子请求分别留证，生产启用仍不在本轮授权内。

### 报告到资产的独立装配

沿既有资产登记/列表/详情/治理契约注入私有核心decorator和部署Host/Origin规则，不重做页面。各路由在真实业务事务内重新核当前身份、真实Study/父资产和原用途；管理员必须同时满足当前role与isTenantAdmin，不能仅凭角色字符串。原本机fixture适配保持不变；正式适配不读取其具名ID、slot或历史报告。报告来源使用同事务原生T17当前读取与固定版本hash；默认全部可访问Study只作筛选，登记时仍明确归属。未装配或未启用的付费能力明确返回不可用，不生成假结果。每个子链独立验证后才加入最终可交付清单。

## 已发现必须处理的差额

- 旧核心89份Prisma迁移与当前public实际结构可能不同，研究增量存在未写Prisma历史的手动DDL。
- Hub最终结构还有脚本内动态ALTER/函数/RLS/GRANT，30SQL库存不完整。
- 现有local AI启动会自动补角色/Agent/Token额度并启动命令扫描器，不能搬作正式入口。
- 资产部分CHECK、附件/评论/复用槽位及AI用途记录绑定具名合成对象，需要按真实父对象、成员和用途授权形成生产等价约束，不能删CHECK或改为true。
- 生产库基线本轮不访问。可交付执行器、候选DDL和严格门禁，不能称已验证对真实生产库适用。正式新角色/GRANT/停线/迁移仍需用户确认后执行。

## Hub检索原生执行装配

独立Hub Sessions实例接收原Queue认领后的execution/claim；原Sessions负责原生配额预留、真实usage、审计与assistant/终态同事务提交。Hub wrapper仅在内存RunInput中将一次只读kb_search绑定为Hub已审核来源，不把虚拟KB传入原Worker真实KB校验。专用Prisma facade同时覆盖elevated/app/tenant事务，在assistant INSERT前以原tx重验Agent授权及来源，保留原生租约/CAS/失败对账。普通旧服务与类源码不改。

仅装配普通Hub来源会话；其他上下文明确未配置，不静默转成普通Hub问答。`/agents`只列已配置且当前具名授权的Hub聊天Agent，不把方法Agent作为聊天入口。状态接口和提交门禁独立，无配置时禁止创建会话、消息、任务或预留。当前具名新库仅获准方法Agent，无聊天Agent/AgentConfig/AgentAccess/模型额度，故本轮免费验证执行拒绝与零写入；依赖注入测试只能证明原生调用和同tx契约，不能称真实LLM能力验收。新增聊天配置/使用授权/额度/启用消费者及付费实跑需单独具名批准。

入队由Hub专用Queue事务facade取得official→tenant锁后，在同tx核准入/具名AgentAccess/真实会话；原生创建完成后再核原生Worker当前权限，失败整笔回滚。启动仅准许已适配的knowledge-import/raw-processing/knowledge-chat，不因付费开关为true就放行其他运行分支。模型就绪检查复用原生ModelRoute resolver及当前凭据引用，不凭字符串假称就绪。合成标记不因改用正式入口而清为false，来源自身标识保持。
