# F01 V0.3 · 准入事务、装配与运维

2026-11-17。只适用ResearchHub固定`lingshu-xinyu`；不改旧系统全局Guard。业务政策见[规格](../product/f01-registration-admission-review-spec-2026-11-17.md)，真实结果见[验收](../testing/f01-admission-2026-11-17.md)。

## 事务与权限

`server/admission`管理application及追加event，两表FORCE RLS；固定tenant/Hub/account、注册材料、材料版本、决定、操作者authVersion、策略、原键/hash和结果。事件禁止UPDATE/DELETE，申请每次revision+1必须同事务有对应事件。密码与验证token不入材料，申请不写公开Hub资料。

WP02确认注册在原授权锁、席位核算与凭证消耗事务中调用registerInTransaction。注册失败全部回滚；成功创建active基础账号及pending准入，不签Cookie。旧注册回执不能变会话。拒绝默认不允许重申，管理员可在该拒绝决定中显式allowResubmit；补充／允许重申沿同一account与application更新，不重新注册，不释放席位。

当前有效审核资格为同租户active账号、有效authVersion、active租户、`role=tenant_admin && isTenantAdmin=true`且本人已获准；不能自审。审批目标账号仍active，当前验证邮箱须与固定注册材料相同。审核、原键核对均重验当前资格，旧JWT或旧管理员回执不能恢复权限。

决定持共同授权锁和申请行锁，revision CAS；同actor/requestKey固定hash。未知写GET带原applicationId/action/baseRevision/requestHash，正文不进入URL。已提交回原结果；当前修订未变且可核定原操作未提交才返回unsubmitted，前端只提供显式原键原输入重试；superseded保输入并重读新材料，不能套用旧决定。客户端核绑定及完整成功形状，未知结果不清草稿、不自动POST。

## 接口与入口

全部`Cache-Control: no-store`、原认证、同源POST及session-v1请求头，8KiB输入上限，严格字段白名单。

| 接口（前缀/api/hubs/lingshu-xinyu） | 范围 |
| --- | --- |
| GET /admission | 当前本人，含固定材料、原因、补充／重申能力及历史 |
| POST /admission/submissions | 本人指定补充／允许重申，原revision及原键 |
| GET /admission/operations/:requestKey | 当前本人提交或仍有权原审核者，完整操作绑定 |
| GET /admissions | 当前管理员；状态、姓名邮箱、20条分页，空末页夹到有效页 |
| GET /admissions/:id | 当前管理员；同Hub固定申请资料和处理记录 |
| POST /admissions/:id/decisions | approve／needs_information／reject，负面理由必填 |

准入Guard在Auth后、原Role/Study前装配到`local-knowledge`和`research-runtime`。原isPublic路由仍按各自公开字段白名单，受保护接口原则上要求approved；认证GET me、本人profile GET/PATCH、本人admission GET/submission POST及原操作GET是精确例外，不按目录整体豁免。缺schema、未知缺记录或不可核定均拒私有业务，不能以迁移没做自动放行。

| 非HTTP／复合入口 | 同事务落点 |
| --- | --- |
| 课题／Study | commands transact及resolveResearchStudyInTransaction |
| 内部Hub资料／引用来源 | visible-repository、external-visible、pmc-visible的私有／AI分支 |
| 接受Study邀请 | invitation-service accept，成员写入前 |
| 默认Skill读取／装备 | default-skills当前身份验证；批准不补AgentAccess或Token |
| AI提交／命令／后台发布 | local-knowledge-ai onJobCreate、commandAuthorize、validateTurnInTx；派发和发布前复验 |

这些落点是源码及契约范围；未借本次验收启动付费模型、原Worker轮询或历史队列。不能把拒绝探针当作新模型能力或所有部署均已验收。

## 界面与恢复

P004原字段、邮箱验证和P003登录保持；已登录无验证链接的加入入口只读本人状态，验证链接仍可独立完成注册但不覆盖已有Cookie。注册结果未知转原登录核对，不重复确认创建。P003按本人准入分流，安全返回申请页会归一为P01，避免循环。

P006有界可见GET：5秒起，错误指数退避上限30秒，累计120秒后暂停；隐藏中止、离页取消、身份／请求代次隔离，不调用renew。恢复过未知提交的当前身份保持申请组件，直到输入／在途／unknown安全清空，避免首次approved卸载草稿。会话草稿只含当前actor/authVersion的本次安全输入，成功清除；不是注册密码/token持久化。

G03原用户／成员功能保留，新增加入审核页签默认待审。资料内一次通过，负面决定同页理由；未确认时禁重复决定，列表条件／页码保留、详情焦点及返回位置恢复。P01业务读取前守门，右侧局部个人知识库入口复用K01，不自动建库／会话／加组；Study能力按[精确配置表](../product/f01-study-capability-config-2026-11-17.md)另核。

## 精确迁移与回退

`node scripts/f01-admission-migration.mjs --prepare|--predict|--apply|--check`只认批准的`wp01_test_full_baseline`合成标记及本机固定租户，不支持通用生产执行。prepare冻结ID／状态／角色／成员／席位和schema源hash；predict全部回滚；apply只增两表及其函数／trigger／最小ACL、清单20个legacy_confirmed和审计。check比较表／列／RLS／ACL／约束／函数／trigger完整定义指纹，未知漂移不覆盖。启动不自动DDL／补审批。

本机已应用定义指纹`b19b135aacbea5e8e26b9695d1512fce841c3da686069c5460e882b80bb7bf15`。私有迁移清单`.tmp/f01-admission/migration-manifest.json`含存量依据，不向Notion传凭据。禁止把现有schema.sql作为未来原地升级脚本；后续结构变更需版本化迁移。

故障时保留Guard、本人状态及历史，暂停注册确认、补充和审核POST，返回明确503；保留原公开读与必要认证恢复。不得回滚到未守门服务或删除表以放开pending。恢复前check定义、原账号/成员及原操作回执，再恢复写。正式生产、真实外发邮件及不同Worker部署另行配置／验证，不以本机apply扩展目标。
