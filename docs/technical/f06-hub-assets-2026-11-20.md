# F06 · Hub成果纳入与跨课题复用

日期：2026-11-20。当前仅独立合成环境实施与验收，生产迁移/发布未执行。

## 1. 范围与权限

用户确认方案A：获准Hub成员取得单一成果固定版的阅读、引用或复制许可，无需源Study成员身份。目录默认hub内部成员可见，元数据范围不推导正文、文件、AI或Study权限。

- 作者从A02本人业务资产详情申请纳入。沿用已有资产审核，不重新登记同一固定版。
- 管理员从G02常用管理的成果纳入审核处理；pending正文仅作者/有效管理员核对。
- 成员从H01原科研资产页签发现成果，提出用途申请；作者明确批准，亦可撤回单人许可。
- 引用记录固定来源；复制在本人有`artifact.create`的另一个Study创建真实原生`protocol_draft`私有草稿。H01以`copyId`直达，原P01“本人研究草稿”也可继续打开；读取和编辑继续核对目标Study权限。
- 移出、原资产/作者权限失效或过期停止新增发现与交付。既有目标草稿及来源历史保留，显示原成果不可用；不自动替换为latest或自动执行统计/采集。

## 2. 实现边界

`server/hub-assets/`拥有目录、用途申请、引用、复制事实及操作回执。`migration.mjs`是明确执行的迁移候选，启动不自动DDL；不放宽旧`rh_asset`或源Study RLS。

`server/research-runtime/hub-asset-bridge.mjs`只在调用方已有应用事务内工作。scope元数据仅解析IDs；实际来源读取和目标操作使用当前用户重新授权，禁止冒充原作者。原生草稿创建/版本服务与新Hub事实、审计、回执同事务提交。

源窄函数按当前账号、租户、准入和指定用途验证，不暴露源Study其他资料。当前支持已审核本人原创、无上游来源绑定的固定资产，以及下述精确适配的原生固定报告。上传附件、其他派生来源、未知报告schema或复杂上游链仍明确拒绝；既有同课题功能不构成Hub跨课题授权。

### 2.1 固定报告来源校验

报告入口沿用原生T17预览、创建、审核、发布，以及原有“登记为科研资产”流程。只有本人已审核的业务资产、`sourceKind=artifact`且唯一绑定一个`rh-formal-report-*`固定v1时可申请纳入；报告正文必须与所绑定报告hash一致。Hub不重复生成报告，不用历史正文兜底失效来源。

当前适配范围为原生`formal-analysis-report-v1`、T15 `t15-synthetic-plan-v1`的3个合成受试者、BASELINE、受试者统计单位及描述统计；不是任意真实研究或任意报告适配器。数值来自真实确定性Worker接受的Run；校验器只逐项核对并复制既有结果，不调用LLM计算、补数或重做统计。完成访视仅支持可完整验证的固定表单修订；含未版本化表单、必需量表或模态文件完成依据的复杂情形保守拒绝。

`report-source-migration.mjs`是单独的显式SQL差量，保留原创校验分支及原资产RLS。`read_source`对报告只返回固定身份描述，不直接交付正文；`report_bundle(entry,purpose)`限定单一条目、实际当前actor和`probe/read/cite/copy`用途，先复核成员准入及单资产许可，再提供服务器内部的最小当前来源集合。原作者当前的原生Study资格、`study_operations`开关、分析和报告权限继续生效；接收者不被提升为原作者，也不要求加入源Study。

锁覆盖原生T15计划序列化、科研项目/方案SHARE、排序后的受试者/入组/访视/表单分配UPDATE、选定表单版本SHARE、Run SHARE与报告UPDATE。等待锁后重新读取并比对固定链，锁保持至同事务交付或目标草稿提交；来源明确失效返回不可用，不中止整个目录投影。表单定义与并发变更的锁实测见专项验收记录。

`source-reader.mjs`必须在同事务调用`createHubReportSourceVerifier`，不能只依赖SQL存在判断或保存的hash。它重用原生策略/参与同意/修订信封/表单投影/质量守门/报告生成的纯函数，重建当前完整manifest并核对计划最新审核、快照、方法最新复核、报告最新审核、正文、blocks及来源快照。目录探测和引用也执行校验；只有获准的阅读与复制返回已验证固定正文，原始个体行不进入接口响应。

运行时额外传入与原生T15一致的`HUB_SYNTHETIC_STUDY_IDS`精确名单。校验器默认空名单并拒绝交付，不能由bundle中的Study自行开通；缺失、移除、错误Study或非法名单均不放行。未知来源不回退为原创，原生校验失败不回退到资产中保存的正文。

## 3. 接口

基址：`/api/hubs/lingshu-xinyu/assets`。所有响应no-store，认证/准入/当前角色/同源保护沿正式运行时。

| 接口 | 作用 |
| --- | --- |
| GET 根路径 / `/:id` | 已纳入目录 / 固定成果详情；`view=author`仅本人纳入历史，支持assetId/version分页前精确筛选 |
| GET `/candidates?studyId=`、`/reuse-targets` | 当前本人合法来源候选、目标创建范围 |
| POST `/submissions`、`/:id/decision`、`/:id/withdraw` | 作者提交、管理员审核、作者/管理员移出 |
| POST `/:id/usage-requests` | 申请单资产用途 |
| POST `/:id/usage-requests/:requestId/decision`、`/revocations` | 作者同意/拒绝、撤回指定许可 |
| GET `/:id/body` | 当前阅读许可下交付固定正文 |
| POST `/:id/citations`、`/:id/copies` | 当前引用许可记录、跨课题私有草稿复制 |
| GET `/copies/:artifactId`、POST `/copies/:artifactId/versions` | 本人目标草稿读取/当前版本编辑 |
| GET `/operations/:key` | 只核对当前用户原请求键的提交结果，不重放写操作 |

目录相关写载荷使用顶层`requestKey`和`expectedRevision`；提交初始revision=0。复制草稿保存使用`requestKey`、`expectedVersion`、`contentMd`，与原条目revision分离。请求哈希绑定动作、条目、载荷，以及审批/撤权的精确requestId。同键不同载荷拒绝；相同键核对回执时重新投影当前权限，原回执版本固定，当前版本可能更高。

草稿正文上限UTF8 131072字节，JSON请求沿全局256KiB上限。超过限制保留输入，不静默截断。

## 4. 独立验证与发布

准备入口：`scripts/f06-hub-assets-rehearsal.mjs`。只创建新的labelled容器、卷、随机凭据及syntheticOnly DB marker，使用可信纯结构，不从旧/生产库复制行数据。当前样例3账号、2Study，接收者源成员0、目标1。

运行入口：`scripts/f06-hub-assets-runtime.mjs`，独立API19662/前端19663、专用存储；原创阶段AI、邮件和workers禁用。报告来源后续验收仅在该owned环境启用全新确定性Python Worker19664，真实执行一次描述统计；付费模型调用为0，不复用旧Worker。验证运行时使用当前仓库只读挂载及已核私有core，属于开发验收装配，不冒称已形成clean生产发布包。

测试入口与状态见[验收记录](../testing/f06-hub-assets-2026-11-20.md)；用户步骤维护在[统一手册](../product/用户验证与操作手册.md)。只有真实PG/HTTP/浏览器及业务产物逐项留证后才登记该切片通过。生产还需精确迁移计划、打包、配置启用和生产复验，不从本机结果推导。

P01的Hub草稿入口通过`createHubCopyWorkspace({readTarget})`同事务核查后给导航hint，foundation延迟绑定后在app启动前由main绑定真实assets bridge。旧草稿不查询新表，不放宽旧设计角色，也不通过另事务持有同一授权锁造成死锁；详情仍重新核权，不将导航hint当作数据授权。
