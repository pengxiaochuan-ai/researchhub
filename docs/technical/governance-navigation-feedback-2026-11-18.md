# 常用管理导航与发布反馈 · 2026-11-18

## 本轮需求与边界

用户要求发布／更新发布成功后有站内弹窗并主动回资讯与活动列表；五个常用管理页面的导航布局统一。仅涉及来源审核、团队资料维护、AI用量与对账、邀请异常的治理入口及资讯与活动。用户已确认最小方案，已按页串行实施：页内统一标题、简要任务说明和“返回治理总览”，保留全局Shell、现有路径、权限和业务内容。

## 发布反馈实现口径

- 保留发布前对来源、使用依据和可见范围的一次确认。只有真实发布响应或原请求查询明确已提交，才回列表并显示“发布成功”／“更新发布成功”。成功弹窗只有“知道了”，支持Esc及键盘焦点；无需再点击返回列表。
- 返回保留当前筛选和页码，清除内容详情参数。若当前筛选不含发布后状态，如实提示按当前筛选展示，不暗改筛选。
- 保存草稿成功留在编辑器；拒绝、版本冲突、请求未提交或结果未知均不显示成功、不离开编辑器，也不自动重复提交。未知发布核对成功与正常成功采用相同反馈。
- 发布已提交后列表读取失败不撤销已知成功，也不自动重发。更换身份不带出旧身份标题、弹窗或私有内容。
- 不改后端/API、数据库或发布范围。研究者及门户继续读取原发布投影；管理员变化只涉及操作反馈和局部导航。

## 验证计划

先用真实组件单元用例核对共享弹窗旧用法兼容及单按钮反馈，再在真实Chrome＋真实API／PG回滚环境验证发布、更新发布、已提交丢响应恢复、未提交失败、取消和草稿保留。五页布局在实施前后同视口留图，核对角色权限、返回和业务动作未变；覆盖1440／1366／1920／390／320及Chrome原生200%，保存PNG、WebM与请求状态。目标环境只读核对导航，合成写入优先回滚，不改现有三条合成内容。

## 导航实施结果

复用一个局部标题组件及限定类CSS。来源／团队既有说明原文移到标题栏，不重复堆放；组件默认仍显示原说明，只有本轮G02嵌入显式移位。对账标题移到卡片外，表格、原核对弹窗和服务状态保留。资讯与活动新建按钮与筛选操作分组，编辑返回仍走原未保存／未知结果守门。

S11仅原裸入口及已有严格、有效overview邀请深链显示治理标题。实际带Study scope的成员页及P010接受页保持；没有新增from／view参数，也没有把界面分支当权限校验。原返回函数保留合法所属模块、页码及邀请关注页。

桌面统一24px、窄屏16px，标题20/28、说明与返回14/22，44px返回目标。初轮发现对账卡片的表格最小宽度撑大grid列，现限定minmax(0,1fr)及卡片min-width:0，使横向滚动留在表内；验收同时断言标题栏右缘和整页宽度，不以外层裁切作为通过。

没有增加后端请求、表、权限或业务动作。本机19501实际两角色、五页五宽及Chrome原生200%通过；管理员键盘返回、三类原治理上下文和真实既有Study入口已核，0业务写，未重载服务。用户体验及生产另验。
