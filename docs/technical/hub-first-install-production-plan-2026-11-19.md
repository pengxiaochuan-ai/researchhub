# Hub 首次安装到共享 aisci 库：实施与原数据保护方案

日期：2026-11-19。状态：**方案及源对象库存已完成，独立技术评审通过、待用户评审；不是生产可执行SQL或发布批准**。

本轮来源：用户确认Hub开发期间使用独立复制库，从未将Hub结构同步到生产aisci；要求补齐首次安装方案，避免误套增量并保护原有数据。承接已批准的生产只读核对；本轮只做方案、源码与结构依赖核对，不执行生产DDL/GRANT、数据导入、服务配置、停线或发布。

## 1. 结论与交付边界

采用“**复用现有public共享表＋安装缺失的Hub专有结构＋逐项审定共享表最小扩展**”。不恢复开发库、不合并两库数据，不再建一套账号、租户、Study或知识库基础表。旧系统和官网继续独立运行；Hub独立进程、域名、配置和应用身份，业务按租户及真实Study归属隔离。

必须新建独立的首次安装迁移包，建议ID为`researchhub-first-install-aisci-v1`，不能修改原五步包的before hash来适配生产，也不能只在前面随意加一段dump。原`researchhub-production-equivalence-v1`仅适用于其原基线，保留SQL、hash和演练证据；新安装包参考其最终业务约束生成新步骤和新账本，不伪造旧包的已执行记录。

“原数据不受影响”在本方案中的可验标准是：迁移不对旧业务行执行INSERT/UPDATE/DELETE/TRUNCATE，不改变原列值、ID/序列进度、原租户/账号/授权/研究归属；旧服务的原有读写与任务处理契约保持；不覆盖旧系统正常产生的新数据。共享DDL可能取得短暂锁，不能承诺绝对零延迟，必须以小事务、有限锁等待、真实兼容测试和失败退出控制影响。

## 4. 所有差额必须按五类评审

| 类别 | 默认处理 | 生产门禁 |
| --- | --- | --- |
| A 已存在且完全兼容的共享对象 | 复用；不CREATE OR REPLACE、不重新授权、不重放旧迁移 | 定义、列类型、唯一键/FK、owner/ACL/RLS及原调用契约匹配 |
| B Hub专有新对象 | 新建rh_*表/函数/索引/策略；只指向真实共享父对象 | 无同名未知对象，生产等价约束、tenant/Study边界和最小权限已验 |
| C 共享表的纯追加扩展 | 逐列/索引/新public扩展表列单，不与B混为一项 | 无旧行回填；旧读取/写入兼容；新列的逻辑默认值与扫描/锁成本明确 |
| D 改变既有契约 | 阻断，单列兼容设计；必要时优先调整Hub适配，不扩大旧底座 | 例如DROP NOT NULL/改默认/重写触发器/新全表唯一约束，不能按“只增”自动通过 |
| E 不明差异、合成白名单/夹具、历史SQL | 不自动应用 | 逐项解释或改为经审核的真实父对象/当前用途规则；不能删除约束或CHECK true求通过 |

已确认需要逐项核对的共享变更候选（**不是确认生产缺失**）：

- WP02源迁移涉及`public.account.emailNormalized/emailVerifiedAt`、租户邮件唯一索引，以及`account_action_challenge`、`research_member_invitation`、`wp02_request_window`。原账号不自动填emailNormalized、不重设密码/邮箱验证；旧账号等价邮箱查询、注册防重复、登录与找回须做兼容用例。旧账号若需规范化回填，另成数据变更，不混入首次结构安装。
- 身份资料源SQL给`public.account`追加`researchProfile`、`researchProfileVersion`、`researchProfileEstablishedAt`、`researchProfileLastMutation`及一致性CHECK。新增列默认NULL；历史行不生成伪档案。
- 研究执行政策涉及`public.study_protocol_version.approvedPolicyVersionId/approvedPolicyHash`及新增`study_execution_policy_version`；CRF修订涉及`public.form_response.currentRevisionId/lockedRevisionId/version`与3张修订/审核/回执表。`version DEFAULT 0 NOT NULL`会改变旧行的新字段可见值，必须显式验证；不重写原answers、score，不自动生成历史CRF“基线版本”。
- `public.study_participation_event`等共享扩展表、研究/方法/质控相关表与public函数，逐对象比对后复用或单独安装，不能仅凭开发迁移编号判为缺失。
- `visit_plan`四字段DROP NOT NULL/移除默认属于D类。默认不进入普通首次安装事务；先验证生产现状、旧服务对空值的假设，以及Hub草稿是否能用局部适配兼容。若确需共享语义修改，提交准确差异再评审；不能只承诺“旧行没UPDATE所以没有影响”。
- `governance-users/account-receipt.sql`等回执增量和脚本内动态ALTER/函数变更必须同时纳入，30份静态SQL不是完整依赖。

**保护边界**：不重建旧public表，不ALTER旧表owner/原RLS策略/全局默认权限，不对共享public执行宽泛REVOKE或GRANT ALL，不修改旧_prisma_migrations记录，不因Hub创建新的全库BYPASSRLS或给旧应用加超级权限。

### 4.1 共享public迁移的记账归属

public共享对象必须有唯一迁移权威，不能由Hub账本和旧Prisma各自执行同一DDL。I02逐项对照旧Prisma版本及checksum：已原生应用且定义一致的只复用；未应用的共享canonical迁移优先沿原生Prisma管理，但必须先证明全部待执行步骤均在本次审定白名单内、没有未批准的回填/语义变更，否则禁止启动整套migrate deploy。需要拆分或调整的旧迁移先明确对旧系统后续发版的影响并提交评审。

保留所有旧_prisma_migrations既有行；若最终选用原生共享迁移流程，新增迁移历史仅由原生工具生成并纳入准确生产清单，不伪造历史、不把未执行步骤标为已应用。Hub自有rh_*使用独立账本。若现有canonical序列无法安全采用，先解决双账本与未来重复执行冲突，不先安装再补记；这是发布阻断项，不是可延期收尾。

## 5. 原数据保护和锁策略

### 5.1 执行前

冻结本次目标版本、生产catalog与对象级保护清单；记录端点摘要、库名、DDL身份、PG版本、待建对象、预期缺失对象、before/after结构指纹、源SHA及计划摘要。旧系统发版造成结构变化即重做差额，不只刷新hash。

只读catalog输出不含业务行、密码、函数中潜在敏感常量或完整配置；完整对象定义如确需导出，先脱敏并仅留私有审查目录。本轮不读取临床数据。生产变更前由运维确认现有备份/PITR覆盖及恢复演练证据，不自动创建付费备份资源。

### 5.2 执行约束

每个事务有有限锁等待（建议1–2秒）和语句超时（通常30–60秒，依据演练定值），迁移互斥用可超时/try的advisory锁。事务失败整体回滚，不自动重试，不终止旧会话，不清空连接池。多步骤按清单提交，后步失败保留前步的真实账本，不冒称整包原子。

纯新增空表的索引可在事务内创建；给已有大表加索引先评估，必要时使用独立的CREATE INDEX CONCURRENTLY步骤。该步骤不能放进事务，也不能复用当前事务执行器强行执行；需专门的超时、索引有效性、失败残留和恢复检查。不可用普通CREATE INDEX长时间挡住旧写入。

旧表新增CHECK/FK能使用NOT VALID再VALIDATE时分开审定；NOT VALID不代表可直接发布，新写入也会受约束，校验仍可能耗资源。旧列类型变更、表重写、大范围校验及约束收紧不自动纳入。本轮不做任何全表数据修补。

### 5.3 如何证明原数据未被迁移修改

- SQL评审与执行记录证明首次安装步骤仅限明确DDL/权限清单，不含旧业务表DML、COPY、setval、触发器回填、动态隐藏写入或启动种子；函数体、DO、依赖函数也在审查内，不靠关键词扫描代替评审。
- 在生产等价**合成库**保存旧租户/账号/研究/CRF/知识/任务/额度等受保护旧列的行数及稳定摘要，迁移后对比；新增列按明确规则单独验证，不能把新增列逻辑默认值造成的差异隐藏。
- 旧系统持续运行时，生产全库hash前后不同可能是合法业务写入，不能作为唯一保护证据；无变化也不能证明事务期间从未改过。正式操作的备份/WAL/审计复核由运维在受控环境完成，读取业务行或增加审计设施须纳入生产清单，不把临床内容发送本机/聊天。
- 在同机运行前后记录另外两项目的容器/镜像/端口、只读健康指标；原流程的写验证在合成环境做。生产不可为验证随意创建旧患者/研究/邀请或排空历史任务。

## 6. 角色、函数和共享任务边界

DDL身份与应用身份分离；迁移账号所需CREATE/REFERENCES等逐项列明，不能拿aisci_app跑到权限不足再动态提权。Hub独立应用DB角色为推荐选择，其创建、继承关系及准确表/列/函数权限提交确认后才执行；若选择复用aisci_app，应明确同一DB身份无法提供进程级授权隔离，不能据此减弱租户/Study重验。

RLS、真实父对象/当前authVersion、状态/版本CAS及审计保留。SECURITY DEFINER函数逐项明确owner、search_path、EXECUTE及必要的窄范围提权；普通应用不BYPASSRLS。不存在的本机专用NOLOGIN角色不自动在生产创建；其必要性及函数owner要有依据，严禁照搬合成bootstrap中临时SUPERUSER角色。

既有旧Worker扫描共享表的隔离属于上线门禁。生产范围键未设只是风险线索；先核实际镜像/实现，再用两租户具名合成任务证明旧消费者不认领Hub任务、Hub不认领旧任务，失败/撤权/重启及在途提交规则均有效。未证明前，不在生产新租户创建会话/导入/方法/导出等可被旧Worker扫描的任务。若确需旧服务配置修改或停线，提出准确最小项单独确认；不恢复已暂停的T03–T24完整排空改造。

核心业务在目标环境未执行即标为阻断/未验；不以默认关闭AI、Worker或邮件后health200的方式宣布完整发布。

## 7. 首次安装包组成和阶段顺序

建议后续产物目录`deploy/migrations/researchhub-first-install-aisci-v1/`。本轮不创建伪可执行manifest，不填写猜测的after hash。

| 阶段 | 产物/操作 | 退出门禁 |
| --- | --- | --- |
| P0 基线 | 生产逐对象catalog；源冻结清单；依赖及A–E分类；旧保护清单 | 当前生产指纹和对象前置一致，无未知差额 |
| P1 共享前置 | public缺失新表、批准的新列/索引/约束；D类单列 | 无旧行DML；旧账号/研究/CRF/知识/任务契约通过 |
| P2 Hub首次结构 | schema、表/类型、索引、FK、函数、触发器/RLS及精确ACL，按拓扑步骤 | 函数依赖完整，无测试ID/部署假设可获得实际生产授权 |
| P3 最终业务约束 | 资产、用途、附件、评论、复用等原五步最终语义进入新包 | 每项有来源hash/差异评审，不套原五步的before/after、不伪造旧账本 |
| P4 验证/封存 | plan/check/apply/verify；每步before/after及独立账本；目标/审批摘要 | 未知/半成品/重跑/同名对象漂移均可解释或拒绝 |
| P5 参考与租户初始化 | 仅核验过的省市字典、正式Hub/默认租户绑定和最小运营身份；独立数据清单 | 不复制开发账号、合成CRF/报告/Token；不覆盖旧租户/账号/额度 |
| P6 Hub配置/发布 | 独立后端和路由、SMTP/存储/解析/模型/Worker；精确回退 | 生产DDL/GRANT/配置/发布清单获批，旧消费者隔离有证 |

P1–P4为结构；P5是独立初始化；论文/临床注册/指南等审核内容与全文、向量索引属于独立内容导入批次，不能混在安装DDL里。旧知识库历史资料不自动跨租户开放，内容/AI许可不因共享表而继承。

P2/P3可按依赖进一步细分编号，每步SQL有SHA、锁/时间预算、受保护旧对象清单及失败处理。首次安装直接形成审核后的正式定义，避免先安装合成白名单再临时放宽；不能以缺历史数据为由删来源、许可、审计或当前授权规则。

## 8. 执行器需补的准确门禁

复用现有manifest/hash/前后结构指纹/目标绑定/逐步账本的设计，但不能宣称现执行器无需适配即可用于此次生产：

1. 当前`migration-runner.mjs`生产模式要求非空数据库comment marker摘要。未核当前生产marker，不能自动给旧共享库覆盖COMMENT来凑准入；先只读核验，若不适用，设计Hub自有部署准入记录并列为DDL，而不是删目标守门。
2. 当前生产驱动要求verify-ca/verify-full，旧server实际DSN为sslmode=disable。需独立核实Hub迁移连接的RDS CA/主机名与可用TLS，不改旧连接，也不降低迁移TLS校验求通过。
3. 增加保护对象投影指纹：整体结构hash可因批准的新列变化，但未授权的旧列/约束/策略/owner/ACL必须保持；不能只验证新对象存在。
4. 可恢复状态至少区分未安装、已封存完成、失败事务已回滚、前步完成后步未执行、外部并发漂移；只允许相同源hash/目标/已核账本继续，禁止不明对象IF NOT EXISTS静默跳过。
5. 如P1含CONCURRENTLY索引，单列非事务驱动与有效性验证；无此驱动则阻断对应步骤，不把它塞进当前事务模式。

这些是后续执行器工作项；本轮没有放宽当前生产守门、创建production配置或生成可运行的apply命令。

## 9. 合成演练与验收矩阵

## 10. 生产执行与回退规则

生产前提交一份具名清单：本次catalog/plan摘要、每项DDL/GRANT、执行身份、受影响旧对象、锁窗口、备份恢复证据、演练结果、旧消费者隔离、正式Hub默认租户与初始化清单、Hub路由/镜像及回退方式，由用户单独批准。

DDL失败停在当前步骤；锁等待超限直接退出，不重试、不杀旧事务。已完成步骤保留，修复后重新plan并审批准确摘要。Hub启动或业务验收失败，仅关闭/回退Hub及其新消费者，保留新增结构和已产生的合法行；不直接执行DROP或旧rollback.sql，不覆盖整个aisci库，否则会丢失旧系统期间正常写入。确需灾难恢复时按已验证PITR/选择性恢复流程由运维另行决策，不能把整库恢复当普通发版回滚。
