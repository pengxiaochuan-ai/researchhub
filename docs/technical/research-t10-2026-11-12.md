# T10 正式任务接口与固定来源

正式入口 `/pages/s08/?formalTasks=1&studyId=...`，可附 taskId；与旧任务及其他正式模式互斥。服务复用旧 StudyOperations 原子命令，Study resolver 决定真实产品 scope，不使用旧夹具任务/账号数量限制。

`/api/research-studies/:id/tasks` 提供 GET 列表/POST创建；GET `context`、`participants`、`options`、`sources/:kind/:sourceId`、`receipts/:requestKey` 和 `:taskId`。PATCH `:taskId` 编辑；POST `:taskId/assignments|transitions|reviews|reminders`；PUT `:taskId/context`。成员/任务分页1–20，来源候选1–100。游标绑定身份及作用域，重启默认失效，多进程须注入稳定签名密钥。

formal_visit 与 formal_response_ref 在共同内部命令中重新核验完整父链、当前授权及同意；固定修订回链同时携带 responseId、assignmentId、revisionNo、contentHash 和 visitId。普通旧接口不能伪装正式来源。安全 DTO 只显示假名编号、访视名、表单名与修订号，失权来源不返回旧摘要及导航。

持久回执仍 `{operationId,taskId,version}`；正式接口对命令/同键重放/GET 原回执追加 `receipt:{requestKey,action:'task.'+action,targetId:taskId,studyId}`。前端严格核验后重读当前对象，404继续未知，不自动重新 POST。业务正文只留本页内存十五分钟，sessionStorage仅最小身份/对象/动作/key标记。变更来源和 task 的锁序验证见真实两连接PG证据。

context kind CHECK 仅在保护合成库扩展固定修订类型；旧记录、RLS/trigger/policy/Prisma history指纹保留，rollback未执行。生产仍待独立配置部署和验收。完整本机证据见 [T10测试](../testing/research-t10-2026-11-12.md)。
