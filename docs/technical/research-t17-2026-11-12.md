## 1. 复用边界与持久对象

这里的复用是复用现有模型、源码 helper、存储和事务服务，再适配正式研究来源；不是直接调用旧科研工作台的远程 API。旧 `analysis_report` 来源契约不能表达本次完整 AnalysisBasis，因此正式报告走独立受控服务，不借旧通用产物入口绕过当前依据校验。

服务只接受 completed、人工confirmed且当前可用的描述统计Run（descriptive-v1、t19-1、`llm:false`）。真实MethodReview须有确认与非空说明。模板核对固定输出形状及逐路径numericEvidence后逐值复制，不由LLM计算统计、概率、阈值或补值。

## 3. API与权限

当前本机路由基址为 `/api/research-studies/:studyId/analysis`。控制器只接受约定字段；业务写入均要求真实身份和requestKey，GET不启动任务或重排队列。

| 方法与相对路径 | 输入/职责 |
| --- | --- |
| GET `/reports` | 当前权限下的报告列表；上限50，逐项当前检查；阻断项只给受限元数据 |
| POST `/reports` | `{requestKey,runId,title?}`，从固定已确认Run创建in_review报告 |
| GET `/reports/:artifactId` | 当前可用固定详情、正文、来源/审核及文件摘要 |
| POST `/reports/:artifactId/reviews` | `{requestKey,versionNo:1,decision,reason}`；decision为approved或changes_requested |
| POST `/reports/:artifactId/releases` | `{requestKey,versionNo:1,reason}`；已批准固定当前版才可released |
| POST `/reports/:artifactId/exports` | `{requestKey,versionNo:1,format}`；专用队列与原操作回执 |
| GET `/report-receipts/:requestKey` | query `action`与`targetId`精确匹配同actor/Study原结果，四动作分别为analysis.report.create/review/release/export |
| GET `/report-exports/:jobId` | 当前授权与来源下读取任务状态 |
| GET `/report-exports/:jobId/file` | 当前授权、实际私有字节和SHA核验后下载 |
| POST `/report-exports/resume` | 显式恢复入口，空body；最多处理原用户20个queued，不由GET或页面读取自动触发 |

状态路径为 `in_review → approved → released`，人工审阅可要求修改；审核不会自动发布，发布不会自动公开资产。来源更正后需要新Run和新固定报告，不能覆盖旧v1。

list/read提供 `capabilities:{canCreate,canReview,canRelease,canExport}`，来自当前DB身份对应的 `artifact.create/review/release/export`，不从前端角色名猜测。只有明确 `REPORT_FORBIDDEN`映射false，撤销身份等其他错误继续拒绝。list仍须有artifact.read，详情还须满足Study数据权和当前来源；权限位不保证该报告状态可执行。

`docxExportStatus:'available'|'unavailable'`独立表示当前storage可用、允许该tenant且worker kind `research-artifact-export`已启用。UI仍须结合fresh详情、状态、来源与服务状态收敛动作；写入口全部重验。来源阻断的列表项不包含正文、原值或完整来源内容。

操作回执与同键重放也重验对应动作当前权限。只有artifact.read而已失去review/release等动作权，不能读取该动作回执。receipt不返回原始答案或存储凭证；未知404仍是未知，不能据此安全重发。

真实D6验证的权限差异须保留：owner当前可读列表且canCreate=true，但缺Study数据分析权，详情由外层拒绝 `RESEARCH_FORBIDDEN`；真正未加入者返回404 `RESEARCH_NOT_FOUND`。不能把身份昵称当成权限契约。

## 4. 当前来源、锁顺序与完整性

所有关键读取和写入都进入当前Study授权事务，使用真实账号/authVersion及scope。T15 `assertCurrent`重验批准计划、计划撤销、protocol、主体同意/用途、质量状态、精确答卷ref及当前manifest，不能仅凭已存snapshot存在就允许新用。

锁顺序沿来源向产物推进：Study/计划/protocol/排序subject等T15锁 → 新模板所需固定FormVersion SHARE → Run SHARE → Artifact UPDATE → Job/claim。不得持有Artifact/Job后反向取得来源锁。新旧报告list缓存也区分Run与模板模式，避免交叉重用。

报告当前可用检查不仅比较摘要，还从可信来源重建并比较 `contentMd`、`contentHash`、完整 `contentBlocks`、`sourceSnapshotHash`及两项来源snapshot/hash。数值证据必须与已确认Run精确一致。读取/审核/发布/导出各阶段都执行当前检查；一个来源失效的报告在列表中保留blocked元数据，不能继续交付旧正文或旧文件。

源数据、计划、同意或质量改变后保留历史固定记录，并阻断当前新用。保护库专项已有失效反例；主三例实际更正后的HTTP、S10及旧导出阻断仍待后续串行验收，不由静态源码或D6正常路径推断完成。

## 5. 可信展示封套与历史兼容

新报告使用 `formal-report-presentation-v1`，同时封存在 `contentBlocks[0].presentation`及 `data_snapshot.snapshot.presentation`，参与完整来源摘要。变量集合与当前已批准manifest完全一致，每项为：

`{key, formVersionId, fieldKey, label, valueType, unit, formDefinitionHash}`。

服务从同scope真实已发布/锁定FormVersion按现行normalizeFormSchema导出标签、类型和单位，以 `{schema, scoring: scoring ?? null}`的canonicalManifestHash核对每条manifest cell。formVersion/field/hash及类型/单位映射不符即拒绝；客户端和LLM不能提供标签或猜单位，未声明单位保留null。

当前检查时重新从可信固定表单导出封套，而非只验证已存label彼此自洽。因此同时篡改正文、封套、来源与摘要也不能绕过真实schema。封套存在但未知、非法、缺项时拒绝，不降级旧模板。

无封套历史报告继续原三参数builder，原正文、block、两项来源和hash逐字重建，不补标签或改旧记录。旧完整builder golden摘要为 `35ec0b62c2bfbb6188e7bb23077db3e16b610b1fbb53c0a926862f47d877a8ce`；真实旧DOCX原字节保持的HTTP证据见测试记录。

新正文主区呈现变量名称、单位、指标和原值。alias/key、field/type/form版本/schema摘要、每条固定JSON路径、Run/算子/快照/basis摘要完整保留在复核附录。重复标签允许，附录仍可区分变量。`< > |`、反引号和`&`安全转义后单次解码，不能静默删除科学符号。null呈现不可估计/未声明等明确含义，不能变为0。

## 6. 新Word分支与数值边界

新helper只适用于 `analysis_report`、首个 `formal_analysis` block且带合法新presentation标记的报告；其他产物及无标记旧正式报告保留旧paragraph renderer。输入仍是已重建核验的固定contentMd/contentBlocks，受控两列表只逐项复制，不重新计算统计。

新DOCX显式A4（11906×16838 DXA）、边距1440；表总宽9026，两列各4513且单元格宽一致，重复表头、不拆单行。中文使用Hiragino Sans GB并设置EastAsia字体；复用现有标题、页眉和页脚，无新依赖。D6实际文件为6个真Word表格，所有主表单元格严格等于持久Run的 `String(value)`。

测试发现的既有序列化边界已如实保留：test-only JS literal `2.8284271247461903`在同fixture的Prisma create/delegate及SQL `jsonb::text`均已为`2.82842712474619`，发生在报告builder之前。本次不改统计、全局Prisma或已存结果，不在renderer补位或舍入。报告严格复制实际持久确认Run；Worker与独立Python基准的数值容差属于独立验收契约。

## 7. 导出、存储与未知结果恢复

导出创建先在事务中固化queued任务、原actor/authVersion、审计及原回执；提交后controller显式调用实际 `processExport`。POST返回原queued结果，随后GET读取真实ready，不能把返回queued描述为文件已生成。

worker只claim一次，保留原请求者身份，不允许撤权后换新管理员代跑。dequeue、存储前和最终CAS阶段分别重验当前权限/依据和live claim。render与存储在事务外；随机私有key写入后通过真实getBuffer读回核SHA，最终ready/file/audit随CAS原子发布。旧generic worker排除正式前缀，不能竞争处理该任务。

下载经过当前检查、MinIO实际字节的长度/SHA核对、交付前再次当前检查，返回受控二进制及MIME、编码文件名、Content-Length、nosniff、X-File-SHA256；没有绕过当前权限的直链。未知提交保留可能已提交的私有对象供核对，不贸然删除，也不以新键重复执行；该孤儿窗口属于需对账边界。

显式resume最多处理原用户20个queued；过期rendering只标failed/interrupted，不自动重新render或requeue。GET列表、任务、文件和回执不启动恢复。D6 harness在POST前记录原键，未知只GET原回执并停线，不把404当重试许可。
