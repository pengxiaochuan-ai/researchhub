# P002 UI 整改与验收记录

日期：2026-10-19。状态：本轮代码整改已实施，本机浏览器已验证；200% 实际缩放及跨浏览器仍待独立复核，不声称完整 WCAG 认证或生产上线。

依据：[UI 审查报告](../ui/audits/2026-10-19-p002/审查报告.md)、[门户排版规范](../ui/portal-typography-v1.0.md)。本轮用户明确要求按审查报告实施代码整改。

## 范围与实施顺序

1. 收敛 P002 独立字体规则：主要正文桌面 18px / 手机 16px；AI 说明、重要限制不低于 14px；输入、导航、按钮 16px。
2. 容器随内容增长；窄屏 AI 工具单列、长标题换行、手机人物卡减少无效高度，保留七区结构与源图。
3. 修正裁切源图加载：有限源图立即加载，显式源尺寸，人物图提供加载/失败状态，不改变裁切坐标。
4. “研究领域”改为“适用人群”，首屏对应 CTA 改为“了解参与方式”；锚点及公开路由不变。
5. 单元、构建、实际 Playwright 浏览器交互与截图；覆盖桌面、手机、320px 内部溢出及关联页面隔离。

本轮没有改变工作台、管理员、后端接口、模型或权限；P002 是独立门户，其他页面仅做共享样式隔离回归。不把前端演示当成真实认证/业务上线。

## 验收

### 代码与自动检查

- `node --test tests/*.test.mjs`：17/17 通过（10 项现有契约、7 项新增图片生命周期测试）；新增测试先失败后通过，覆盖正常/错误、已缓存成功/失败、同步事件、装饰图无状态节点。
- `pnpm run build`：退出 0，Vite 构建成功。仍有原有大于 500kB chunk 警告；本轮未扩展到全站拆包。
- `git diff --check`：通过。未增加运行依赖、远程字体或改动图片二进制文件。
- 图片加载集成入口：`/tests/fixtures/p002-image-states.html`。调用生产 `loadCropImage` 与生产样式，真实有效源图进入 `loaded`、错误地址进入 `error`，错误文字可见，`aria-busy=false`。开发服务器会将不存在的地址回退为 HTTP 200 HTML，触发图片解码失败；这是错误资源实测，不冒称真实 HTTP 404 或断网测试。

### 仍需独立验收的边界

- 当前内置浏览器没有暴露实际缩放设置，尝试平台缩放快捷键后 CSS 视口未变化，不能证明 200%。本轮已改用 rem 与内容自适应，但未把 320px 重排当作 200% 缩放通过。后续应在桌面 Chrome / Safari 中设置 200% 再复核。
- 原始位图的小字没有重绘；关键节点语义依靠常显 HTML 说明。图示重制、完整屏幕阅读器及全页图片/渐变逐像素对比度认证不在本轮通过项中。
- 人物区采用有限七个共享源图立即加载，保证直接跳转可呈现；不声称首屏流量已优化。慢网资源预算需另行性能专项。
- 本轮没有认证、管理员或后端能力改造；没有生产部署，也未执行 git 提交/推送。
