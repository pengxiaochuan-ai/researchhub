## 建议的最小修改顺序（待用户批准）

| 优先级 | 修改 | 用户价值与边界 |
| --- | --- | --- |
| P1 | 利用已保存JATS恢复章节/段落、参考文献关系及Fig/Table定位；增加当前文章内目录/锚点 | 从“存着一段文字”变成能核对的文章；不以AI改写、补造或另抓全文替代。图片仍按原比例展示。 |
| P1 | 队列切换/下一项后使新文章标题和当前状态进入可见范围，并保持左侧队列位置 | 不从上一对象的低位开始看新对象；焦点不能藏在视口外。 |
| P1 | 完整性按摘要、正文、表格、图片、作者附录、PDF分别说明有无/缺失影响；原始XML/TXT归技术追溯 | 管理员不用理解文件数和格式。原文无此对象与采集失败必须区分，不承诺3/4代表75%内容。无需新增审核条件。 |
| P2 | 阅读详情中保留紧凑的决定/继续入口或底部重复动作 | 读完不必长距离回顶部；限定来源子功能，不改治理总览。与“当前对象”绑定，不能遮住正文/键盘焦点。 |
| P2 | 未决定时明确为“跳过，查看下一篇”，决定后为“下一篇待审核”；始终说明是否已保存 | 不把浏览下一篇当成完成审核，不加重复确认弹窗。 |
| P2 | 数量统一为当前筛选口径，或明确“全来源待处理34／PMC共20，当前PMC待审17” | 区分总数、待处理数和筛选数，避免误读。 |
| P2 | 补真实表头、caption和单元格关联，保留14/22表格与16/28连续阅读 | 改善语义和键盘/辅助技术使用，不靠一律放大字体解决结构问题。 |
| 后续 | 审核子页说明合并、空表格改“原文无表格”、长队列标题适度收束且可完整展开 | 增加有效阅读面积，但不更换页面框架，不未经确认裁掉题名。 |

“暂不放行”包含未决定与已明确拒绝的潜在语义差异，本轮不据此新增状态或改变审核数据模型；如需区分，另提最小提案。
