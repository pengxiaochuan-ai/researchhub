## 失败、评审与限制

1. 初次fixture把AuditLog字段写成detail而非meta，旧Client拒绝、全事务回滚；核对实际模型后只初始化成功的新具名夹具。
2. scoped JSON parser导致Nest不装默认parser，原登录400反例复现后显式保留100KiB默认parser，WP02先过16KiB；原服务不改。
3. 首次同标签fragment打开邮件没切验证阶段；保留`browser/failure.json`，补hash监听后主链通过。
4. 独立评审无Critical、3 Important。演示标记、迟到响应、S11移动Shell逐项核实并RED→GREEN修补，完整[评审关闭记录](../planning/account-invitation-2026-10-23/review.md)。评审未二次签认，最终修补验证由主实现完成；不以单元全绿替代真实业务/视觉检查。
5. 浏览器主链无未捕获pageerror；401/403/404等预期拒绝可产生浏览器网络错误日志，不宣称所有console零错误。真实外发、跨设备邮件送达、生产反代/CSRF/域名配置、容量/投递运维、SSO、L2/L3及专业用户最终效果未验收。
