# P002 门户 UI 与字号审查

日期：2026-10-19。代码基线：`190f509`。地址：`http://localhost:5173/pages/p002/`。

状态：本文保留修改前的审查快照；用户确认后已实施代码整改，结果与剩余验收边界见 [整改记录](../../../testing/p002-ui-remediation-2026-10-19.md)。下文“当前 / 待整改 / 未实施”均指审查时点，不代表修改后的页面。

## 结论

保留蓝紫科研视觉、七区顺序、主要素材和桌面构图。当前主要矛盾是辅助信息过小与响应式容器，不是所有标题都偏小。1440px 下 Hero 为 43.2px，常规 H2 约 40px，已经有基本标题层级；流程标签和 AI 说明只有 12px，搜索框与人群辅助说明为 11px。390px 下 AI 工具说明和人群辅助说明最低 9px，重要责任说明 10px，优先整改。

320px 下 AI 工具内部超出可视区，被区块隐藏；根页面没有横向滚动条仍不能通过重排验收。人物卡首次进入出现空白，后续复查图片加载成功，问题应归类为加载呈现与占位不足，不能写成永久缺图。

## 优先级与整改清单

P1 表示明显影响阅读或核心内容可见，P2 表示层级、一致性或反馈问题；不表示本轮已修复。

### P1：辅助文字及重要说明过小

证据：步骤 1、2、6、7 的截图与字号表。手机 AI 区域需要靠近屏幕才能辨读；桌面大屏留白较多，AI 条依然维持接近脚注的字号。

调整：将 AI 工具说明、责任说明、流程标签升至 14px / 22；输入与主要操作采用 16px。允许 AI 条变高或改列数，不只改变字号。普通正文以桌面 18px、手机 16px 为基准；12px 仅留给短图注与日期等低优先级信息。

### P1：320px 内部裁切被隐藏

证据：[窄屏截图](16-narrow-flow-overflow.jpg)。CSS 视口 320px，根 clientWidth/scrollWidth 都为 305px（含滚动条差异）；`#process` 的 scrollWidth 却为 328px。AI 条内部宽 259px、scrollWidth 305px；第二列卡片右缘到 x=328，超过可视右缘 305px。`overflow: hidden` 令根滚动扫描看似正常。

调整：AI 工具网格按内容改为单列或可收缩列；处理子项 min-width、nowrap 及内边距，同时保持 14px 说明。验收必须检查容器内部文字，而非只检查根宽度。此问题影响 WCAG 重排相关目标，但本轮不是完整合规认证。

### P2：同级标题和正文被按区块分别缩放

证据：步骤 2–6。人群第五张卡标题约 17px，其他四张约 24px；原始面板宽度 1213px 的加载后复查还可见末卡长标题裁切。共同体小标题约 17px，与 16px 正文差距很小。手机主 H1 28px，而普通 H2 32px、共同体 37px、CTA 39px。页面正文存在 16/17/18/20/21px 多套规则。

调整：建立角色字号而非逐块缩放；长标题同级同号并自然换行。重点 CTA 可以强调，但手机常规 H2 应与 Hero 建立稳定层级。保留有用途的导语/正文差别，不把所有文字改成同一个尺寸。

### P2：图片首次进入的加载状态不清楚

证据：步骤 6 在 1440px 锚点进入时，五张人物卡为空白深蓝底，彼时五张 `img.naturalWidth=0`、`complete=false`。原始面板 1213px 下连续向下滚动五屏后，五张变为 `naturalWidth=1586`、`complete=true`，人物图可见；本地 `reference-6.png` 返回 HTTP 200，1,937,594 bytes。两次进入的路径与宽度不同，因此不能单凭这组对照归因于网络延迟或某一 CSS 规则。

调整：检查裁切图配合原生懒加载的触发与加载时序，明确占位及失败反馈；保持卡片空间稳定。不能据早期截图断言资源永久丢失，也不能凭最终加载成功忽略首次体验。未通过控制变量实验确认唯一根因，未测冷缓存加载耗时。

### P2：图示含位图文字，不能靠 CSS 放大解决

证据：步骤 1、3、4；首屏飞轮和共同体网络均有嵌入图片的说明文字，手机图示缩小后比旁边 HTML 文本更难读。DOM 字号扫描无法测出这些像素文字的字号。

调整：保持现有图示与素材，依靠常驻 HTML 详情提供完整含义；后续取得分层素材时可将关键标签分离为真实文字。不能以整体放大图示破坏标题及点击命中区域。

### P2：入口名称与落点不一致

证据：首屏“探索研究领域”和导航“研究领域”均指向 `#audience`，实际落点是临床医生、科研人员等“适合这样的你”，没有展示疾病或研究方向。

调整：在后续页面实施时统一入口与落点语义，例如改为“找到适合你的参与方式”；若仍称“研究领域”，则应进入已有且符合公开访问规则的领域内容。此次未改变文案、路由或信息架构。

### P2：页面长度与重点分配

证据：步骤 2、6 与手机截图。390px 文档总高约 13,709px；手机人物卡高 490px，五张连续展示占据较长滚动。桌面 1366×768 的首区内容高约 900px，不应为压成一屏继续缩字。

调整：保留七区顺序，让内容高度自然增长；手机适当缩短人物图区域，压缩装饰性留白。五步说明与价值说明用信息密度控制长度，不省略必要说明。

## UI 文档问题与本次修订

| 原文档问题 | 影响 | 本次处理 |
| --- | --- | --- |
| Foundation / Shell 适用范围容易被读成全站 | 把门户误套 14px 正文、12px 辅助文字和固定侧栏 | 三份 UI 工作区文档补充门户边界，Frozen 数值保持原值 |
| 没有完整门户角色字号和手机下限 | 各媒体查询把 AI 说明缩到 9–10px | 新增 `portal-typography-v1.0.md`，明确后续目标与尚未落地状态 |
| Layout 将筛选标签指定为 tertiary | `#8B98AC` 白底约 2.9228:1，普通文字不足 4.5:1 | 需要阅读的标签改为文档要求用既有 secondary；不改 Token 数值 |
| 验收仍固定“19 页均有 Topbar + Sidebar” | 现有清单 50 页，且门户不应具有工作区侧栏 | 按 manifest 与页面职责分型，补充内部溢出、图片、对比度与缩放检查 |
| 门户方案只列桌面固定字号并笼统保留首页特例 | 可被误读为难读字号也不得调整 | 方案第 7 节链接新排版规范，保留构图同时允许可读性修正 |

`--text-secondary: #5F6F89` 对白底约 5.0951:1；门户正文 `#52638F` 对 `#F4FAFF` 约 5.6396:1。前者说明既有 Token 中已有可用选择，后者说明“看起来偏小”不能一概归因于文字颜色。透明层、图片、深底渐变的实际对比度仍需逐项实测。

数值由确定性的 sRGB 相对亮度公式计算。参考 [W3C 对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[文字放大](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)、[重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。本项目 16/18px 等字号建议属于阅读体验规则，不冒称 WCAG 统一最小字号。
