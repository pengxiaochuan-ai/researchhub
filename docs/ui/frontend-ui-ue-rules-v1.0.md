# 前端UI/UE实施与验收规则 V1.1

## 2026-11-07补充：一看就懂，而不是先学习产品

面向用户的页面优先降低操作负担和理解成本：用户应直接看懂“当前是什么、能做什么、做完会怎样”。只呈现完成任务必要的字段/选择；合理默认交给系统，不把内部分类、技术配置、完整后台能力转嫁给用户。无实际必要的辅助模块直接不展示，不用堆说明补救复杂流程。保留必要责任、权限、来源、审核、审计和风险信息，异常恢复才按需展开细节。验收不只检查功能存在，也检查用户能否不依赖讲解找到主动作。规则不授权改变其他页已确认布局。

## 2026-11-06补充：确认统一站内弹窗

业务确认使用共享ConfirmDialog，不新增window.confirm/alert/prompt。既有页面随功能开发逐页替换，不进行未经授权的全站改版；保持原确认条件和布局，说明对象与影响，取消/Esc保输入，支持键盘约束和焦点返回，不增加多余确认。关闭标签/刷新时浏览器强制beforeunload保护保留，不能用无法持续存在的站内组件替代文档销毁确认。当前G02范围及验证见[规格](../product/team-page-confirmations-2026-11-06.md)。

## 2026-11-06补充：页面不保留开发说明

用户明确：“页面中不要保留开发说明，记住这个规则。现在页面上有很多开发说明。”适用于研究者、管理员和访客业务页面。

- 不展示开发进度、接口/数据库接线、实现方式、测试验证、本轮开发授权/预算、“布局还原不新增权限”等研发叙述；移入研发文档、日志或专用调试工具。不得把后端实现和验收记录当用户帮助。
- 只保留用户完成当前任务所需的信息：当前对象、实际状态、可执行动作及失败后的下一步。未具备的能力用简短“暂不可用”等真实状态表达，不用接线过程解释，也不能伪装可用或成功。
- 权限限制、来源/数据范围、审核责任、AI风险与演示/合成数据性质不是开发说明，仍须在必要位置清楚呈现；用用户语言集中表达，不反复堆叠。内部ID/版本/回执等仅在确有恢复需要时按需查看。
- 新页面和每次修改都检查是否残留研发文案；旧页面逐页清理，保持已确认布局和业务语义，完成真实浏览器验证。规则生效不等于全站遗留已清空，本次仅沉淀规则，未批量改运行页面。

## 2026-11-05补充：审核不要机械重复确认

已在原内容旁明确展示范围与必填责任信息时，常规审核的主动作就是明确提交，不再复制整份内容让用户重复确认。首次公开、扩大可见范围或其他明确新增风险，才保留一次简短影响确认；不能因此省略权限、依据、责任、版本和审计。缺项原位提示，保存后保留审核输入，不要求用户管理内部参数。用户已批准并在G02当前团队页实施；其他页面仍须逐页说明和确认布局差异。

日期：2026-10-20。适用于ResearchHub后续前端功能实施、旧功能复用和页面整改。用户目标：页面风格不漂移、交互一致、文字可读。本文是既有规范的执行入口，不是全站重设计，也不代表现有50页已通过验收。

## 2. 每个模块开发前必须写UI/UE约定

2026-11-02用户明确：页面布局与交互必须依据真实用户的实际操作路径，不随意改变、不靠猜测。规格先写明角色、入口、如何找到对象、核对什么、主要动作、结果反馈、下一项/返回及失败恢复；依据为真实页面观察、当前数据/API与用户确认，不把实现字段或技术步骤直接当产品流程。浏览器验收须走完整任务路径；入口可达、API成功或截图好看都不能代替“用户能完成当前任务”。任何未经用户验证的体验判断标为待评审，不推断用户满意。

模块规格增加“UI/UE验收”段，至少列明：

1. 页面编号、门户/工作区类型、参考母版/已确认页面、基准视口。
2. 科研侧、管理员侧及列表/详情/新建/编辑的受影响入口；不适用项写明理由。
3. 复用组件、字号角色、主操作及其权限条件，不重新定义平台导航。
4. 加载、空态、失败、无权限、长文本、重复操作、未保存离开的交互。
5. 实际服务/演示的边界，以及对应截图、录屏和自动化用例。

缺少的业务决定写待确认，不能由页面开发者擅自改变权限、保存方式或审批流程。不存在的公共组件应在该任务中确认最小共享实现，不能声称已有完整组件库。

## 3. 字体与排版：按信息角色，不按剩余空间缩字

### 2026-11-05补充：操作负担是实施与验收项

从“进入→找对象→填写/选择→确认→反馈→继续/恢复”逐步检查：去掉重复说明和重复填写；能直接选择的搜索结果不叠加“搜索→下拉→添加”；常规区一个主要动作，草稿等为次要动作。内部版本/哈希/请求键不作为用户日常步骤，异常恢复才显示必要对照。说明分层，每区一句必要说明、其余按需展开；关键风险、范围与责任不得折叠隐藏。低风险操作不反复确认，审核/发布等集中一次明确确认，不减少服务端鉴权、来源核验、版本防重和审计。错误同时给出原因、工作保留状态和下一步。评审需列前后动作数/重复字段及真实任务证据，不凭按钮减少数代签体验提升。本轮样板为G02团队维护，不自动改其他页布局。

工作区使用Foundation Token；Reading为[ADR-0004](../decisions/0004-scoped-reading-typography.md)受控新增角色，不修改旧Token值：

| 信息角色 | 字号/行高（CSS px） | 实施要求 |
| --- | --- | --- |
| 页面主标题 | 24/34，600 | H1；强化概览可按Foundation使用Display 28/40，不全页滥用 |
| 区块标题 | 20/28，600 | 同级同尺寸、同字重 |
| 卡片标题 | 16/24，600 | 长标题可折行，不能单独缩成更小字号 |
| 操作正文、表单输入、主要表格内容 | 14/22，400 | 密集操作/短信息；不得使用Caption替代 |
| 论文、报告、AI长段解读的连续阅读正文 | 16/28，400 | 显式Reading角色；不是全局p/输入/表格覆盖，样板行宽上限48rem（默认768px） |
| 按钮、Tab、筛选当前值 | 14/22，500 | 空间不足调整布局，不压成小字 |
| 短辅助说明 | 13/20，400 | 重要错误、风险、AI限制及操作指导不得降为脚注 |
| 时间、版本、短标签等低优先级元数据 | 12/18，400或500 | 仅作短元数据；12px是下限，不是正文默认 |

门户不套用上述密集工作区字号：主要正文桌面/手机均16px，导航/输入/按钮16px，短辅助14px；标题、行高及重点区块以[门户字号表](portal-typography-v1.0.md)为准。其他门户不能仅凭P002通过而视为达标。

- 工作区引用现有`--text-*-size/line`变量；门户用其作用域内角色变量。继承旧固定值时按角色收敛，不新增散落的任意字号或全局覆盖。
- 不用`transform: scale()`、容器zoom或超小字号“缩到放得下”；不单凭缩放截图判断字号。
- 中文标题/长机构名优先折行、增加内容高度、降低列数；Tab/短筛选词保持完整，溢出有可操作的滚动/换行方案。次要列表摘要、长标题、来源标识可缩略展示，但必须有键盘与点击均可达的全文/详情和真实复制路径，不能只靠hover或title。输入框保留完整值并可选择/复制；关键错误、确认对象、主要数值及单位、责任说明必须在任务决策处完整呈现，不能藏在缩略文本后。
- 字号、行高、字重、容器和对比度一起核验；连续长文不能用12/13px堆叠。Reading正文随内容增高，桌面避免无限拉长单行；辅助栏摘要用14/22，不作为第二个全文区。只加大字号而不限制宽屏行长，不算阅读整改完成。
- 标题视觉等级与HTML语义分别正确；一页一个主要h1，其他标题按结构嵌套。字体沿用当前中文/拉丁字体栈，不自行引入远程字体。
- 普通文字对比度目标至少4.5:1，大字至少3:1；按实际合成背景测量。`--text-tertiary`白底约2.92:1，不作为可读说明文字默认色；状态同时提供文本/图标，不只靠颜色。

## 4. 视觉和组件一致性

- 公共Shell由统一模块挂载；业务页不得复制或覆盖Topbar、侧栏、面包屑、页头、上下文导航和用户区域。真实身份由认证状态适配，不能沿用演示人物冒充当前用户。
- 相同语义的按钮、输入、筛选、表格、分页、卡片、Badge、弹窗、抽屉、通知使用相同组件或共享样式；同一种操作的名称、图标、位置和禁用解释一致。
- 工作区间距沿用4/8/12/16/24/32/48，正文边距24、栏距16；颜色/圆角/阴影按Token。门户留白及布局遵循母版，不机械复制工作区尺寸。
- 同一操作区突出一个主要动作；不让“保存”“提交审阅”“AI生成”看起来是同一行为。危险动作使用明确文案和确认，不把选中态/正常指标涂成危险色。
- 图标沿用已有Lucide/SVG体系，图标按钮有可访问名称；同义图标不混用emoji或其他随机风格。
- 新增样式限于组件/页面作用域，不能用无作用域的body、button、input、h1或main选择器改动其他页；公共样式变更须列出全部消费者。

共享`Button`的最小运行契约：默认`type="button"`，表单提交显式`submit`；原生属性、可访问名称及描述透传。`disabled`和受控`loading`同时阻止鼠标/键盘重复触发；忙碌态有可见反馈和`aria-busy`，保留原操作名称。成功/失败由调用者依据实际操作恢复状态，组件不自造成功、不代替服务端幂等；禁用原因放在相邻可读说明，不能只用禁用按钮的hover提示。同步本机操作不添加假等待或假进度。

| 编号/场景 | 统一交互要求 | 最小反例验收 |
| --- | --- | --- |
| UE01 导航与返回 | 保留合法Hub/Study/对象上下文，详情返回保留适用筛选/位置；站外返回地址拒绝；未知对象有明确状态 | 改URL/未知ID不能进入固定示例或其他研究 |
| UE02 加载与刷新 | 请求中有反馈、占位与稳定布局；区分首次加载和已有数据刷新，防止旧请求覆盖新筛选结果 | 慢网/乱序/重复点击后对象、结果与生效条件一致 |
| UE03 空态与错误 | 区分无记录、筛选无结果、无权限、服务失败、未配置；提供对应下一步，不能统一显示“暂无数据” | 403/超时不展示零结果或假成功；提示不泄露无权资源内容 |
| UE04 表单与校验 | 持续可见label、必填及格式说明；提交尝试或字段触碰后才报对应错误，首次打开不满屏报错；失败聚焦首错并关联错误说明，保留允许保留的输入 | 草稿与进入下一步分开校验；重要错误14/22，不只用红色或placeholder；密码/token不落本机草稿/日志 |
| UE05 提交与保存 | 异步提交防重复；成功以真实存储结果为准；区分未保存/保存中/已保存/失败，标明本机或服务端；只有真实编辑差异才保护离开，保存成功立即解除 | 网络/存储失败不提示已保存；版本冲突不覆盖；同步保存不假造保存中；未有自动保存不显示自动保存；改回已保存值不误拦离开 |
| UE06 筛选与分页 | 同页遵循已确认的立即生效或“应用”模式；配置条件与生效条件明确；清空/分页/选中范围可解释 | E01继续先应用后生效；批量操作不能误扩为全部筛选结果 |
| UE07 弹窗与抽屉 | 打开时进入合理焦点，模态焦点不逃逸，关闭回到触发点；Esc/遮罩/取消策略一致且不丢未保存内容 | 键盘可完成/退出；关闭抽屉不等于后台任务已取消 |
| UE08 危险/受限动作 | 按不可逆性/共享影响分级：收藏、展开等可逆低风险动作即时反馈，不反复确认；删除、锁定解锁、对外发布共享说明具体对象、范围和后果；无权限解释路径 | 仅服务确实支持撤销时显示撤销；UI隐藏不代替后端拒绝；重试不重复发布/邀请；不把所有动作都做确认弹窗 |
| UE09 AI任务 | 明示输入对象、授权范围、真实阶段、来源及草稿性质；完成、失败、取消、待人工确认可区分；采纳进入业务对象需确认 | 工具未执行不显示完成；不伪造进度百分比；切对象不串用结果；重试保留run/版本来源 |
| UE10 数据与提示 | 表格单位/缺失/版本可读，缺失不显示0；普通成功用polite status不抢焦点，重要错误常驻alert；长文本不挡操作；复制仅在剪贴板成功后反馈 | 复制拒绝提供全文手动复制，重试不混入错误提示；慢复制不得把旧页签结果标成新页签；图表和评级不能仅靠颜色 |

AI角色、人工确认和四层证据继续遵守[AI专项](../planning/phase1-review-2026-10-19/ai-special-design.md)，不因统一UI增加未经确认的诊断、审批或数值生成能力。公共账号、权限及服务未接入时显示实际限制，不用Demo成功覆盖正式流程失败。

固定示例必须在相关结果与复制产物中保留演示/未核验标识；展开既有文本叫“展开示例摘要”，不能叫“已生成”。未接入导出、原文或AI时解释未接入状态，不能使用空按钮制造可用错觉。E02本轮不改医学数值、不核验示例论文，不构成科研证据或AI能力交付。

## 6. 响应式、键盘和可读性

- 工作区以1440×900为主，补1366×768和1920×1200；主要功能在实际200%浏览器缩放下检查。门户另测390×844与320px窄屏。面向手机的具体入口按其职责验收，未测不能声称全站手机适配。
- 宽表格可在有提示的表格容器内横向滚动；不能通过缩字、裁列、隐藏操作来适配。固定栏/浮层不遮焦点、错误和主要操作；多栏/长内容滚动规则沿用Layout。
- Tab可到达全部交互，焦点可见；Enter/Space行为符合控件语义，不把输入回车默认绑定不可逆操作。不可仅靠hover、拖拽或颜色传递必要信息。
- 门户触控目标按现有44×44px项目建议核验；密集工作区图标增加可点击区域并检查间距，不仅放大图形。不把项目目标冒称统一法规尺寸。
- 图片预留空间，失败可解释；截图前确认懒加载已呈现。持续动效支持减少动态效果；流式输出不强制抢滚动、自动覆盖研究者正在编辑的文字。
- 记录实际CSS视口、设备像素比、浏览器缩放与computed字号/行高；改变视口不能冒充完成200%缩放验收。自动扫描不覆盖位图文字、全部对比度或真实任务可用性，人工核对不能省略。
- 密集表格/采集区和长文阅读区分别评价，不以“所有页面统一16px”验收。固定Shell沿用母版；当前任务未授权全局重构时，将Shell缩放缺陷登记而非自行改全站导航。
- 真实领域页 H05/H01 的手机入口也需占满可用正文宽度；收起固定侧栏时必须给原五项一级导航提供可见、可键盘操作的替代入口。打开模态导航时遮罩后的页头与正文不可聚焦，Tab/Shift+Tab 不得逃逸；关闭后侧栏不可聚焦，Esc/遮罩/按钮关闭要归还焦点，切回宽屏恢复背景交互。复用已有真实来源页的移动 Shell 规则时，须在 390px、320px 和原生 200% 分别核验内容宽度、折行、平台导航与保留的账号入口。该局部消费者扩展不改变桌面 Frozen 尺寸，也不代表其他工作区页面已适配手机。
- 2026-10-31真实来源非空验收补充：H01/C01/C03/H06小屏底部平台导航应有独立保留区域，主滚动内容不得进入浮钮下方；须逐一核对详情/来源/返回链接的元素命中，而非只测根宽度。长标题/编号还要检查文字Range是否越过卡片。原生200%如遇headless截图截半幅，另保存完整viewport对照并核查实际DOM边界，不把截图伪影误判为布局裁切。[本轮证据](../testing/initial-five-display-2026-10-31.md)。

## 7. 每个前端任务的完成门槛

1. **实现前：**明确参考图/版本、类型、受影响页面/组件和UE01–UE10适用项；需要改变母版或Frozen规则时先确认。
2. **实现中：**组件与Token优先、最小改动；新建/列表/详情/编辑及科研/管理/后端关联同时核对。纯后端任务也记录受影响UI或说明无影响。
3. **测试：**按实际工程命令运行单元/集成与`pnpm run build`；用真实浏览器完成关键流程、键盘、视口和错误状态；Playwright截图/录屏留证。测试工具不可用就列阻断，不能编造已执行命令或拿Mock代替真实业务。
4. **视觉比较：**同尺寸前后截图，对照当前确认母版和同类组件；检查字号、行高、裁切、溢出、状态及交互。页内修复不能以构建成功销项。
5. **回归范围：**从`platform-pages.json`读取当前清单；公共Token/Shell变更对所有受影响消费者回归，保留ADR要求的历史19页最低集但不以其替代当前范围。无公共影响的局部任务列明覆盖及未覆盖页。
6. **交付：**更新living spec/版本记录、使用说明和相关专项文档，按项目规则同步Notion；分别报告代码、配置、真实执行和用户效果，不统称“已完成”。

每个检查项标记“通过／失败／未测／不适用及理由”，不能只勾选“已检查”。未测的关键路径不能标为该模块验收通过。截图/日志使用合成或获准非患者样例，清除凭证和个人敏感信息；不将患者数据上传开发会话或Notion。

任务可用性至少用一条完整操作链检验“能找到下一步、失败后不丢工作、返回后上下文正确”。自动化可证明操作路径和状态契约；研究者阅读舒适度、误操作率、完成时间及专业结果质量仍需真实用户评审，不从断言数量推导“用户体验已提升多少”。已知控制台告警必须保留并标明，不用白名单将其宣传为零告警。
