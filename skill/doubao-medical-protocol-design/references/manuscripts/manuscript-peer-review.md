# 医学稿件审阅与同行评审

用于审稿、投稿前自审、审稿人视角评价及模拟同行评议。本分支给出有依据的稿件评价和修改建议；作者改稿、逐条回复审稿意见按用户要求进入对应写作分支，不把审稿报告自动改成作者回复信。

用户只要求审稿时，也完成范围相称的正式 Word 审稿报告。正式报告默认交 `word` Skill 生成真正 `.docx`，语言与目标期刊/用户要求一致；用户另选最终格式时遵从其要求。

## 1. 真正读稿，明确本轮可评估的范围

实际读取稿件、摘要、图表、补充材料及用户提供的期刊要求，保留版本和可核验的章节、图表编号。只有摘要或选段时，就该范围进行评价；区分“原稿明确存在的问题”“所给材料尚未展示的信息”和“当前无法判断的事项”。没有看到方法或验证材料，不直接认定研究没有实施。

先用简短笔记还原稿件主线：研究问题、研究类型与对象、比较和时间结构、主要结果及不确定性、作者主张、所称贡献、适用人群与局限。随后核对“问题—方法—证据—推论—贡献”是否连贯，正文、摘要、图表和结论是否相互支持。

评价贡献时结合目标期刊、专业领域与预期读者，分清方法学或临床价值、新颖性和可读性。新颖性、首创或优于既有工作的判断需要实际依据；不把显著阳性结果、跨学科影响或顶刊式创新当成所有医学研究的共同门槛。

## 2. 按实际医学设计评价证据链

围绕中心主张选择适用维度，不要求每篇稿件完成同一套检查。

| 研究类型 | 主要审阅重点 |
|---|---|
| 随机或其他干预研究 | 干预与对照定义、分配单位与方法、分配隐藏、适用的盲法/终点评估、结局与时间窗、交叉/失访、依从性、分析人群、安全结果及其与主张的对应 |
| 观察性研究与真实世界数据 | 人群来源、选择过程、时间起点、暴露与结局定义、混杂和测量偏倚、缺失与删失、敏感性分析；关联证据是否被写成超出设计支持的因果结论 |
| 诊断与预测研究 | 目标场景和人群、参考标准、测量/判读、开发与验证的独立性、数据泄漏、适用的诊断性能或区分度/校准、不确定性及拟议用途所需的验证 |
| 系统综述与 Meta | 问题与纳排标准、实际检索覆盖、筛选与提取、偏倚风险、研究可比性、异质性及合成方法，结论是否反映证据确定性；叙述性综述按实际范围评价，不套用未声称的方法 |
| 实验与转化研究 | 模型和研究问题、对照、独立实验单位与重复、测量可靠性、机制链条、可重复性，以及从模型向临床外推的边界 |
| 定性与实施研究 | 抽样与场景、资料收集和分析过程、解释的材料支撑、研究者影响、实施情境及结论可转移性，不强套量化试验指标 |

跨研究类型重点核对：

- **内部效度**：设计是否能回答问题，主要偏倚、对照和测量能否支撑作者的关键推断。
- **外部效度与医学意义**：对象、场景、干预和时间范围是否支持所称应用；区分效应大小、精确性、统计显著性与临床意义。
- **统计与数据一致性**：分析单位、分母、比较方向、终点和时间窗一致，模型与数据结构相符；按需要检查混杂、聚类/重复测量、多重比较和缺失处理。核对摘要、正文、表图的数字、百分比、区间、汇总层级和结论，能复算的差异实际核对。
- **安全与报告透明度**：根据人群和干预核对实际风险、安全结果、适用的伦理/注册信息，以及方法、数据来源和报告内容的可追溯性。未提供证明材料时说明当前可见范围，不推断未获批准或存在不当行为。

新增医学判断、方法学批评、关键参数或既有研究比较需要外部依据时，按[工具路由](../tool-routing.md)和[相关研究与引用](../related-research-and-citations.md)定向核实。可复现的内部数值错误、尚待澄清的汇总口径和疑似重复展示分别说明，不把异常直接定性为学术不端。

## 3. 将问题写成可定位、可判断、可解决的意见

### 关键问题 Major concerns

用于会实质影响中心结论、可信度、医学适用性或可重复性的事项。按影响排序，必要时说明其中哪项在解决前使中心主张尚不能成立。

每条意见包含：

1. **编号与原文位置**：如 M1，给实际章节、图/表或已核实页码/行号；没有行号时用章节和可定位短语，不编造位置。
2. **涉及的主张或写法**：准确概括作者在该处声称什么。
3. **问题及依据**：指出稿内证据、数值/方法对应关系或已核实的外部依据，分清已确认问题与待澄清事项。
4. **影响**：解释其怎样改变结果解释、中心论证、适用范围或读者判断。
5. **可执行修法与解决判据**：明确需要补充哪段信息、澄清哪项定义、完成哪类分析或调整哪项表述，以及怎样判断问题已得到回应。

### 次要问题 Minor comments

用于不改变中心结论的局部清晰度、术语、图表呈现、引用或格式问题。按 m1、m2 等保持稳定编号，给位置、具体问题、判断依据、局部影响和所需修正，避免重复展开完整科学讨论。

问题严重度由对论证的影响决定，不按语气强弱或修改是否容易决定；不凑问题数量。资料中的清楚优点同样说明其证据基础。

## 4. 修改建议与证据缺口相称

优先判断问题能否通过澄清已有方法、补足报告、展示已有数据、适当再分析或缩小结论来解决。需要新增数据、独立验证或实验时，解释它与中心主张的关系，以及较轻的替代方案能否回答问题；区分确有必要的修正与可供未来研究开展的扩展。

不把所有研究改成随机试验，不一概要求补实验、多中心、多数据集或重新完成一项研究。阴性或非显著结果按估计值、精确性和研究问题评价；样本量、验证深度与结论范围对应。建议专业、直接而有分寸，具体指出问题，不使用夸张拒稿判断或推测作者动机。

审稿报告可给基于当前材料的总体评价及修改优先级；期刊是否接收属于编辑决策。用户要求多视角评阅时按其范围组织，不虚构审稿人身份、独立性或一致意见，也不设置固定审稿人数、轮次或问题配额。

## 5. 报告与 Word 交付

正式审稿报告可按下列顺序组织，详略服从材料和用户要求：

1. 审阅材料、版本与范围。
2. 稿件核心问题、贡献与总体评价。
3. 有依据的主要优点。
4. 关键问题及可执行建议。
5. 次要问题。
6. 最重要的修改方向与需要作者补充的实质材料。

报告保持审稿人立场；作者回复信另按对应分支逐条回应，不能把尚未完成的修改写成已完成。仅审稿时交付完整审稿报告，不以润色后的原稿替代。

将报告、问题编号、原文定位、引用与 URL、目标语言及用户模板交给 `word`。英文等非中文报告采用相应学术文档的标题层级、字体、段落、图表和参考文献排版；由 `word` 按当前专业流程完成真实 `.docx`，不以纯 Markdown 作为正式报告交付。按[文档生成与交付](../output-and-feishu-qa.md)确认文件及呈现，使用 `present_files` 提供最终文档；遵守用户仅本地、禁止上传等偏好。
