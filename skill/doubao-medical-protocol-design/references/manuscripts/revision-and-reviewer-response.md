# 医学论文返修与回复信

用于根据编辑和审稿意见改稿、起草或润色回复信、整理返修材料。先按用户本轮要求确定是直接改稿、仅写回复，还是同时完成两者；局部任务处理指定意见或段落，整篇返修再统筹全文。

## 1. 确定本轮使用的稿件和意见

读取原稿、编辑决定信、审稿意见，以及已有修改稿、作者说明和实际分析/实验结果。确认目标期刊、稿件题名或编号、文档语言、返修要求及要交付的文件；大修、小修、转投等安排以编辑信为准。已有材料足够的部分直接推进，关键缺口集中列给作者补充。

沿用编辑和各审稿人的原编号与意见原文；原意见无编号时按原顺序编号。一条意见包含多个问题时，在其下面逐项回应；多条意见涉及同一处改动时，修改稿统一处理，各条回复分别说明。需要导航时，可用简短的“意见编号—修改段落或图表”索引，便于在稿件与回复信之间查找。

## 2. 先把意见落实到医学稿件

先找出影响主要结论的修改，再处理报告清晰度和语言。围绕稿件实际需要调整相应内容：

- **方法与研究设计**：把对象、对照、选择过程、混杂处理、重复单位、终点定义和统计方法写具体；需要补分析时，使用实际数据与分析结果说明样本量、效应量、区间、多重比较及解释。伦理、注册、数据可用性和图像处理信息依作者实际材料更新。
- **结果与图表**：将真实新增的分析或实验落实到相应结果段落、表图和题注，同时处理摘要、主要结果及补充材料中的对应数字。实验条件、样本及比较口径随实际结果保留，修改前后使用相同术语和定义。
- **讨论与结论**：根据修改后的结果重新判断中心论点、临床适用性和局限。需要外部依据时补充与问题直接相关的文献，说明它怎样支持研究解释、定位或边界；审稿人推荐的文献也按相关性与核验结果采用。关联性结果使用与证据相称的表述。
- **信息呈现**：原稿已包含依据而读者仍产生疑问时，将关键内容移到容易理解的位置，补清定义、图注或交叉引用。主论证所需的信息放在正文，较长方法和扩展分析按稿约安排到补充材料。

对有科学分歧的意见，先界定真正影响结论的问题，再依据本研究的设计、数据与相关文献解释取舍，并同步改善相应稿文。只采纳其中一部分时，明确哪些内容已调整、其余建议为何未纳入，以及对结论有何影响。

建议的新实验或分析超出本研究可回答的范围时，说明其需要增加的研究条件及其与当前主张的关系；结合现有材料采用可行的补充分析、证据解释或结论收缩，并把适用范围写进稿件。不同意见对同一内容提出冲突要求时，结合编辑要求与科学理由形成一套一致改法，再分别解释处理结果。

## 3. 从修改稿写出逐条回复

回复按期刊要求分编辑、分审稿人排列，紧接原意见给出清楚回答。自然段通常先回答对方提出的科学或表述问题，再说明本次具体改动及依据，最后给出修改稿的位置；重要改文可附短摘录，较长内容直接指向相应章节、图表或补充材料。感谢语简洁，主要篇幅用于回答问题。

联合任务先完成实质改稿，再让回复准确描述这一版稿件。仅写回复时，依据作者已提供的修改、分析结果和说明起草；需要作者继续完成的内容另列为建议或待补项，使用与实际进展相符的时态。仅改稿时，将意见落实到指定稿件，按用户需要附简洁修改说明。

回复中的数据、P 值、效应量、实验结果、图号和页行采用实际资料。说明“已补充”“已修订”的内容应能对应具体改文或作者提供的工作说明；最终稿有稳定页行时据实定位，尚无行号时用章节、段落、图表或可定位短语。主要回复、关键数字、引文和位置随同一稿件版本整理。

需要回复信概述或 revision cover letter 时，围绕最重要的实际修改概括。语言、合并或分审稿人文件、审稿可见范围按期刊要求安排。转投材料适配接收期刊；针对拒稿的申诉按申诉目的、编辑决定和该刊规则单独组织。

## 4. 证据支持与正式交付

新增医学判断、关键数值或方法依据时，按 [工具路由](../tool-routing.md) 和 [证据与引用](../related-research-and-citations.md) 定向检索，复用已有来源；纯语言调整围绕现有内容完成。保留原有和新增文献的真实 URL 及其与稿件的对应关系。

正式回复信与正式修改稿默认交给 `word` Skill 生成 `.docx`，英文及其他非中文材料同样采用正式学术文书排版。一次交接完整内容、目标期刊或用户模板、语言、标题层级、原意见与回复的区分方式、图表及引用要求；按需要交付回复信、清稿、修订痕迹稿或修改对照，用户指定其他载体时按其要求。

引用默认采用现行 GB/T 7714 顺序编码制，用户或目标期刊明确指定其他格式时按其要求。Word 正文使用不附链接的原生上标编号，文末每条参考文献末尾提供带真实超链接的“（查看来源）”，具体生成交接沿用 [共同交付规则](../output-and-feishu-qa.md)。最后使用 `present_files` 交付最终文件及已创建的配套材料入口。
