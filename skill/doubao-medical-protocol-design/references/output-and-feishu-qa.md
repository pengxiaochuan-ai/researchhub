# 科研文档生成与交付

本文件负责科研任务的载体、Word/飞书/PPT/表格生成和相称的质量确认。内容按本轮任务分支组织，研究方案模板仅用于方案任务。

## 1. 先确定最终产物

| 用户需要 | 交付 |
|---|---|
| 科研咨询、选题建议、单独大纲、仅指定句段的润色或修改建议 | 聊天中直接给可用内容；用户要求文件时再按指定载体生成 |
| 科研基金申报辅导、申请材料整理/修改、基金评议与经费说明等正式材料 | 读取 `funding/funding-workflow.md` 与国内格式参考，在资助方允许的辅助范围内，按目标年度/类别模板交 `word` 生成工作稿或修改稿 |
| 研究方案/方案报告、论文撰写、改写、仿写、润色、修改，以及综述、开题/立项/进展/结题等正式科研材料 | 优先读取并使用 `word` Skill 的正式学术论文/科研文书模板或专业排版流程，默认生成真正可打开的 `.docx`，无需用户再次指定 Word |
| 技术交底、权利要求、完整专利稿、专利已有稿修改及正式论文—专利对照材料 | 读取 `patents/patent-drafting.md`，默认调用 `word` 按正式专利文书体例生成 `.docx` |
| 论文审稿、投稿前预审、审稿意见、审稿回复信、正式修改稿 | 默认调用 `word` 生成正式审稿报告、回复信或修改稿 `.docx`；按本轮范围组合产物 |
| 飞书、在线文档或在线协作 | 读取并使用 `lark-doc`，按其当前流程创建/编辑在线文档 |
| Word 文末的使用说明、注意事项、补充阅读及配套资料 | 简短内容可由 `word` 放在文末；详细补充材料或持续协作内容可主动同步使用 `lark-doc` 创建配套飞书文档，与 Word 分别交付 |
| 科研汇报、开题答辩、组会等 PPT/幻灯片 | 读取并使用 `ppt` Skill |
| 独立于文档的数据统计表、数据汇总表、单独表格、访视/样本/变量/进度表或工作簿 | 读取并使用 `sheet` Skill 创建可编辑表格；无需用户明确指定 Excel/xlsx |
| 论文、方案或报告正文中的表格 | 随 `word` 或对应文档能力制作，与正文一并交付 |
| 用户指定 Markdown、PDF 或其他形式 | 按其要求及对应能力交付 |

在写作或格式锁定前识别用途：本轮主要产物是独立表格时先进入 `sheet` 分支，论文、方案、审稿或科研报告等正式文档则使用默认 Word 路由，正文内表格随文档制作。正式 Word 与配套飞书文档可以组合交付，按内容的实际价值选用。主动选择本 Skill 与系统匹配使用相同的任务路由；任务复杂时加深对应分支。已明确要求正式产物时持续完成该产物。

## 2. Word 正式材料

创建论文、研究方案、科研报告及审稿等学术 Word 材料前，明确本稿引用默认采用现行 GB/T 7714 顺序编码制，整理正文展示编号、国标参考文献条目与实际来源 URL 的对应关系，再将科研内容、标题层级、图表及题注、引用映射、原稿、用户模板或目标期刊要求交给 `word`。沿用用户要求的仅本地、禁止上传和既有文档样式等偏好。

整篇论文的撰写、改写、仿写、润色、修改，以及方案报告、审稿报告和审稿回复，均按正式 Word 文档交付。论文采用正式学术论文格式，方案采用正式研究方案格式；生成内容与版式都由对应文种决定。英文和其他非中文材料同样输出规范 `.docx`，Markdown 用于内部起草；正式交付使用 Word 的真实文档样式。

- **论文与综述**：按 `manuscripts/research-writing-and-editing.md` 区分论文类型，优先目标期刊稿约。内容采用规范学术表达，正文引文、图表和参考文献对应；摘要、关键词、中英文内容及作者信息按实际要求设置。
- **改稿**：按用户要求提供清稿、修改对照或修订痕迹，原始事实与数据保持一致；审稿意见回复对应问题和改动位置。只润色指定范围时交付该范围的修改。
- **审稿报告**：题名与实际审阅范围、总体评价与主要贡献、关键问题、次要问题及可执行建议，按需要组织。每个问题提供原文位置、依据和改进方向，分组编号便于后续回应。
- **审稿回复**：按编辑/审稿人分节、按意见编号组织原意见、作者回复、实际修改和位置；长回复以清晰段落呈现，需对照时再用简洁表格。清稿、修订痕迹稿与回复信按用户所需生成，内容与引用一致。
- **科研报告/申报材料**：按文种组织背景、目标、内容/方法或实际进展、成果与分析、可行性/问题和后续计划，充分回应申报或汇报要求。
- **科研基金**：按 `funding/china-application-format.md` 确定当年资助类别、正文结构、字段和篇幅，使用基金文书体例；实际模板的排版优先于下方通用版式。技术路线、任务安排、真实研究基础与经费说明对应，引用沿用国标、原生上标和末尾来源链接规则。国自然等有 AI 辅助专门要求的项目按对应规定处理；作者使用说明可作为独立配套材料交付，正式申请正文按模板组织。
- **研究方案**：文首先概括设计并直接回答用户核心问题，再展开必要方法。完整方案按 `protocols/protocol-design-workflow.md` 组织；模块方案围绕指定部件交付。
- **正式论文版式**：优先使用 `word` 的正式学术论文模板及目标期刊版式。按文章类型设置题名、实际作者与单位、摘要关键词、分级标题、正文、图表和参考文献，保持学术论文的连贯表达。标题使用真正的样式层级，图表编号、题注、正文引用与文献编号对应。
- **正式方案版式**：完整方案可采用封面/版本信息、方案摘要、目录、研究背景与依据、目标与假设、设计与方法、流程与终点、样本量和分析框架、质量/安全/伦理、实施计划及参考文献；按本研究类型选择章节。模块方案保留其范围，采用同样规范的 Word 标题、表格和编号体系。
- **专利材料**：按 `patents/patent-drafting.md` 组织技术交底、权利要求书、说明书、摘要及附图，按需要合并或分文件交付；使用正式专利体例、清晰的权利要求层级、段落/步骤/附图编号和原生可编辑公式。权利要求与摘要使用其专利正文体例，现有技术、来源映射及参考文献按下方专利引用要求安排。
- **通用排版**：用户未指定时采用 A4、约 2.5 cm 页边距，中文正文宋体小四、英文与数字使用协调的学术字体（如 Times New Roman 12 pt），约 1.5 倍行距；标题层级清晰，连续页码，长文按需设置自动目录和简洁页眉。采用规范三线表或简洁表格，列宽、跨页表头、题注与分页协调，避免孤立标题和图表分离。具体落实由 `word` 的专业排版流程完成。
- **国标引文**：论文、方案和科研报告默认采用现行 GB/T 7714 顺序编码制，文中按首次引用顺序标注，与文末规范著录条目对应，同一来源沿用同一编号；用户明确指定其他格式时再调整。每条参考文献在规范著录条目末尾必须追加中文括号“（查看来源）”，将其中“查看来源”创建为指向该来源真实原始 URL 的 Word 超链接。条目已有 DOI、题名链接或编号链接时，也必须保留末尾入口。期刊分区/证据分级主要用于内部评价，按论文或报告需要展示。

### 专利材料的引用与格式交接

专利权利要求与专利摘要以技术特征、步骤、关系及效果组织，引用映射可放在技术交底、论文—专利对照或独立支持材料附录，采用文件/页段/图式位置与真实来源链接。学术正文的 `[n]` 上标规则仅用于需要学术引文的部分；列参考文献时仍采用现行 GB/T 7714，每条末尾加带真实超链接的“（查看来源）”。专利公开号、公开日、申请人和 URL 按已取得记录保留。

触发 `word` 时一次传递专利文种、章节顺序、权利要求与步骤/图式编号、术语、原生可编辑公式和实际需要的上下标，以及支持材料的引用与来源链接要求。Word 按对应专利文书体例完成生成。

### Word 引用上标与末尾链接

- 学术正文引用的 `[1]`、`[2,5]` 等作为独立 Word run，设置原生 `superscript`，方括号和完整编号一起上标，不附超链接；文末参考文献条目的编号保持基线，并保留与文末条目的来源对应。由 `word` 按当前生成接口落实；使用 python-docx 时对应 `run.font.superscript = True`。不得把 Markdown 的 `^`、`^{[1]}` 当作上标，也不得依赖 Unicode 上标数字逐位拼接引用标号。
- 公式和单位中需要的上标、下标同样使用 Word 原生格式；使用 python-docx 时对应 `run.font.superscript` 或 `run.font.subscript`，保持数学含义、单位和原文一致。
- 末尾入口的可见形式为：`[1] 文献国标条目.（查看来源）`。此处为结构示意；实际 `.docx` 中仅“查看来源”文字承载真实超链接，不能只留下文字、裸 URL 或 Markdown 链接源码。每条都追加，包括已有 DOI 的条目。
- 来源沿用共享引用记录中的真实 URL，允许搜索工具返回的 PDF、第三方存储/索引、镜像及其他既有可用入口；不为补末尾链接额外核对卷号。

触发学术材料的 `word` 生成时，将正文编号与来源 URL 映射、完整编号原生上标且不附超链接、公式/单位上下标，以及每条文末“（查看来源）”真实超链接要求一并传递，由 `word` 按对应文种落实。

### 文末使用说明与补充阅读

正式 Word 文档末尾可增加简短的“使用说明”“注意事项”或“补充阅读”。可放在参考文献之后或独立后附页，内容围绕本次产物，例如待填位置与结果回填方法、数据表使用方式、修改稿阅读提示、后续步骤及值得继续阅读的资料入口。

由 `word` 使用独立段落样式排版，可采用约 9–10 pt、浅灰字（如 `#6B7280`），保持清晰可读、篇幅适度，并与论文、方案或报告正文清楚区分。影响研究结论和使用方式的关键信息仍在正文相应位置清晰呈现。说明语言与文档协调；投稿稿件可将这部分标为“作者使用说明”并置于后附页，按用户模板或稿约安排。

补充资料使用实际题名或清晰锚文本提供可点击来源；正式引用沿用正文的 GB/T 7714 编号与 URL 映射，延伸资料可列为“补充阅读”。已有配套飞书文档时，在文末附其题名和链接，便于查看详细材料。

### 英文、其他语言与双语文档

- 语言按用户、原稿和目标期刊要求确定；未指定时沿用稿件/审稿意见的主要语言。回复信的礼貌、立场和学术术语符合该语言的正常表达习惯。
- 英文正文默认使用 Times New Roman 11–12 pt，或目标期刊指定字体；中文与英文混排时分别设置适用字体。其他语言使用覆盖相应字符且风格协调的字体，统一标题、正文、引文与图表的层级。
- 采用整齐的学术页面、约 2.5 cm 页边距、协调的段间距与 1.5 倍行距；期刊要求双倍行距、页行号或指定纸型时据此调整。长文按需设置目录、简洁页眉和连续页码。
- 审稿回复中原意见与回复以缩进、段落样式和清楚的小标题区分，保持舒适字号。段落、编号、项目符号、表格、题注与超链接均使用 Word 原生结构；公式、上下标、希腊字母与单位正确排版。
- 文中引用位置以实际章节、段落、图表号或已核对的页行号表示。学术正文引用使用原生上标；专利材料按其文种安排来源说明；文末每条“（查看来源）”入口按上述必需规则创建，避免长链接破坏版面。
- 将分页、图表、引用和语言字体要求交给 `word` 的正式排版流程。最终使用 `present_files` 交付 Word 文件及已创建的配套材料入口，聊天概括本轮结论、重要改动和各产物用途。

## 3. 飞书与在线协作

### Word 配套补充材料

完成 Word 的同时，可根据补充内容的价值主动创建配套飞书文档，适用于较详细的使用说明、材料填写与数据收集指引、关键设计依据、修改说明、拓展阅读与原文链接、后续工作安排等。简短说明可留在 Word 文末，较丰富且适合在线更新的内容放入飞书；独立可编辑的数据统计表仍交 `sheet`。

配套文档可命名为“主文档题名｜补充材料与使用说明”，文首标明对应 Word 题名及版本或日期，再按实际内容组织使用说明、补充材料、资料来源与后续建议。Word 文末可链接到该飞书文档；飞书说明其与主文档的对应关系，正文涉及的研究事实、数据和引用保持一致。配套文档中的资料同样保留可点击来源链接。沿用用户指定的仅本地等交付偏好。

### 在线文档生成

读取 `lark-doc` 当前示例与工具合同。研究方案可取 `assets/feishu-protocol-template.xml` 并按设计范围裁剪；论文和科研报告使用自身文种结构。

方案文首可使用“方案总结”“仍需确定的问题”高亮块；用户的核心问题先直接解答，再按需展开背景和设计。与范围无关的章节删除，待确认项集中呈现。其他科研文种采用适合该文种的标题与摘要形式。

生成 XML 时：

- 使用当前支持的标签，表格按其示例组织 `table/thead/tbody/tr/th/td`，首个内容元素为标题。
- 动态文本中的 `&`、`<`、`>` 与属性引号按 XML 规则编码一次，保留真实标签；来源链接中查询参数的 `&` 按属性转义。
- 加粗和图表按当前示例；公式上标使用 Unicode。正文在相关句段旁以 `[1]`、`[2]` 等编号直接链接实际来源，例如 `<a href="来源URL">[1]</a>`；按首次出现编号，同一来源复用编号，文末列对应题名、作者/机构/期刊和年份并保留可点击入口。组件 `RichMediaReference` 用于聊天回答。
- 替换模板占位并移除内部注释。完整内容优先一次创建，载荷受限时再分大块写入同一文档。
- 创建后按实际需要一次回读，确认标题、核心内容、关键表格和来源链接；创建返回 warning 时先核对已返回文档，再处理修正。

创建方式和参数以 `lark-doc` 当前流程为准，不另加固定 API 版本要求。纯 JSON/XML 解析不设为每次科研任务的额外必经步骤。

## 4. PPT、图表与独立表格

科研 PPT 使用 `ppt` Skill，制作前按题材检索常见结构与风格，再按问题、背景、研究设计/实际结果、讨论和总结组织。各页内容充分、逻辑递进，按信息价值使用对照表、研究流程、机制图和数据图，页脚标注支持该页内容的来源超链接。

需要图片时先通过 `tool_search` 发现 `visual_search` 再搜索并按返回来源引用。数据图来自实际数据；方案示意图明确表达拟议设计。页面数量、图表数量与内容量匹配。

### 独立表格与 Sheet 交付

需要独立数据统计表、汇总表或单独表格时，读取并使用 `sheet` Skill 的当前流程创建表格。可用于研究数据整理与统计汇总、基线/结果汇总表、访视安排、变量字典、样本清单和进度管理。按任务设置工作表、表头、字段单位、数字/日期格式、必要公式及来源；用户明确要求 xlsx 时按该 Skill 的能力导出真正可打开的工作簿。

确认表头、工作表、格式、公式及关键数值，保留 ID、前导零、日期和缺失值含义；访视、终点、变量与正文使用相同定义。文档内表格随文档制作；同时交付独立表格与 Word 时保持两者数值和口径一致。按 `sheet` 的当前交付方式提供可编辑表格链接或文件，并使用 `present_files` 交付最终入口。

## 5. 交付前一次集中确认

检查本轮涉及的事项即可：

- 用户要求的内容、范围、语言和格式已完成。
- 医学事实、原始数据、数字、结论和材料中的时间状态一致，重要依据可追溯。
- 正文引文与参考文献、图表来源和 URL 对应；未知表格字段按规则处理。
- 依据生成工具返回的实际文件或文档入口交付正式产物。
- 有文末说明或配套飞书材料时，说明与主文档的对应关系并提供链接。
- 方案任务另核对目标—对象—终点—时间—分析—样本量是否一致，以及适用的安全、伦理和可行性问题；写作任务核对原稿/大纲/审稿要求及学术表达。

只有新增改动、失败或发现实质问题时再定向确认。过程文件保留，无需任务结束时清理。

## 6. 最终回复

概括本轮完成的内容、最有价值的结论或改动，以及需要用户补充的实质信息；使用 `present_files` 一并交付 Word、已创建的配套飞书文档及其他最终产物，简短说明“正式稿”“补充材料”“独立表格”等各自用途。XML、CSV、manifest 和内部草稿留作过程材料，用户明确需要时再提供。后续建议围绕本轮目标给出，按需提出一个有帮助的下一步。
