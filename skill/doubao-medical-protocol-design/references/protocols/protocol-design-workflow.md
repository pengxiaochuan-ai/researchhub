# 研究方案设计分支

仅当用户要研究设计判断、一个设计模块、完整研究方案或既有方案审查时读取。选题、大纲、论文语言与写作任务走各自分支；本文件保留原 Skill 的方案设计能力。

## 1. 确定设计范围

先读 `routing-and-decision-queue.md`，选择 `design_fit`、`focused_component`、`full_protocol` 或 `review_existing`。范围由本轮需求决定：解释一个点就回答该点，要求样本量模块就完成该模块，完整方案才组织整体设计。

建立简短设计总结：问题与用途、目标参数、对象/系统、比较与结局、时间结构、候选设计、主要风险、产物和未决项。区分已知事实、可讨论假设与未知要素。只澄清会改变主设计、主要终点或可行性的少量问题，其余可给带明确假设的初版建议。

`full_protocol` 表示覆盖深度，不等于关键事实已经确定。关键要素未知时交付初版方案，给出当前首选路线、必要条件和待确认项；参数充分时再形成具体入排、终点、访视、安全规则与样本量。

## 2. 设计与研究语境路由

| 主问题 | 参考 | 典型候选 |
|---|---|---|
| 主动干预的有效性、安全性或实施效果 | `clinical-interventional-design.md` | 随机、集群、交叉、务实、非随机试验 |
| 暴露、病因、负担、自然史或比较效果 | `observational-and-rwd-design.md` | 队列、病例对照、横断面、RWE、目标试验模拟 |
| 检测、诊断、预后或个体风险 | `diagnostic-prognostic-prediction.md` | 诊断准确性、预后因子、模型开发/验证/更新 |
| 体验、流程、采纳或实施机制 | `qualitative-implementation-mixed-methods.md` | 定性、实施、过程评价、混合方法 |
| 人源样本连接临床表型或结局 | `translational-human-specimen-design.md` | 样本队列、嵌套研究、标志物验证 |
| 动物、细胞、类器官或技术平台 | `experimental-biomedicine-design.md` | 平行、析因、剂量反应、重复测量、验证实验 |

研究语境按临床与人群、人源转化、实验生物医学区分。人源材料再读 `human-biospecimen-overlay.md`；常规医疗数据、受监管干预、AI 与聚类等按路由文件叠加。针对当前任务加载相关模块。

## 3. 设计链条与独特要求

- 保持研究问题、目标参数、对象、比较、主要终点、时间结构、分析单位、偏倚控制与可行性一致。
- 终点、样本量或方案级分析框架读取 `endpoints-sample-size-analysis.md`；关键参数有出处及适用条件，资料不足时给情景和所需输入。正式计算保留可复算方法与输出。
- 观察性治疗比较对齐资格、策略分配、time zero 与随访，宽限期按观察性模块处理；独立研究单位、生物重复和技术重复按研究语境区分。
- 伦理、安全、注册、数据/样本治理及报告规范在相关设计中读取 `../ethics-data-governance-reporting.md`，使用时核对适用版本和具体范围。
- 原有数据清洗、统计、建模、结果复核，以及设计冻结后的独立 SAP，交医学科研数据分析能力完成；本分支给与整体设计一致的分析框架。

## 4. 证据、记录与交付

按共享工具与引用参考检索主题研究、关键方法、相关指南及参数，重点说明证据对当前设计的具体启示。完整方案需要立题依据时，按论文引言的逻辑组织重要性、国内外进展、证据局限和研究必要性；局部模块只给理解该模块所需背景。

多来源正式方案使用共享六列 CSV 和一次 `--csv --in-place` 期刊匹配，直接采用返回的逐条结果。`assets/protocol-manifest-template.json` 是复杂方案需要结构化追踪时的可选记录，按适用部分裁剪，并从同一来源记录映射引用；一般设计判断、局部模块及论文写作可直接组织产物。

研究方案与方案报告默认读取并调用 `word`，使用正式研究方案/科研文书模板和专业排版，生成 `.docx`，引用默认采用现行 GB/T 7714 顺序编码制。完整方案可设封面与版本信息、方案摘要、目录，再展开研究背景与依据、目标、对象、干预/暴露、终点、流程、偏倚、样本量、分析、安全、伦理、可行性与参考文献；按研究类型及用途选章，摘要先回应核心设计问题。模块方案采用同样规范的 Word 版式，保留模块范围。方案末尾可附简短使用说明、数据填写指引或补充阅读；需飞书/在线协作或配套详细说明时读取 `../output-and-feishu-qa.md`，正式方案在线呈现时再按需采用 `assets/feishu-protocol-template.xml`。
