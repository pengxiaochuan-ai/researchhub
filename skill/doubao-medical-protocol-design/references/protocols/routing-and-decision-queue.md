# 研究方案路由与决策队列

仅用于 `protocol_design` 分支。选题、论文、改稿与科研报告先按 `../research-task-routing.md` 选择任务；本文件的 A/B/C 队列用于研究设计决策。

## 一、从研究问题而不是惯用设计出发

| 用户真正想知道什么 | `question_family` | 优先考虑 |
|---|---|---|
| 某干预是否改善结局或安全 | intervention | 随机/务实/集群/交叉/非随机干预研究 |
| 某暴露是否与结局有关 | etiology_risk | 队列、病例对照，必要时目标试验模拟 |
| 某人群现况或负担是多少 | burden_prevalence | 横断面、调查、登记描述 |
| 检测能否识别当前状态 | diagnosis | 诊断准确性/一致性研究 |
| 基线因素与未来结局关系 | prognosis | 预后因子研究 |
| 能否为个体预测未来风险 | prediction | 模型开发、验证、更新或影响研究 |
| 为什么流程不被采纳、如何实施 | implementation | 实施研究、过程评价、集群/混合方法 |
| 患者/人员如何体验或解释 | experience | 定性研究 |
| 分子或细胞机制是什么 | mechanism | 转化研究或实验生物医学研究 |

用户提出的设计名称不是绝对命令。先判断该设计能否回答实际问题；若不能，说明冲突并提供一个首选替代方案。

## 二、研究语境优先于技术名词

- 有患者结局 + 基因/影像：仍可能是临床或转化研究，不因“组学”变成纯生物实验。
- 只有细胞/动物机制：属于实验生物医学，不写临床入排、疗效或患者获益。
- 人源标本 + 临床表型：属于转化研究，患者层设计与标本层设计缺一不可。
- 医疗流程/医生行为/患者体验：可属于人群、实施或定性研究，不应硬改成生物标志物研究。

## 三、设计适配检查

在推荐前检查：

1. 时间顺序能否建立；
2. 干预能否、是否应该随机；
3. 结局罕见、潜伏期或随访负担；
4. 是否需要估计发病/风险、诊断性能、个体预测或因果效应；
5. 数据/样本/招募来源是否真实可达；
6. 主要偏倚能否在设计阶段降低；
7. 伦理、安全、资源和时间是否允许；
8. 研究结果将用于什么临床或科学决策。

只给一个主要推荐，并说明关键替代。不要列十种设计而不作选择。

## 四、决策队列

把未确定事项按“如果答案不同，是否改变设计或主要结论”排序：

### A 级：现在必须决定

主要问题/用途、研究语境、首选设计、主要对象、主要干预/暴露/检测、主要结局、time zero/实验起点、策略可判定时点、宽限期处理、分析单位、核心可行性或安全限制。

### B 级：可在初版方案中给出情景建议

次要终点、部分协变量、访视细节、样本处理细节、非关键亚组、备选招募策略。

### C 级：后续运营文件处理

页面排版、内部编号、非关键表单格式和不影响设计的文案。

每轮只问 1–3 个 A 级问题。若用户授权假设，写入 `assumptions` 并继续；不要把 B/C 级问题变成长问卷。

### 设计成熟度与初版交付

- `full_protocol` 只描述方案覆盖深度，不等于所有 A 级事实都已冻结，也不覆盖用户明确指定的交付格式；正式方案默认交 `word`；用户要求飞书/在线协作，或适合配套补充材料时使用 `lark-doc`，并按共享交付规则组织文末说明。不要用完整目录制造“方案已经定稿”的错觉。
- 一个或多个 A 级要素未知时，仍可按文档优先规则交付，但应定位为“初版方案”：分别列出已知事实、条件假设、可选路线、首选建议、路线切换条件和 1–3 个待确认项。
- 精确入排阈值、剂量、终点、访视、样本量或停止规则只有在其适用条件和依据已核实时才可作为推荐值；否则给区间、情景或待确认参数。单项研究的特异性规则只能作为有边界的实例，不得直接改写成所有同类研究的通用标准。

## 五、按需推进

内部按问题、设计、对象、测量和统计完善方案。面向用户的更新聚焦已解决的问题、影响设计的发现和必要澄清，简短说明有实际意义的变化。

## 六、证据深度

- 仅整理用户材料时，不自行补写“已有研究表明”。
- 设计是否符合规范、量表/终点定义、药品/器械安全、注册要求等需要定向核验。
- 完整立题依据、事件率或效应参数需要证据支持时，使用有停止条件的检索；达到足以支持当前设计决策且无关键冲突时停止。
- 未取得全文或官方文件时，标记证据边界；搜索摘要不能冒充核验原文。

## 七、附件与草案

- 实际读到方案后才能做逐段审查并定位原文。
- 只看到摘要/截图时，只做相应范围的审查。
- 用户说“按附件修改”但附件不可访问时，说明无法读取，并可提供结构模板或请求重新上传。

## 八、服务模式

| 模式 | 本轮范围 |
|---|---|
| `design_fit` | 设计判断、理由、关键替代和下一步 |
| `focused_component` | 用户指定的终点、样本量、分析框架、访视、CRF、质控等部件及必要接口 |
| `full_protocol` | 组合与本研究有关的设计模块，形成完整初版或较成熟方案 |
| `review_existing` | 根据实际读到的方案定位问题，优先处理影响可回答性、安全性和执行的缺陷，给出修改建议 |

按明确需求选择范围，不因问题长、显式选择 Skill 或使用文档而自动升级为 `full_protocol`。范围宽泛时先给可用研究主线和少量关键决策，再按用户目标形成方案。文档结构可动态调整，默认正式材料交 `word`；文末说明、配套飞书补充材料及用户指定的其他格式按 `../output-and-feishu-qa.md` 执行。

## 九、叠加层映射

| 叠加层 | 触发条件 | 必加字段/检查 | 额外模块 |
|---|---|---|---|
| `human_biospecimen` | 使用可链接的人体组织、血液、体液、原代细胞等 | 参与者/标本/检测/分析集、同意范围、链路、前分析、批次、撤回 | `human-biospecimen-overlay.md` |
| `routinely_collected_data` | EHR、claims、登记或常规诊疗数据是主要来源 | 数据捕获、time zero、代码/表型、链接、缺失与历年变化 | `observational-and-rwd-design.md` |
| `regulated_intervention` | 药品、器械、生物制品等受监管干预 | 监管状态、风险、产品版本、GCP、监测和法域 | `clinical-interventional-design.md` + 伦理治理 |
| `AI_model` | 开发、验证、更新或评价 AI/机器学习模型 | 预测时点、患者级拆分、锁模、版本、校准、外部验证、漂移 | `diagnostic-prognostic-prediction.md` |
| `clustered_design` | 分配、抽样或实施在中心/科室/家庭等集群层 | 随机/抽样单位、集群数、ICC、污染、集群失访和分析 | 对应主设计 + 样本量分析 |

一个研究可同时启用多个叠加层。叠加层只补充强制字段，不能将观察性研究改名为试验，也不能将人源原代细胞机制实验改名为临床验证。
