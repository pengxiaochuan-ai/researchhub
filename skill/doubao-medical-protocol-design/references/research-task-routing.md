# 医学科研任务总路由

按用户最终要获得什么来选择分支，格式、材料多少和任务复杂度分别判断。一个请求可以先形成选题/大纲，再继续方案或论文，但本轮只完成用户要求的范围。

## 1. 任务与参考文件

| 任务 | 常见输入 | 本轮重点 | 读取 |
|---|---|---|---|
| `research_consultation` 科研咨询 | 方法问题、概念、思路比较、具体追问 | 直接判断、理由和下一步 | 本文件；涉及方法时加对应设计参考 |
| `topic_outline` 选题与大纲 | 一个疾病/方向、选题、拟申报主题、文章题目 | 聚焦问题、价值与可行性、主线和可写提纲 | `topic-development-and-outlining.md` |
| `funding_application` 科研基金 | 国家/地区/机构资助类型、资助方全称与地区、年度/类别、指南与模板、原创思路、前期基础、申请书或基金评审意见 | 资助方向匹配、科学论证、研究者主导的材料完善、局部改稿/经费说明；正式材料交 Word | `funding/funding-workflow.md` 与 `funding/china-application-format.md` |
| `manuscript_drafting` 论文写作 | 大纲、数据结果、文献、原稿、参考范文 | 论文或指定段落、摘要、综述、讨论 | `manuscripts/research-writing-and-editing.md` |
| `manuscript_peer_review` 同行审稿/预审 | 稿件、图表、补充材料或目标期刊 | 研究问题、方法与证据评价；Word 审稿报告 | `manuscripts/manuscript-peer-review.md` |
| `manuscript_revision` 实质改稿 | 原稿、修改目标、编辑/审稿意见 | 修订论证、结构、方法说明和证据；Word 修改稿 | `manuscripts/revision-and-reviewer-response.md` |
| `reviewer_response` 审稿回复 | 编辑与审稿意见、已改稿及真实补充内容 | 逐条回复，交代实际改动与位置；Word 回复信 | `manuscripts/revision-and-reviewer-response.md` |
| `manuscript_polishing` 语言润色 | 稿件、段落、语言或表达要求 | 章节功能、段落衔接、术语与句法；整篇 Word 稿 | `manuscripts/manuscript-language-and-style.md` |
| `research_report` 科研材料 | 开题、立项、进展、结题、科研汇报等要求 | 与文种相符的内容、论证与正式材料 | `manuscripts/research-writing-and-editing.md`；包含新设计时追加方案分支 |
| `standalone_sheet` 独立表格 | 数据统计表、单独表格、工作簿、独立访视/样本/变量/进度表 | 可独立编辑使用的表格 | `sheet` Skill；交付见 `output-and-feishu-qa.md` |
| `patent_drafting` 医学科研专利 | 论文、技术方案、方法/装置/系统、实验与补充资料、已有专利稿 | 专利点、技术交底、权利要求与说明书、论文—专利对照或修改稿；正式材料交 Word | `patents/patent-drafting.md` |
| `protocol_design` 研究方案 | 临床观察、研究假设、设计问题、现有方案 | 设计判断、指定模块、完整方案或方案审查 | `protocols/protocol-design-workflow.md` |

研究方案/方案报告，以及整篇论文的撰写、改写、仿写、润色和修改，默认经 `word` 的正式学术论文/科研文书流程生成 `.docx`，无需用户再次指定 Word；论文与方案按各自正式结构排版，引用默认采用现行 GB/T 7714。具体咨询、大纲或仅指定句段的文本处理可在聊天交付。用户明确要求在线文档、PPT、Excel 或其他格式时遵从其要求，详见 `output-and-feishu-qa.md`。用户仅要求“给我大纲”时，大纲就是本轮产物；用户要求“按大纲写成论文”时继续成稿。

审稿报告、审稿意见和审稿回复也默认交付正式 Word，包括英文等非中文材料。正式文档使用 Word 的标题、段落、列表、表格和引文样式，Markdown 留作内部草稿。`review article` 的文献综述按论文写作处理，`peer review/referee report` 按审稿处理。

基金申报、基金立项、改本子、申报答辩和基金评审意见进入 `funding/`；先辨明国自然、具体地区自然科学基金或其他资助项目，简称由通知、模板或申报地区定位。学位开题及一般科研报告沿用报告/方案分支，论文中的基金致谢按论文实际信息填写。基金评审采用相应资助方目标和当年要求；论文同行审稿采用稿件评价流程。基金正式材料默认 `word`，按本机构、本年度和本类别模板，以及其 AI 辅助使用要求组织。

专利材料作为独立分支，按用户范围形成专利点意见、技术交底、权利要求、完整专利草稿或既有稿修改。先读 `patents/patent-drafting.md`，正式材料默认由 `word` 按专利文书体例生成；普通科研任务保持其原有分支。专利权利要求与摘要采用专利表达，引用及来源说明按该分支组织。

独立于文档的统计表、数据汇总表、清单或工作簿优先路由 `sheet`，即使用户没有指定 Excel/xlsx。用户仅需要论文/方案内的一张表时，由 `word` 或对应文档能力制作；同时需要文档与独立表格时分别生成，字段、单位和数值保持一致。

正式 Word 文末可附简短、小字号浅灰字的使用说明、注意事项或补充阅读；详细补充材料适合在线查看与更新时，可主动同步路由 `lark-doc` 创建配套飞书文档。按 `output-and-feishu-qa.md` 组织说明、建立对应链接并一并交付。

先按用户最终目标分流：只要审稿意见就完成审稿报告；要求改稿则修改指定范围；要求回复则逐条形成回复。混合任务按“诊断问题 → 修改稿件 → 与实际改动一致的回复”协作，产物按本轮需求组合。语言润色聚焦表达，发现影响结论的实质问题时说明具体位置并按需衔接改稿分支。

## 2. 起步时识别四件事

1. **要完成的任务**：咨询、提纲、基金、方案、论文、报告、专利材料或修改，及本轮范围。
2. **可用材料**：主题、原稿、大纲、真实研究方法与结果、文献、模板、审稿意见；基金任务还包括资助机构、年度、类别、官方材料和真实研究基础，专利任务还包括技术细节、图纸、实施例与已有公开信息。
3. **表达与用途**：语言、受众、目标期刊/申报要求、希望保留的风格与结构。
4. **交付**：聊天、正式 Word、在线协作、PPT 或 Sheet 独立表格；按需要组合 Word 文末说明与配套飞书补充材料。

先使用已有信息；缺少关键材料时，先给能完成的分析、框架或可填写稿件，并集中提示少量实质缺口。附件实际可读后再定位原文；只有摘要或截图时按可见范围处理。修改任务保留原稿与本轮版本的对应关系。

## 3. 证据深度随任务变化

| 证据模式 | 适用 | 执行 |
|---|---|---|
| `user_material_only` | 忠实整理、语言润色、格式调整、按已有材料编排 | 基于原稿完成；保留数据、事实、引文和 URL |
| `targeted_verification` | 新增或纠正关键医学断言、数值、方法、审稿问题 | 只查影响当前段落或判断的关键来源 |
| `evidence_informed` | 选题论证、综述、方案依据、科研报告中的新增学术内容 | 围绕主题、方法和证据缺口检索并综合 |

从任务需要出发，优先安排能解决关键问题的检索；相互独立的搜索同步并行。一般先完成一批高价值查询，再根据会影响结论或设计的缺口补查。来源足以支撑本轮任务、无重要冲突时停止。综述范围较大时按主题拆解检索，正式系统综述另按其实际方法覆盖检索、筛选与报告要求。

## 4. 与相邻能力的边界

| 最终目标 | 路由或协作 |
|---|---|
| 仅查找指南/论文、梳理研究进展或文献清单 | `doubao-medical-literature-search`；文献为选题、写作或方案服务时仍由本 Skill 组织 |
| 具体患者的诊断、用药、治疗、预后、会诊或转诊决策 | `doubao-clinical-decision-support`；科研研究中的转诊流程或 MDT 模式评价仍可在本 Skill 设计 |
| 实际数据清洗、统计计算、模型训练、结果复核或冻结设计后的独立 SAP | `medical-research-data-analysis`；本 Skill 提供研究问题、方法框架，并根据真实分析结果撰文；需要独立统计汇总表时由 `sheet` 承接结果表格 |
| 单篇文献的来源内解读/翻译 | 对应文献解读/翻译 Skill；为当前科研写作整合多来源时继续本 Skill |
| 患者病历文书整理、临床教学或工作总结为主 | 对应临床文书、临床总结与汇报 Skill；科研论文和科研报告继续本 Skill |
| Word、PPT、在线文档、独立表格等正式载体 | 本 Skill 完成科研内容后，分别交 `word`、`ppt`、`lark-doc`、`sheet`；Word 可附文末说明，也可与飞书补充材料组合交付 |

## 5. 跨分支协作

- 基金申请：基金分支负责资助方向、科学论证、年度格式和申请材料；方法细节按需调用方案模块，已有研究基础与未来任务分清。基金进展或结题按资助方模板组织实际工作和成果。
- 开题报告中的新研究设计：方案分支负责方法，写作分支负责论证与成稿。
- 由已有真实研究写原创论文：先整理实际问题、方法和结果，再写论文；原研究的改进建议另行表达。
- 参考范文写新主题文章：参考层级、论证方式和语言特征，新稿的事实与引用来自本主题材料。
- 专利材料：由专利分支提取技术特征和原文支持，按需检索专利现有技术与论文，再由 `word` 生成相应材料；与论文写作并行时分别组织专利保护逻辑和学术论证。
- 综述论文：科研助手负责写作与稿件修改，按需复用文献检索思路；正式文档交 `word`，语言与版式按稿约处理，引用沿用共享的国标默认或用户明确指定格式。
